# 품목이 여럿인데 첫 품목 코드에 합계 수량이 붙어 나갔다

- 날짜 : 2026-10-13
- 알려 온 곳 : (E)최상은 건 — 「환자분들 주문 제품 여러 개 경우, 메세지 상에 수량은 총 수량이나, 제품 번호는 1개만 보인다고 함」
- 고친 것 : `f7711d2c`

## 무엇이 보였나

환자(E)최상은님의 주문 `EUD202610130853571` 은 제품이 둘이다.

| 코드 | 이름 | 수량 |
|---|---|---|
| 5372 | EasiCath Nalaton CH12 Female 20cm - White | 350 |
| 28582 | SpeediCath Compact CH12 Female | 120 |
| | 합계 | 470 |

그런데 환자가 받은 문자는 이랬다.

```
1. 주문사항: 5372, EasiCath Nalaton CH12 Female 20cm - White, 470개
```

**첫 품목의 코드ㆍ이름에 합계 수량이 붙었다.** 350개를 주문한 제품이 470개로 적혔고,
28582 는 아예 보이지 않았다.

## 까닭

보내는 자리가 `orders` 표의 요약 칸 셋을 그대로 꺼내 썼다.

```php
'#{제품번호}' => (string) ($order->product_code ?? ''),
'#{제품명}'   => (string) ($order->product_name ?? ''),
'#{주문수량}' => (string) ((int) ($order->quantity ?? 0)),
```

그 세 칸의 뜻이 서로 다르다 —

- `product_code`ㆍ`product_name` : **첫 품목**
- `quantity` : **합계**

품목이 하나일 때는 셋이 같은 것을 가리켜 여태 드러나지 않았다. 둘이 되는 순간
코드와 수량이 어긋난다. 품목 줄은 `order_items` 에 따로 있는데 아무도 읽지 않았다.

같은 코드가 두 자리에 있었다.

- 문자 — `app/Services/PaymentLinkService.php`
- 알림톡 — `app/Http/Controllers/PrescriptionController.php` 의 `알림톡값들()`

## 번진 범위

운영에서 **품목이 둘 이상인 주문 24건 가운데 21건**에 틀린 글이 나갔다.
통수로는 **289통**(결제 링크 안내ㆍ계좌 안내ㆍ구매 내용 안내ㆍ반품 신청 안내).
한 주문에 여러 번 나간 것은 정정으로 링크를 다시 보낸 건들이다.

## 고친 것

승인된 알림톡 문구는 **한 글자도 고칠 수 없다** — 팝빌이 승인 본문과 견주어 받는다.
그래서 변수를 늘리는 대신 **셋에 나누어 담는다**. 다 이었을 때 아래 글이 되도록 가른다.

```
코드1,이름1, 수량1개 / 코드2,이름2, 수량2개
```

곧 `#{제품번호}` = 첫 코드, `#{주문수량}` = 마지막 수량, 가운데 전부가 `#{제품명}` 이다.
품목이 하나면 가르기 전과 똑같은 값이 나온다.

규칙은 `Order::주문사항칸들()` 한 곳에 두고 문자ㆍ알림톡이 함께 읽는다. 이어 붙여 본
것이 원래 글과 한 글자라도 다르면 요약 칸으로 되돌린다 — 어긋난 글을 보내는 것보다
여태 보내던 글이 낫다.

글머리의 「○○ 결제 안내입니다」 자리는 `Order::상품한마디()` 가 「… 외 1건」으로 적는다.

## 남은 것

품목 줄이 **같은 코드로 두 줄 이상** 선 주문이 둘 있다(`EUD202610061624261` 29012 가
30개ㆍ330개, `EUD202610121045371` 28512 가 300개ㆍ30개ㆍ30개). 글에는 그대로 두 번
적힌다. 합쳐 적는 편이 읽기 좋지만, 줄을 따로 세운 까닭이 있을 수 있어 — 추가 주문이
원 주문에 딸리는 자리가 있다 — 묻기 전에는 합치지 않는다.
