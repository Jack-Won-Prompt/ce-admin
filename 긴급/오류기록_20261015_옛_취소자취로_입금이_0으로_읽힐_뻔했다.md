# 옛 취소 자취 때문에 입금이 0원으로 읽힐 뻔했다

- 날짜 : 2026-10-15
- 찾은 자리 : 토스 구매자명이 상호로 보이는 43건을 살피다가
- 걷은 것 : 주문 `EUD202610121422281` · (E)이승준A · 81,000원

## 무슨 일인가

```
2026-10-12 14:43:12   카드 결제를 물렀다
2026-10-12 14:43:16   가상계좌를 새로 발급했다   ← 네 초 뒤
```

`toss_payments` 는 **한 주문에 한 줄**이라 새 발급이 그 줄을 덮어쓴다. 그런데 덮이는
것은 결제키ㆍ상태ㆍ계좌번호ㆍ기한뿐이고 **취소 자취는 그대로 남았다.**

```
status        WAITING_FOR_DEPOSIT     ← 새 가상계좌. 아직 입금 전
due_date      2026-10-15 14:43        ← 오늘이 기한이었다
canceled_at   2026-10-12 14:43:12     ← 옛 카드의 자취
cancel_amount 81,000원                 ← 옛 카드의 자취
토스 응답의 cancels : 없음              ← 이 가상계좌는 취소된 적이 없다
```

## 왜 돈이 0으로 읽히나

```php
// Order::받은금액 → TossPayment::남은금액
return max(0, (int) $this->amount - (int) ($this->cancel_amount ?? 0));
//            81,000 - 81,000 = 0
```

입금이 들어와 상태가 `DONE` 이 되는 순간 `쥐고있나()` 가 참이 되고, 남은금액이
**0원**으로 떨어진다. 화면에는 「받지 못함」으로 서고, 입금 자동 증빙도 그 값을 보고
돌지 않는다.

같은 꼴로 받은 돈을 0 으로 잘못 읽은 적이 있다
(`project_toss_one_row_per_order`).

## 걷었다

빗장 넷을 모두 지나갈 때만 고치게 했다 — 토스에 취소가 없을 것, 입금 대기일 것,
입금 시각이 없을 것, 걷을 자취가 있을 것.

```
걷기 전 : cancel_amount 81,000 · canceled_at 2026-10-12 14:43:12 · 받은금액() 0원
걷은 뒤 : cancel_amount 0      · canceled_at (없음)
          → 입금되면 남은금액() = 81,000원
```

걷은 값은 **활동 이력에 적어 두었다** — 무엇을 왜 걷었는지 되짚을 수 있다.

## 전수로 다시 보았다

```
우리 칸에 취소가 적힌 줄
   토스에도 취소가 있는 것(제대로 취소된 것) : 2건
   토스에는 없는데 우리만 적힌 것            : 0건   ← 걷기 전 1건
```

**이 한 건뿐이었다.**
