# 운영에 예약 일감을 세웠다

- 날짜 : 2026-10-15
- 지시 : 「세우기」
- 찾은 자리 : 토스 입금 콜백 실패 메일을 뒤지다가

## 여태 **아무것도 돌지 않았다**

`routes/console.php` 에 예약이 넷 적혀 있는데, 운영 서버에 `schedule:run` 이 걸려 있지
않았다. 적어 둔 것만으로는 돌지 않는다 — 일 분마다 그것을 불러 주는 자리가 있어야 한다.

```
root·ubuntu·www-data 의 crontab   모두 비어 있었다
/etc/crontab · /etc/cron.d        artisan 을 부르는 줄이 없었다
systemd 타이머                     laravel·schedule 이름이 없었다
```

그래서 넷이 모두 멈춰 있었다.

```
cashbill:sync --days=1      매시간    현금영수증 팝빌 동기화
cashbill:sync --status      15분마다  국세청 전송 상태 갱신
fax:sync-pending            5분마다   팩스 전송 결과 반영
withworks:sync              10분마다  창고 상태 동기화
```

**그런데도 자취는 갱신되고 있었다** — 사람이 화면을 열 때 함께 도는 길이 따로 있기
때문이다. 담당자가 일하는 동안은 돌고 **밤과 주말에는 멈춘다.** 그리고 오늘 만든
입금 대사(`toss:sync-deposits`)는 화면에서 부르는 자리가 없어 **영영 돌지 않았다.**

## 세우기 전에 하나씩 손으로 돌려 보았다

갑자기 다섯이 함께 도는 것이므로 먼저 따로 돌려 무슨 일이 나는지 보았다.

```
fax:sync-pending        대상 0 · 반영 0 · 실패 0
cashbill:sync --status  갱신 12건 · 오류 0건
withworks:sync          확인 200건 · 변경 0건        (2분 28초)
cashbill:sync --days=1  동기화 12건 · 오류 0건
toss:sync-deposits      물어볼 줄 8건 · 반영 0 · 탈 0
```

다섯 모두 깨끗하다. 돈을 쓰거나 지우는 일은 하나도 없다 — 조회와 반영뿐이다.

## 세운 것

```cron
HOME=/tmp/wwhome
XDG_CONFIG_HOME=/tmp/wwhome/.config
* * * * * cd /opt/ce-admin && /usr/bin/php artisan schedule:run >> …/storage/logs/schedule.log 2>&1
7 3 * * * tail -n 3000 …/schedule.log > …tmp && mv …tmp …/schedule.log
```

`www-data` 로 건다 — artisan 은 그 사용자로 돈다. `HOME` 을 주는 것은 일부 꾸러미가
그 자리를 찾기 때문이다(tinker 에서 겪었다). PHP 는 `/usr/bin/php` 로 못 박는다 —
cron 의 PATH 는 사람이 쓰는 것과 다르다.

로그는 당분간 남긴다. 걸어 둔 것이 제대로 도는지 눈으로 보려는 것이다. 다만 일 분마다
쌓이므로 새벽 세 시에 끝자락 3,000줄만 남기고 줄인다 — 영영 두면 디스크를 먹는다.

## 실제로 도는 것을 보았다

```
14:20:01  fax:sync-pending     461ms   DONE
14:20:02  withworks:sync       2m 28s  DONE
14:22:30  toss:sync-deposits   1s      DONE
```

`withworks:sync` 가 2분 28초 걸린다. 10분마다 도니 겹치지 않고, 겹치더라도
`withoutOverlapping` 이 막는다.

## 이제 달라지는 것

- **밤과 주말에도** 팩스 결과ㆍ창고 상태ㆍ증빙 상태가 갱신된다
- **웹훅이 끊겨도** 입금을 열 분 안에 찾아낸다 — 오늘 만든 대사가 비로소 돈다

## 지켜볼 것

며칠 뒤 `storage/logs/schedule.log` 를 열어 `DONE` 이 아닌 줄이 있는지 본다. 괜찮으면
로그를 `/dev/null` 로 돌려도 된다 — Laravel 이 제 로그를 따로 남긴다.
