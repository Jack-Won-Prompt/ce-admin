3. **가상계좌 · 기업은행**으로 바꿨다. 토스 화면에 「실제 결제가 안되는 테스트입니다」가

## 짚어 보고 **결함이 아니었던** 것 둘

### ㈎ `payment_events` 에 발급 자취가 없다

`PaymentLinkObserver` 는 **링크 상태가 바뀌는 순간에만** 적는다. 가상계좌 발급은 입금
전이라 링크가 `sent` 그대로다 — 적을 걸음이 없다. 입금이 확인되면 `paid` 로 바뀌며
그때 `KIND_PAID` 가 적힌다. 설계대로다.

### ㈏ 링크의 결제 수단이 `card` 로 남아 있다

링크 #225 의 `method` 는 `card` 인데 실제 결제는 가상계좌다. 이것은 **「무엇으로
안내했는가」**이고, 돈이 오간 걸음에는 토스가 알려 준 유형을 쓴다 — 2026-10-06 에 이미
고친 자리다(`PaymentEvent::적기`). 확인해 보니 그대로 돈다.

```
Order::payMethod()   'virtual'   ← 토스 유형을 따른다 ✓
toss_payments.method VIRTUAL_ACCOUNT
받은금액()           0원          (아직 입금 전이니 맞다)
```

## 끝까지 가지 못한 반쪽 — **입금 통보**

입금이 되어야 웹훅이 오고, 그 뒤의 증빙ㆍ창고까지 볼 수 있다. 그런데 **샌드박스에
입금을 일으킬 길이 우리 손에 없다.**

- 응답에 담긴 영수증 주소(`dashboard-sandbox.tosspayments.com/receipt/…`)를 열어 봤더니
  **입금한 뒤에 고객이 조회하는 화면**이었다. 입금 시늉 단추는 없다.
- 웹훅 본문을 우리가 직접 던져도 소용없다 — `handleDepositWebhook` 은 본문을 믿지 않고
  `paymentKey` 로 토스에 되물어본다. 토스 쪽 상태가 `WAITING_FOR_DEPOSIT` 이면 입금으로
  처리되지 않는다. **이것은 막는 장치이지 흠이 아니다.**

입금 시늉은 **토스 샌드박스 상점 콘솔**에서 눌러야 한다. 그 계정을 쓸 수 있는지 알려
주시면 입금까지 돌려 「승인 → 웹훅 → 결제 줄 → 증빙 → 창고」를 끝까지 보겠다.

웹훅 주소도 샌드박스 콘솔에 등록되어 있어야 한다.

```
https://www.ceadmin.co.kr/toss/webhook/{열쇠}
   (열쇠는 이 환경 settings 에 담겨 있다 · 2026-09-27 에 이 주소로 4건 받은 자취 ✓)
   토스 열쇠 확인은 꺼져 있다 — 확인하나('toss') = false
```

## 10-19 뒤에 다시 돌릴 때 견줄 것

같은 절차를 그대로 밟고 **이 다섯 가지**를 본다.

```
1. paymentKey 가 몇 자인가 — 지금 24자. 200자를 넘지 않는지
2. toss_payments.payment_key 가 잘리지 않고 그대로 담겼는가
3. 가상계좌 발급 화면에 예금주가 「김선미」로 채워지는가 ((E) 제거 유지)
4. 발급 응답ㆍ우리 표ㆍ영수증 주소의 식별자가 서로 같은가
5. 입금까지 간다면 — 웹훅 200 · payment_events 한 줄 · 증빙 한 벌 · 창고 한 건
```

지금 시험 서버에 담긴 결제키는 **1개 · 24자 · 앞머리 `tlink`** 다. 10-19 뒤에 둘이 되면
생김새가 바로 갈린다.

## 뒤처리

- 발급한 가상계좌는 샌드박스이고 돈이 오가지 않는다. 입금하지 않으면 10-18 에 기한이
  지나며 스스로 닫힌다 — 지울 것이 없다.
- 증빙은 입금되지 않았으므로 하나도 나가지 않았다.
- 문자 두 통은 우리 시험 폰으로 갔다(위 오류기록 참고).
