# 세금계산서 종이 서식 — 주민번호ㆍ이름ㆍ주소 세 칸을 고쳤다

- 날짜 : 2026-10-15
- 지시 : 운영 담당자 — 「10/1부터 진행된 세금계산서 생성 증빙 모든 파일에
  ① 주민번호 마스킹 없이 ② 환자 이름 뒤 알파벳 제외 ③ 공급받는자 사업장 주소에는
  주소만」
- 급한 까닭 : **내일부터 공단 청구 제출**

## 고친 자리는 한 곳이다

종이를 그리는 길은 `App\Support\TaxInvoiceForm::parties()` 하나다. 주문 화면의
「세금계산서 출력」ㆍ공단 팩스 합본ㆍ입금 자동발행의 붙임까지 모두 이것을 거치므로,
한 곳만 고치면 세 갈래가 함께 바뀐다.

**담긴 값(신고한 값)은 한 글자도 바꾸지 않았다.** 국세청에 간 것은 그 값이고, 되짚어
고치면 기록과 어긋난다. **그릴 때만** 바꾼다.

## ① 주민등록번호 — 가리지 않고 적는다

`tax_invoice_biz_no` 는 평문 칸이라 발행할 때 **일부러 가려서** 담는다(P0-1 보안 결정).
원문은 처방전ㆍ거래처의 암호화 칸에만 있다. 그래서 종이에도 가려진 채로 찍혔다.

```
520917-1******   ← 여태 찍히던 것. 번호가 없으면 반려 사유다
520917-1234567   ← 이제 찍히는 것
```

그릴 때 원문을 연다 — 처방전의 `residentNoOcrFor()` 를 먼저 보고, 없으면 거래처의
`residentNoFor()` 를 본다. **여는 자리마다 감사로그가 남는다**(사유 「세금계산서 서식
출력」). 원문을 찾지 못하면 담긴 값(가려진 번호)을 그대로 쓴다 — 지어내지 않는다.

**짚어 둘 것** : 이 종이를 PDF 로 저장하면 그 파일에 주민번호 원문이 들어간다. 공단에
내는 서류라 그래야 하지만, 파일을 다루는 자리에서 조심해야 한다.

## ② 상호ㆍ성명 — 동명이인 꼬리를 뗀다

```
이영주A → 이영주      (상호ㆍ성명 두 칸 모두)
```

`A`ㆍ`G` 는 같은 이름을 가르려고 **우리가** 붙인 글자이지 그 사람의 이름이 아니다.
`Patient::실명()` 으로 뗀다 — 붙여 쓴 꼬리만 떼므로 상호 「주식회사 AB」는 깎이지 않는다.

**국세청에는 꼬리가 붙은 채로 신고되어 있다.** 341건 가운데 37건(칸으로는 74개)이 그렇다.
이제 종이와 신고 내용이 그 글자 하나만큼 달라진다 — 수정 발행을 할지는 업무 판단이라
손대지 않았다.

## ③ 사업장 주소 — 주소만 남긴다

상세주소 칸에 받는 사람과 전화번호를 함께 적어 둔 건이 많아 그대로 찍혔다.

```
앞 : (04574) 서울 중구 난계로15길 5 3층(010-4587-4167) 010-7313-4107
뒤 : (04574) 서울 중구 난계로15길 5 3층

앞 : (16401) 경기 수원시 … 1601호((E)정지영 010-2998-5884(보호자)) (E)정지영 010-2998-5884(보호자)
뒤 : (16401) 경기 수원시 … 1601호
```

걷는 차례가 중요하다.

1. `(E)` 와 그 뒤에 붙은 이름을 뗀다
2. **전화번호가 처음 나오는 자리에서 뒤를 통째로 자른다** — 주소는 늘 그 앞이다
3. 자르면 괄호가 열린 채 끝날 수 있다 — 짝 없는 여는 괄호부터 끝까지 자른다
4. 「○○○님」처럼 받는 사람을 적어 둔 꼬리를 뗀다

우편번호 `(21065)` 와 법정동 `(공릉동)` 은 괄호 안에 전화번호가 없으므로 **남는다.**

### 떼지 않은 것 하나

**홀로 선 이름은 떼지 않았다.**

```
(10077) 경기 김포시 전원로 27 102동 303호 김슬기((E)김재평 010-9010-5522) …
                                      ↓
(10077) 경기 김포시 전원로 27 102동 303호 김슬기
```

지우려면 사람 이름인지 건물 이름인지 갈라야 하는데, 「라온채」 같은 세 글자 건물명과
구별할 길이 없다. **주소를 깎는 쪽이 더 나쁘다.** 걸리는 건이 있으면 거래처관리에서
상세주소를 고치는 것이 맞다.

## 얼마나 되나 (운영 `unicorn_mycolo` · 10-01 ~ 10-15)

```
세금계산서 발행           341건
   등록번호가 가려진 것    341건  ← 모두 ①에 해당한다
   이름에 꼬리가 붙은 것    74개(37건 × 상호ㆍ성명)
   주소에 전화번호         307개
   주소에 (E)              254개
```

## 확인한 것

주소 거르개를 운영에서 뽑은 실제 보기 열 개와 **건드리면 안 되는 주소 세 개**로
먼저 시험했다. 열 개는 모두 주소만 남았고, 정상 주소 셋은 한 글자도 바뀌지 않았다.

올린 뒤 **운영 342건을 전수로** 돌려 세 칸이 실제로 어떻게 찍히는지 보았다.

```
① 주민번호 13자리로 열렸다   342건
   아직 가려져 있다             0건
② 아직 꼬리가 남은 것           0개
③ 전화번호가 남은 것            0개
   (E) 가 남은 것               0개
   거르다가 비어 버린 것        0건   ← 주소를 통째로 깎은 건이 없다
```

찍히는 모습(주민번호는 여기 적을 때만 가린다).

```
EUD202610011108171
   등록번호 850313-*******
   상호 정지영 · 성명 정지영
   주소 (16401) 경기 수원시 권선구 칠보로 102 102동 1601호
```

서식이 실제로 그려지는지도 다섯 건으로 보았다 — 모두 `%PDF` 로 시작하는 54~55KB
파일이 나온다. **결과물은 저장하지 않았다** — 주민번호 원문이 든 파일을 남길 일이 없다.

## 하다가 낸 오류 둘

### ㈎ 복호화 사유 코드를 지어냈다

`residentNoOcrFor('세금계산서 서식 출력')` 로 적었더니 **복호화가 통째로 거절**됐다.

```
RuntimeException  허용되지 않은 복호화 사유 코드입니다: 세금계산서 서식 출력.
```

사유 코드는 `config/rrn.php` 에 등록된 것만 쓸 수 있고, 이 용도의 코드가 **이미 서 있었다**
— `tax_invoice`(「전자세금계산서 공급받는자(개인) 주민등록번호 기재」). 지어내지 말고
먼저 목록을 읽었어야 했다. 바로잡아 올렸다(`41fff6b7`).

### ㈏ 소스에 제어문자를 집어넣었다

주소 거르개 끝에서 `trim()` 의 둘째 인자를 쓰다가 이스케이프가 풀려 **실제 탭ㆍ개행ㆍ
NUL 바이트**가 소스에 박혔다. 파일이 바이너리로 취급되어 `git diff` 가 내용을 보여 주지
못했다. 이스케이프가 필요 없는 정규식으로 바꿨다.

`php -l` 은 통과했다 — 문자열 안의 NUL 은 문법 오류가 아니다. **문법 검사만으로는
못 잡는다.** 앞으로 이런 치환을 하면 `file` 로 파일 갈래를 함께 본다.
