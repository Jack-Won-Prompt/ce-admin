# 「문자는 시늉이라 안 나간다」고 잘못 판단했다

- 날짜 : 2026-10-15
- 어디 : 시험 서버 ceadmin.co.kr (DB `colo_unicorn`)
- 무엇 : 바탕 시험을 돌리기 전에 「문자는 시늉이라 환자에게 나가지 않는다」고 적었는데,
  **실제로는 적힌 번호로 그대로 나가는 상태**였다

## 내가 본 값과 실제로 쓰이는 값이 달랐다

```
popbill.sms_simulate = true     ← 내가 본 것 (옛 열쇠)
popbill.sms_mode     = 'live'   ← 실제로 쓰는 것
```

`config/popbill.php` 는 이렇게 되어 있다.

```php
'sms_mode' => env('POPBILL_SMS_MODE')
              ?: (env('POPBILL_SMS_SIMULATE', env('POPBILL_IS_TEST', true)) ? 'simulate' : 'live'),
```

`sms_simulate` 는 **`sms_mode` 가 비어 있을 때만** 보는 옛 열쇠다. 시험 서버의 `settings`
표에는 `sms_mode = live` 가 담겨 있어 옛 열쇠가 **아예 읽히지 않는다.**

발송하는 자리(`MessageService::send`)도 `sms_mode` 만 본다 — 세 갈래다.

| 값 | 하는 일 |
|---|---|
| `live` | **적힌 번호로 보낸다** ← 지금 이 값 |
| `redirect` | 시험 받는 번호(`01057990084`)로 돌린다 |
| `simulate` | 보내지 않고 `SIM-…` 접수번호만 돌려준다 |

`sms_simulate` 가 `true` 여도 `live` 면 **그냥 나간다.**

## 이번에 나간 것 — 다행히 우리 폰이었다

```
09:52  결제 링크 안내   01084860533  접수 026101509000000963  state=3 result=100
09:57  가상계좌 안내     01084860533  접수 026101509000001056  state=3 result=100
```

팝빌에 접수번호로 되물었더니 둘 다 **완료ㆍ성공**이고 통신사는 SK 다. 즉 진짜 나갔다.

그런데 `01084860533` 은 **우리 사람 번호**다.

```
users #11  Stella Kim    krsk@coloplast.com     01084860533
users #35  모바일시험     mtest@ce-admin.co.kr   01084860533
처방전 #672 의 mobile_ocr                        01084860533
환자 (E)김선미(#12985) 의 환자표 번호             (비어 있다)
```

내가 집은 처방전이 **모바일시험 계정으로 올린 시험 건**이었고, 환자 번호 칸이 비어 있어
처방전에 적힌 시험 폰으로 갔다. **운이 좋았던 것이지 막혀서 안 간 것이 아니다.**

## 지금 남아 있는 위험

`sms_mode = live` 인 채로 시험 서버에서 **실제 환자 번호가 든 건**을 집으면 그 환자에게
진짜 문자가 간다. 이 DB 에는 운영 거래처 12,608명이 복제되어 있다.

이미 그렇게 나간 자취가 있다.

```
message_histories 721줄 · 성공 678통
   우리 사람 번호로 : 353통
   밖의 번호로      : 번호 226개 · 325통
      그 가운데 거래처ㆍ환자 표에 있는 번호 177개
      어느 표에도 없는 번호 49개

날짜별 (밖의 번호)
   10-01  3통 · 09-30 42 · 09-29 42 · 09-28 36 · 09-23 54
   09-22 71 · 09-21 73 · 09-20 3 · 09-19 1
   10-02 ~ 10-14 : 0통
```

다만 **9월 하순의 이 발송은 정상 업무였을 수 있다** — 운영 도메인이 mycolo.co.kr 로
넘어간 것이 09-21 이고, DB 가 `unicorn_mycolo` 로 갈린 것은 10-10 이다. 그 전까지
`colo_unicorn` 이 운영이었다면 이 325통은 환자에게 가야 했던 글이다. 이 기록은
**그렇다고 단정하지 않는다** — 셈만 적어 둔다.

10-02 이후로는 밖의 번호로 간 것이 없다.

## 고칠 것

- **아직 고치지 않았다.** 시험 서버의 `sms_mode` 를 `redirect` 로 돌려 두면 시험 중에
  환자에게 갈 일이 없어진다(시험 받는 번호 `01057990084` 가 이미 담겨 있다). 그러나
  설정 한 칸을 저장하면 같은 묶음의 다른 스위치가 꺼진 적이 있어
  (`project_service_settings_checkbox_trap`) 지시를 받고 하겠다.
- **내 점검 버릇을 고친다** — 갈래를 가르는 값은 `simulate` 가 아니라 `mode` 를 읽는다.
  앞으로 시험 서버에서 무엇이 밖으로 나가는지 볼 때 다음 넷을 함께 읽는다.

```
popbill.sms_mode   popbill.fax_mode   popbill.issue_simulate   popbill.env
```

`settings` 표가 정본이므로 `.env` 나 옛 열쇠를 보고 판단하지 않는다
(`project_popbill_settings_live_in_db`).
