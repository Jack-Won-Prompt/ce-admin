# 창고는 출고를 끝냈는데 우리는 모른다 — 오늘 so.shipped 가 한 건도 오지 않았다 (2026-10-15)

## 어떻게 드러났나

「위드웍스와 상태 값이 같은가」를 보려고, 처음에는 **우리 표 안에서** 주문 상태와
위드웍스 칸을 견주었다. 어긋남 1건이 나왔고 (E)박금신 건을 「창고가 피킹을 되돌렸다」고
적었다. **틀린 읽기였다.**

창고 표(`schedule_by_ships`)를 직접 열자 그 줄은 **55 피킹완료**였다. 우리 주문 상태
`picked` 와 같다. 뒤처진 것은 창고가 아니라 **우리 `withworks_ship_status` 칸**으로,
13:56 에 적힌 `02 신규` 에 멈춰 있었다.

우리 칸끼리 견주면 우리 칸이 틀린 것을 찾을 수 없다. **정본은 창고 표다.**

## 뿌리 — 오늘 so.shipped 가 한 건도 오지 않았다

받은 사건을 사건별로 세었다(최근 7일).

```
so.created        256건 · 마지막 2026-10-15 15:40:18
so.confirmed      238건 · 마지막 2026-10-15 16:00:09
so.allocated      259건 · 마지막 2026-10-15 14:20:32
so.picked         259건 · 마지막 2026-10-15 15:40:35
so.invoiced       241건 · 마지막 **2026-10-14 18:08:39**
so.shipped        241건 · 마지막 **2026-10-14 17:39:45**
```

등록ㆍ확정ㆍ할당ㆍ피킹은 오늘도 들어온다. **송장(invoiced)과 출고(shipped)만 어제
저녁부터 멈췄다.** 그런데 창고 표에는 오늘 출고완료가 서 있다(최재웅 15:57, 정영애
05:22, 김병근 05:23, 김용녀 05:24). 창고는 나갔고 우리는 듣지 못했다.

이것이 막으면 이어서 셋이 멈춘다.

1. **출고 안내**(문자ㆍ알림톡)가 환자에게 가지 않는다
2. `shipped_at` 이 비어 **청구 기한(출고일＋2주)** 이 세어지지 않는다
3. 입금이 먼저 들어와 미뤄 둔 **증빙 자동 발행**(`DepositAutoIssue`)이 돌지 않는다

## 우리 쪽 그물도 함께 찢어져 있었다

웹훅이 멈춰도 10분마다 도는 훑기가 메우게 되어 있다. 그 길이 두 군데서 막혀 있었다.

**① 출고 상태 이름표를 둘만 안다.**
`WithworksSync::DB_SHIP_LABEL` 은 `02 신규`ㆍ`95 출고완료` 두 가지뿐이고,
`출고맞추기()` 는 이름을 모르는 코드를 **적지 않고 물러난다**.

```php
if (isset(self::DB_SHIP_LABEL[$코드])) { ...적는다... }
else { Log::info('모르는 출고 상태 — 이름을 적지 않는다'); }
```

창고에 실제로 서 있는 코드는 `02 7건 · 14 1건 · 55 50건 · 95 360건 · 98 3건` 이다.
**14ㆍ55ㆍ98 은 영영 적히지 않는다.** 박금신이 02 에 멈춘 자리가 바로 이것이다.

그런데 **같은 파일에 이름표가 이미 다 있다** — `WithworksSync::SHIP_STATUS` 는 창고
화면의 고르는 칸을 그대로 옮겨 적은 열다섯 가지다(2026-08-31 확인). `DB_SHIP_LABEL` 은
그것을 모르고 새로 좁게 만든 둘째 지도다.

**② 훑기가 돌 때마다 같은 자리를 지우고 다시 적는다.**
`pull()` 은 `apply(full: true)` 로 출고 칸을 전부 `null` 로 밀고 시작한다. 응답에
`ship` 묶음이 없으면 그대로 비고, 뒤이어 `출고맞추기()` 가 출고번호만 다시 채운다.
그래서 (E)정영애 건에 **5분마다 같은 기록이 쌓였다**(14:21ㆍ14:41ㆍ15:02ㆍ15:30ㆍ15:51
「출고 정보를 저쪽 자료로 맞췄습니다 — 상태 98」). 상태는 한 번도 남지 못했다.

## 손대기 전에 멈춘 자리

`DB_SHIP_LABEL` 을 `SHIP_STATUS` 로 넓히면 출고 상태가 제대로 적힌다. 그런데
`apply()` 는 출고 상태가 `95`ㆍ`98` 로 바뀌는 순간 **환자에게 출고 안내를 보내고**
증빙 자동 발행을 돌린다.

그러면 위 표의 다섯 건에 안내가 한꺼번에 나간다. 그 가운데 둘은 보내서는 안 된다.

* **(E)정영애** — 81,000원을 **받지 않았는데** 물건이 나갔다
* **(E)김한극** — **취소한 주문**인데 405,000원어치가 나갔다

그래서 고치지 않고 멈췄다. 사람이 정할 일이다.

## 창고 쪽 사정 — 같은 판매번호에 저쪽이 줄을 더 세웠다

두 건의 저쪽 줄을 `so_id` 까지 짝지어 보았다.

```
(E)정영애  so S2610140027
   판매 681994 · 02 · remark [CE-ADMIN] RX-20261008-011 / 환자: (E)정영애   ← 우리가 세운 줄
   판매 682326 · 95 · remark 없음 · 10-15 00:20 생성                        ← 저쪽에서 선 줄
      출고 757107 · 98 오더종결 · SH2610140027 · 완료 10-15 05:22

(E)김한극  so S2610120014
   판매 681110 · 99 · remark [CE-ADMIN] RX-20261012-003 / 환자: (E)김한극   ← 우리가 세우고 취소한 줄
   판매 681133 · 95 · remark 「화물」 · 10-12 09:19 생성                     ← 저쪽에서 선 줄
      출고 755812 · 95 출고완료 · SH2610120015 · 완료 10-12 17:12
   판매 681523 · 95 · remark 없음 · 10-13 00:19 생성
      출고 756201 · 98 오더종결 · SH2610120015 · 완료 10-13 05:27
```

우리가 세운 줄에는 `[CE-ADMIN]` 과 처방전 번호가 remark 에 적힌다. 나간 물건이 달린
줄에는 그것이 없다 — **창고 쪽에서 같은 판매번호로 새 줄을 세워 출고했다.** 우리가
취소한 뒤에도(김한극 10-12 09:44 취소 → 17:12 출고) 나갔다.
