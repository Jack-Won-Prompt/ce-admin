# 위드웍스에서 이미 나간 건에 우리 주문번호와 주문 등록일이 났다 — 61건

- 날짜 : 2026-10-13
- 확인 요청 : 「주문등록 판매상태:위드웍스 출고완료건들에 대해서 주문등록일과 주문번호가 없어야 하는 것 같은데 확인 요청 / 만약 주문 등록일이 있으면 등록일 10월로 조회 시, 위드웍스와 CEadmin 건 수에 중복으로 포함되는 것 같은데 정밀 검증」
- 결과 : **지적하신 그대로입니다.** 61건이 그렇습니다.

## 무엇이 보였나

(E)지순란 님 줄이 그 보기입니다.

| 주문 등록일 | 위드웍스 추가정보 등록일 | 주문번호 | 참조번호 | 판매상태 |
|---|---|---|---|---|
| 2026-10-06 | 2026-07-10 | EUD202610061232161 | WW-ADD0047405 | 위드웍스 출고완료 |

위드웍스에서 **2026-07-10 에 이미 나간 건**인데, 우리 주문번호가 2026-10-06 자로 났습니다.

## 왜 그랬나 — 소스에서 확인한 자리

주문 줄은 처방전 목록의 **「주문등록 이동」**이 세웁니다
(`PrescriptionController::approve()` → `OrderSync::ensure()`).

`OrderSync::seed()` 의 문턱은 다섯입니다 — 빈 초안이 아닐 것, 상담만 적은 것이 아닐 것,
유형을 골랐을 것, 검수가 `approved`ㆍ`ordered` 일 것, 거래처가 붙었을 것.

**위드웍스에서 이미 끝난 건인지는 보지 않습니다.** 그래서 담당자가 이관된 처방전을 열어
「주문등록 이동」을 누르면, 저쪽에서 2021년ㆍ2023년ㆍ올해 7월에 이미 팔려 나간 건에도
새 주문번호가 나고 주문 등록일이 **누른 날**로 섭니다.

`Order::대기이름()` 의 주석에는 이 상태를 두고 이미 이렇게 적혀 있습니다 —
「이 건은 애초에 서지 말아야 했던 주문이다」. 2026-10-12 에는 **화면 표시만** 고쳤고
(판매상태를 「위드웍스 출고완료」로 적게 함), 주문이 서는 것 자체는 막지 않았습니다.
