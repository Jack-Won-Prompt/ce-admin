# 배송지가 두 번 적히고 「(E)」가 환자에게 갔다

- 날짜 : 2026-10-13
- 드러난 자리 : (E)최상은 건의 문자를 들여다보다가 같은 글에서 함께 보였다
- 고친 것 : `f7711d2c`

## 무엇이 보였나

```
2. 주소: 인천 중구 하늘별빛로 66 영종힐스테이트 908동 2204호((E)최상은 010-3061-3623) (E)최상은 010-3061-3623
```

- 받는 사람과 전화번호가 **두 번** 적혔다
- **「(E)」가 환자에게 갔다.** 우리끼리 쓰는 사업부 표시다 — 2026-09-27 에 환자에게
  가는 글에서 떼기로 했고, 이름 자리는 그때 고쳤는데 **주소 자리는 남아 있었다**

## 까닭

`orders.shipping_address` 칸 자체에 이미 두 벌이 담겨 **저장돼** 있었다.

```
shipping_address        인천 … 2204호((E)최상은 010-3061-3623) (E)최상은 010-3061-3623
shipping_address_detail (E)최상은 010-3061-3623
```

거래처 주소 줄(`patient_addresses`)의 `address` 가 「…2204호**((E)이름 전화)**」 꼴로
상세까지 품은 것이 있다 — 이관분이 그렇다. 주문 화면은 그 값을 「도로명 주소」 칸에
넣고 상세 칸을 따로 채운 뒤, 저장할 때 **아무 조건 없이 이어 붙였다.**

```js
shippingBase + ' ' + shippingDetail
```

적어 보내는 쪽(`주소한줄()`)은 「이미 품고 있으면 덧대지 않는다」를 지켰다 — 그 잣대는
제대로 돌았다. 두 벌이 된 것은 **저장 때**다. 그래서 보내는 쪽을 들여다봐도 범인이
보이지 않았다.

## 번진 범위

| 잣대 | 수 |
|---|---|
| 거래처 주소 줄의 `address` 에 「(E)」가 섞인 것 | 7,068 / 21,122건 |
| 저장된 배송지에 상세가 두 번 적힌 주문 | **191 / 277건** |
| 결제 링크 문자 가운데 「(E)」가 실려 나간 것 | **212 / 308통** |

## 고친 것

이미 그렇게 담긴 값은 **되돌리지 않는다** — 거래처 주소는 이관분이라 지우지도 고치지도
않는다(운영 데이터 규칙). 대신 두 자리를 막았다.

1. **적어 보낼 때** — `Order::배송지한줄()` 이 두 번째부터를 뒤에서 걷어 내고, 상세를
   떼어 괄호만 남은 자리(`…2204호()`)를 치우고, 「(E)」를 뗀다. 문자와 알림톡이 같은
   줄을 쓴다 — 여태 알림톡은 `shipping_address` 를 날것으로 적어 겹침이 그대로였다.
2. **새로 저장할 때** — 주문 화면의 세 자리에서 기본주소가 이미 상세를 품고 있으면
   덧대지 않는다.

고친 뒤 최상은님 건은 이렇게 선다.

```
2. 주소: 인천 중구 하늘별빛로 66 영종힐스테이트 908동 2204호(최상은 010-3061-3623)
```
