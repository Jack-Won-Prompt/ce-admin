# 담당자 배정에서 「The order_ids.0 field must be an integer」 (2026-10-15)

## 무엇이 보였나

주문 등록 화면의 주문 목록에서 한 줄을 골라 **담당자 배정** → **1건 배정하기** 를
누르면 화면 오른쪽 아래에 영문 한 줄만 떴다.

```
The order_ids.0 field must be an integer.
```

담당자는 바뀌지 않는다. 무엇이 잘못됐는지 알 길도 없다 — 우리말 안내가 아니고,
어느 줄 때문인지도 적혀 있지 않다.

확인요청에 딸린 화면에서는 **「이미 다른 담당자가 배정되어 있습니다」 → 「담당자 변경」**
으로 들어간 길이었고, 그 건은 `RX-20261006-052 · (E)김여정` 으로 **주문번호가 「—」**
였다.

## 왜 그랬나

주문 목록에는 두 가지 줄이 함께 선다.

* 주문이 선 줄 — `id` 에 주문 id 가 있다
* **주문이 아직 없는 줄** — 처방전은 들어왔는데 주문이 서지 않은 건
  (`PrescriptionController.php` 의 「주문 없는 처방전」 묶음, 화면에는 「주문 없음」)

뒤쪽 줄은 주문이 없으므로 `'id' => null` 로 만든다. 그런데 화면은 고른 줄의 `id` 를
그대로 모아 보냈다.

```js
order_ids: olAsRows.map(r => r.id),     // → [null]
```

서버는 정수만 받는다.

```php
'order_ids'   => 'required|array|min:1',
'order_ids.*' => 'integer',
```

`null` 이 걸려 422 로 되돌아왔고, 화면은 그 영문을 그대로 띄웠다.

**담당자는 본디 처방전에 붙는다.** 주문을 거쳐야 할 이유가 없는 일인데, 보내는 열쇠가
주문 번호 하나뿐이어서 주문 없는 건이 통째로 막혀 있었다. 그 자리의 주석도 「처방전이
없는 주문도 넘길 수 있어야 한다」고만 적어 두었다 — **반대쪽(주문이 없는 처방전)은
생각하지 못한 것이다.**

## 고친 자리

**① 줄에 처방전 번호를 함께 싣는다** (`PrescriptionController::주문목록쪽`)

```php
'id'    => null,
'rx_id' => $rx->id,      // 담당자 배정이 이것으로 넘어간다
```

**② 화면이 둘로 나눠 보낸다** (`resources/views/prescriptions/order.blade.php`)

```js
order_ids: olAsRows.filter(r => Number(r.id) > 0).map(r => Number(r.id)),
rx_ids:    olAsRows.filter(r => !(Number(r.id) > 0) && Number(r.rx_id) > 0)
                   .map(r => Number(r.rx_id)),
```

**③ 서버가 둘 다 받는다** (`PrescriptionController::bulkAssign`)

주문에서 온 것과 처방전에서 바로 온 것을 한 묶음으로 모은다. 같은 처방전이 두 길로
들어와도 한 번만 다룬다. 둘 다 비었을 때만 막고, 그때는 **우리말로** 말한다.

```php
'order_ids' => 'nullable|array',
'rx_ids'    => 'nullable|array',
...
return response()->json(['success' => false,
    'message' => '담당자를 배정할 건을 목록에서 선택해 주십시오.'], 422);
```

**④ 돌려주는 줄에 처방전 번호를 더한다.** 화면은 바뀐 줄만 고쳐 그리는데, 주문이 없는
줄은 `order_id` 가 `null` 이라 짝이 서지 않았다. `rx_id` 로 찾는 길을 함께 둔다.

## 시험 (시험 DB · colo_unicorn)

실제 컨트롤러를 그대로 불러 돌렸다.

```
주문 없는 처방전 한 건
   응답 200 · moved 1 · rows[{order_id: null, rx_id: 889, rx_number: RX-20260930-004}]
   다시 읽은 담당자 : 바뀐 사람

주문 있는 줄 + 주문 없는 줄 섞어 한 번에
   주문 584 · 처방 898 · RX-20261001-001 → 원동희
   주문 NULL · 처방 889 · RX-20260930-004 → 원동희
   둘 다 바뀜 확인

같은 처방전을 두 길로(order_ids 와 rx_ids 동시에)
   바뀐 줄 1건 · 그대로 0건   ← 두 번 세지 않는다

아무것도 고르지 않고
   422 · 「담당자를 배정할 건을 목록에서 선택해 주십시오.」
```

시험으로 바꾼 담당자는 모두 본디 값으로 되돌렸다(#889 May park · #898 Blue Kang).
