# 에스크로 엑셀에서 운송장번호가 `6.00885E+11` 로 깨져 보였다

- 날짜 : 2026-10-15
- 알린 이 : 운영 담당자 — 「주문 관리 화면에서 토스 에스크로 엑셀 내용에서 값이 깨짐」
- 어디 : 주문 관리 › 토스 에스크로 배송정보 엑셀 · `배송정보` 장 D 칸(운송장번호)

## 무엇이 보였나

```
운송장번호
 8952388931      ← 양식의 예시(열 자리). 멀쩡하다
 6.00885E+11     ← 우리가 담은 값(열두 자리). 깨져 보인다
 6.0089E+11
 6.00867E+11
 …
```

## 까닭 — 엑셀의 기본 서식은 **열한 자리까지만** 자릿수를 그대로 보인다

엑셀의 `General` 서식은 숫자가 열두 자리를 넘으면 **지수 표기로 바꾼다.** 열 너비를
아무리 넓혀도 그렇다. 셀을 눌러 보면 수식 입력줄에는 `600885123456` 이 멀쩡히 있다 —
**담긴 값은 맞고 보이는 것만 틀린** 것이라 더 나빴다.

우리 엑셀은 서식을 하나도 주지 않았다. `XlsxWriter` 의 `styles.xml` 에 선 꼴이 셋뿐이고
셋 다 `numFmtId="0"`(General)이었다.

```xml
<cellXfs count="3">
  <xf numFmtId="0" …/>                    <!-- 보통 -->
  <xf numFmtId="0" … applyFont="1"/>      <!-- 굵게 -->
  <xf numFmtId="0" … applyAlignment="1">  <!-- 줄바꿈 -->
</cellXfs>
```

운송장번호는 `'숫자칸' => [1, 3]` 으로 **숫자**로 담고 있었다. 숫자인데 서식이 General
이니 열두 자리에서 지수로 넘어간 것이다.

**왜 늦게 드러났나** — 양식에 박힌 예시 `8952388931` 이 열 자리라 멀쩡했다. 담당자가
예시 줄만 보면 아무 문제가 없어 보인다. CJ 운송장번호는 열두 자리다.

## 고친 것 — 값은 그대로, **서식만** 정수로

`XlsxWriter` 에 정수 서식을 한 꼴 더하고(`numFmtId="1"` = 내장 서식 「0」), 장 설정에
`정수칸` 을 받는다. `EscrowSheet` 의 배송정보 장은 B·D 를, 수령정보 장은 B 를 정수칸으로
적었다.

```php
'숫자칸' => [1, 3],
'정수칸' => [1, 3],   // ← 더한 것
```

**자료형도 값도 바꾸지 않았다.** 셀은 그대로 숫자(`<v>600885123456</v>`)이고 서식만
`0` 이 붙는다. 그러므로 **토스가 읽는 것은 달라지지 않는다** — 보이는 것만 고친다.

글자(문자열)로 바꾸는 길도 있었지만 쓰지 않았다. 토스 양식의 예시가 숫자이고, 저쪽이
숫자를 기대하는지 아닌지 우리가 알 수 없다. 받는 쪽 동작이 달라질 여지가 없는 쪽을
골랐다.

## 확인한 것

같은 자료로 고치기 전/후 파일을 지어 견주었다.

```
before.xlsx   D2 8952388931   서식 General
              D3 600885123456 서식 General   ← 엑셀에서 6.00885E+11 로 보이던 것
after.xlsx    D2 8952388931   서식 0
              D3 600885123456 서식 0         ← 자릿수 그대로 보인다
```

셀 XML 도 확인했다 — 값과 자료형은 그대로이고 꼴만 `s="3"` 이 붙는다.

```xml
<c r="D3" s="3"><v>600885123456</v></c>
```

**엑셀로 직접 열어 보지는 못했다.** 이 PC 의 엑셀 자동화(COM)가 응답하지 않아 화면을
눈으로 확인하지 못했고, LibreOffice 는 엑셀의 열한 자리 규칙을 흉내 내지 않아 전후가
똑같이 나온다. 서식이 `0` 으로 붙은 것까지는 기계로 확인했으니, **담당자가 새로 받아
한 번 열어 봐 주셔야 끝**이다.

## 번진 데가 있나 — 없다

- `XlsxWriter` 를 쓰는 자리는 에스크로 엑셀 한 곳뿐이다.
- 운송장번호를 싣는 다른 내보내기는 없다. 주문관리 CSV 의 칸 목록에 운송장번호가 없다.
- 그 CSV 의 주민등록번호는 가려진 값(`*` 섞임)이라 글자로 서서 같은 문제가 없다.

## 이미 받아 둔 파일

전에 받은 파일은 깨진 채로 보인다. **다시 받으면 된다** — 담긴 값은 처음부터 맞았으므로
토스에 올린 것이 잘못되지는 않았다. 다만 그 화면을 보고 손으로 옮겨 적은 것이 있다면
지수로 읽힌 값일 수 있으니 한 번 견주어 보시는 것이 좋다.
