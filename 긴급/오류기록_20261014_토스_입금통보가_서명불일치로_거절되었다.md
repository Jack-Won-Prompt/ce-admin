# 토스 입금 통보가 서명 불일치로 401 거절되어 돈이 장부에 남지 않았다

- 날짜 : 2026-10-14
- 지시 : 「가상계좌 입금완료 통보가 정상적으로 처리되지 않았습니다 => 토스에서 이메일 받음 상황 확인 및 검증」 → 「가」(놓친 건을 지금 처리)
- 올린 것 : `f66e6801`

## 토스 메일이 맞았습니다

**돈이 들어왔는데 우리 장부에 없는 건이 3건(243,000원)** 있었습니다.

| 주문 | 환자 | 금액 | 토스 승인 |
|---|---|---|---|
| EUD202610121331501 | (E)류기현 | 81,000원 | 10-14 15:18:20 |
| EUD202610141429271 | (E)최종혁 | 81,000원 | 10-14 15:05:15 |
| EUD202610141434531 | (E)박우범 | 81,000원 | 10-14 15:25:37 |

## 까닭 — 토스가 서명을 붙이기 시작했고 우리 셈이 달랐다

```
토스 웹훅에 서명 헤더가 붙어 온 날
   10-10  0건 · 10-11  0건 · 10-12  0건
   10-13  6건   ← 이때부터
   10-14 40건   ← 점점 늘었다
```

서명이 붙은 것은 **전부 401 「서명 불일치」**, 서명이 없는 것은 그대로 200 이었습니다.
첫 401 은 **2026-10-13 10:47:58** 입니다.

우리는 `HMAC-SHA256(본문 + ':' + 시각)` 으로 맞춰 보는데 토스 것과 다릅니다.

놓친 3건은 토스가 **각각 9~12회 재시도**했고 모두 401 로 막혔습니다. 그래서
현금영수증ㆍ세금계산서ㆍ위드웍스 확정ㆍ결제 완료 안내가 하나도 나가지 않았습니다.

## 막은 것 — 서명이 안 맞아도 거절하지 않는다

그래도 되는 까닭이 둘입니다.

1. **주소에 박은 열쇠가 그 위에서 이미 걸러 냅니다**(`WebhookKeys::맞나`). 서명 검사로
   오는 요청은 그 열쇠를 지난 것뿐입니다.
2. **처리하는 자리가 본문을 믿지 않습니다** — `paymentKey` 로 토스에 다시 물어 확인하고서야
   적습니다(`handleDepositWebhook`). 거짓이 심기지 않습니다.

어느 서명 꼴이 맞는지는 **지어내지 않았습니다.** 흔한 꼴 여섯을 모두 맞춰 보고 그 결과를
적어 둡니다(`TossClient::서명이맞는꼴`) — 운영에 들어오는 진짜 서명이 답을 알려 주면
그때 다시 막을 수 있습니다.

```
본문:시각 · 시각:본문 · 시각.본문 · 본문.시각 · 본문만 · 시각+본문
(base64 와 hex 를 모두 본다)
```

### 고친 뒤

```
15:45 뒤 토스 웹훅 15줄 — 200 15줄 · **401 0줄** ✓
   그중 서명이 붙어 온 것 5줄 — 모두 지나갔다
   우리 셈과 맞은 것 0줄  ← 여섯 꼴 가운데 맞는 것이 아직 없다
```

## 되살린 것

고친 것이 배포된 뒤 **토스 재시도로 2건이 저절로 들어왔고**((E)최종혁 ㆍ(E)박우범),
나머지는 손으로 되살렸습니다. 모두 **토스에 다시 물어 DONE 인 것만** 처리했습니다.

```
(E)류기현  입금 없음 → DONE · 입금 15:18:20 · 받은 돈 81,000원
           현금영수증 1건 · 세금계산서 1건 · 창고 S2610140196
(E)최종혁  입금은 적혔으나 증빙이 빠져 뒷일만 다시 돌림
           현금영수증 1건 · 세금계산서 1건 · 창고 S2610140277
(E)박우범  입금ㆍ증빙 모두 끝나 손대지 않음
```

주문마다 왜 그랬는지와 근거를 활동 이력에 적었습니다.

## 전수로 훑었다

```
① 우리는 입금 대기인데 토스는 받았다고 하는 것 : 0건 ✓
② 입금은 적혔는데 증빙이 하나도 안 나간 것(10-13 뒤) : 2건 → 모두 정상
     (E)박방래 EUD202610131512371 · (E)이진우 EUD202610141159561
     둘 다 **카드 승인이 있어 카드매출전표가 증빙**인 건이다(2026-10-07 · SR #89).
     거래명세서ㆍ카드매출전표ㆍ창고 확정ㆍ결제 완료 안내 모두 나갔다.
     내 훑기 잣대가 「현금영수증 0 + 세금계산서 0」이라 카드 결제에는 거칠었다.
```

## 남은 일 — 서명 꼴을 알아내야 한다

지금은 서명을 **보기만 하고 막지 않습니다.** 열쇠와 토스 재조회가 있어 안전하지만,
서명까지 맞출 수 있으면 한 겹 더 두텁습니다.

여섯 꼴 가운데 맞는 것이 없으므로, **토스페이먼츠에 서명 규칙을 물어보는 편이 빠릅니다** —
어떤 문자열을 어떤 차례로 이어 HMAC 을 걸고 어떻게 인코딩하는지. 알려 주시면 그대로
맞추고 다시 막겠습니다.

## 덧붙임 — 로그가 서명 값을 가린다

`webhook_logs.headers` 에 서명이 `(가림)` 으로 담겨, 지난 기록만으로는 어느 꼴이 맞는지
맞춰 볼 수 없었습니다. 지금은 들어올 때 여섯 꼴을 맞춰 보고 결과(`signature_ok`)를
남기므로, 맞는 꼴이 생기면 바로 드러납니다.
