# 출고 안내에 「#{송장번호}」가 글자 그대로 나갔다

- 날짜 : 2026-10-15
- 찾은 자리 : 오늘 현황을 훑다가 알림톡 실패 한 건을 쫓아서
- 받은 분 : (E)김시영 외 두 분 — **세 건, 여섯 통**

## 무엇이 나갔나

```
[콜로플라스트] 제품 출고 안내

주문하신 제품이 출고되었습니다.

-택배사:CJ택배
-운송장번호:#{송장번호}      ← 이대로 나갔다
```

## 까닭 — **자리표 이름이 둘이었다**

```
글을 짓는 자리(ShipNotice::compose)가 아는 것 :  #{운송장번호}
메시지 유형의 본문이 쓰는 것                   :  #{송장번호}
```

우리 문자는 본디 `#{운송장번호}` 를 썼다. 그런데 **알림톡 승인 문구가 `#{송장번호}`**
로 서 있고(알림톡 본문은 한 글자도 고칠 수 없다), 문구를 한 곳에서 관리하게 되면서
문자 본문도 그 이름으로 바뀌었다.

`compose()` 는 옛 이름만 찾는다. 그래서 운송장이 없을 때

- **그 줄을 걷지 못하고**(`#{운송장번호}` 가 든 줄을 찾는데 없다)
- **치환하지도 못해**(열쇠가 `#{운송장번호}` 뿐이다)

자리표가 그대로 나갔다.

운송장이 **있을** 때는 괜찮았다 — 보내는 자리가 `['#{송장번호}' => $tracking]` 을 따로
건네고 그쪽에서 치환되기 때문이다. 최근 358통 가운데 352통이 정상이고 여섯 통만
그랬다.

```
#3934 #3933  처방 84586 (E)김시영   2026-10-15
#2453 #2452  처방 84379             2026-10-12
#1176 #1175  처방 84315             2026-10-06
```

## 알림톡은 그 자리에서 거절됐다

```
[메시지] 묶음 발송 실패 {"channel":"alimtalk",
  "error":"「제품 출고 안내(20260924)」에 입력되지 않은 항목이 있습니다 : #{송장번호}"}
```

보내는 자리가 빈 값을 `array_filter` 로 걷어 **열쇠째 빠졌고**, 팝빌은 그것을
「입력되지 않은 항목」으로 돌려보낸다. 그러면 문자로 넘어가므로 **환자는 받기는
했다** — 다만 자리표가 든 글을 받았다.

## 고친 것 둘

**하나. 두 이름을 모두 본다.**

```php
$자리표 = ['#{운송장번호}', '#{송장번호}'];
// 줄 걷기도, 치환도 둘 다 건다
```

**둘. 운송장이 없으면 알림톡을 건너뛰고 문자로만 보낸다.**

알림톡 승인 문구는 그 변수를 비울 수 없다. 보낼 수 없는 것을 보내 보고 거절당하지
않는다 — 오류 줄이 매번 쌓이면 진짜 고장과 섞인다. 문자는 그 줄을 걷고 제대로 나간다.

## 운영에서 확인했다

```
운송장 있을 때  -운송장번호:600885123456      채널 alimtalk + sms
운송장 없을 때  (그 줄이 아예 없다)           채널 sms 만
```

## 이미 나간 여섯 통은 되돌릴 수 없다

문자는 회수가 되지 않는다. 받으신 세 분께는 운송장이 나오는 대로 담당자가 따로
알려 드리는 편이 좋겠다 — 「두 번 보내지 않는다」 잣대가 있어 같은 처방으로는 자동
발송이 다시 나가지 않는다.
