# (E)이완영 세금계산서 작성일자 정정 — 취소 후 재발행 (2026-10-16 지시)

## 왜 고쳤나

작성일자는 **공급시기**를 적는 칸이고, 우리 공급시기는 돈이 들어온 날이다
(2026-10-06 지시). 그런데 담당자가 10-16 에 손으로 발행하자 작성일자가 **오늘**로
찍혔다.

```
돈이 들어온 때   2026-10-12 14:09:01   가상계좌 13,500원
현금영수증       K00035842 · 거래일시 20261012
세금계산서       작성일자 20261016   ← 나흘 어긋남
```

수동 발행 화면이 작성일자를 보내지 않았고, 받는 쪽은 값이 비면 오늘로 적는다.
자동 발행은 입금일을 보내는데 손으로 낼 때만 빠져 있었다.

## 한 일 — 국세청 실신고 두 번

운영 팝빌은 `live` 갈래다. 취소와 재발행이 모두 국세청에 실제로 나갔다.

```
16:09:48   취소     202610164100020300002404   (작성일 20261016)
16:10:38   재발행   20261012410002030000718f   (작성일 20261012)
```

움직이기 전에 두 가지를 확인했다 — 발행 상태인가, 문서번호가 예상과 같은가.
취소 뒤에는 팝빌에 직접 물어 **600(발행취소)** 를 확인하고서 다시 냈다.

## 결과

### 팝빌에 직접 물은 값

```
TI20261016000559      600 발행취소      작성일 20261016 · 승인 202610164100020300002404
TI20261016000559-01   300 발행완료      작성일 20261012 · 승인 20261012410002030000718f
```

### 날짜가 맞는가

```
입금(공급시기)    2026-10-12 14:09:01
세금계산서 작성일 20261012   → 같다
현금영수증 거래일 20261012   → 같다
```

금액은 건드리지 않았다 — 공급가 110,455 · 부가세 11,045 · 합계 121,500원 그대로다.

### 서류

세금계산서 PDF 가 새 값으로 다시 붙었다(서류 #2087 · 10-16 16:10). 취소된 앞 건의
종이는 취소 처리에서 함께 걷혔다.

## 그 과정에서 드러난 것 — 취소 시각이 남는다

재발행 뒤에도 `tax_invoice_cancelled_at` 이 16:09:48 로 남았다. **오늘 아침 현금영수증에서
고친 것과 같은 자리**인데 세금계산서 쪽은 고치지 않았었다.

이 칸이 남으면 전자세금계산서 화면이 그 건을 「발행됨」으로 세우지 않는다.

```php
// Popbill/TaxinvoiceController.php
'issued' => $o->tax_invoice_status === 'issued' && ! $o->tax_invoice_cancelled_at,
```

### 고친 것

발행할 때 취소 시각을 비운다. 취소된 앞 건의 기록은 팝빌과 우리 표에 그대로 남는다.

```php
'tax_invoice_issued_at'    => $issuedAt,
'tax_invoice_cancelled_at' => null,
```

커밋 `c1e731e1`.

### 같은 증상 4건을 바로잡았다

팝빌에서 그 문서번호가 **살아 있는 발행 건인지 확인하고서** 비웠다.

```
EUD202610021058041 · (E)임귀라  · 304 국세청 신고완료 · 작성일 20261008
EUD202610081134061 · (E)최승훈  · 304 국세청 신고완료
EUD202610121352451 · (E)이완영  · 300 발행완료 · 작성일 20261012
EUD202610121542471 · (E)김정수C · 304 국세청 신고완료
```

네 건 모두 이제 전자세금계산서 화면에 **발행됨**으로 선다.

(E)임귀라 건은 발행과 취소가 **같은 초**(10-13 12:20:47)에 찍혀 자동 잣대에서 빠졌다.
활동 기록을 보니 「작성일자를 입금일로 정정」한 건이었다 — 같은 종류의 작업이다.
팝빌 상태를 확인하고 따로 비웠다.

## 수동 발행 화면도 고쳤다

세금계산서 발행 창에 **작성일자 칸**을 두고 **입금일로 미리 채운다**.

```
작성일자 *  [ 2026-10-12 ]
            공급시기입니다 — 입금일로 채웠습니다 (수정 가능)
```

자동 발행이 쓰는 값과 같다 — 담당자가 확인한 입금일이 먼저, 없으면 토스가 알려 준
입금 시각이다. 커밋 `5cbead9b`.

앞으로 뒤늦게 발행해도 작성일자가 어긋나지 않는다.

## 남은 확인 사항

세금계산서 금액이 **121,500원**인데 현금영수증은 **13,500원**이다. 본인부담 13,500 ·
공단부담 108,000 이므로 세금계산서는 청구전략에 따라 **전체 금액**으로 나간 것으로
보인다. 의도한 것이 맞는지 확인이 필요하다.
