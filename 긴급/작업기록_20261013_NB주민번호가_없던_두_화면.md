# NB주민번호가 없던 두 화면 (SR #171 · #191)

- 날짜 : 2026-10-13
- 알려 온 것 : 「NB주민번호 모든화면 재 확인 요청 — (E)진춘자, 처방전 구매 환자인데
  NB주민번호가 공란인 화면이 있음」 / 「모든 화면 연결필요 — 일부 화면에서 해당 정보가 없음」
- 고친 것 : `5c129676` → `b7607530`

## 알려 준 보기는 설계대로였다

(E)진춘자 님은 **기초(의료급여) · 청구처 지자체(local)** 다.

```
처방 WW-69495 · 자격 기초 · 청구처 local · 가린것 421015-2****** → NB 빈칸
```

NB주민번호는 **공단이 통장에 찍는 입금자명**이다 — 「NB + 주민번호 앞 여섯 자리」.
지자체는 기관마다 달라 정해진 규칙이 없어 비워 둔다. 없는 규칙을 지어내면 담당자가
그 값으로 통장과 맞추려 들고, 안 맞는 까닭도 알 수 없게 된다.

처방전 84,858장을 가른 결과다.

| 갈래 | 수 | |
|---|---|---|
| NB 가 섬 | 65,714장 | |
| 청구처가 건보가 아님 | 12,213장 | 지자체ㆍ해당없음 — **규정상 빈칸** |
| 청구처를 아직 고르지 않음 | 6,365장 | 고르면 선다 |
| **건보인데 주민번호를 못 뽑음** | **566장** | 메울 것이 있는 유일한 갈래 |

## 진짜 빠진 것 — 칸이 없는 화면 둘

NB주민번호가 **공통 묶음(`ceWwCols`)에만** 있었다. 그 묶음을 쓰는 12개 화면에는 서고,
쓰지 않는 화면에는 **칸 자체가 없었다.** 값을 보려면 주문 관리로 건너가야 했다.

| 화면 | 전 | 후 |
|---|---|---|
| 처방전 목록 | 없음 | **섰다** (엑셀에도) |
| 거래처 관리 | 없음 | **섰다** |

셈하는 잣대는 `OrderGridExtras::nb주민번호` 한 곳을 그대로 쓴다 — 화면마다 따로 세면
같은 사람이 화면마다 다른 값으로 선다.

거래처 관리는 청구처가 거래처에 없으므로 **그 사람의 가장 최근 처방전**의 청구처로
센다. 자격이 바뀌지 않는 한 사람마다 하나로 정해진다. 쪽에 선 사람만 한 번에 긁는다 —
줄마다 물으면 한 쪽에 쉰 번을 묻는다.

## 내가 낸 실수 하나

청구처를 한 번에 긁어 두고도 **닫힌 함수의 `use` 목록에 넣지 않았다.** 그래서 거래처
관리 100줄이 모두 빈칸으로 섰다. 화면에서 보고 바로 고쳤다(`b7607530`).

## 남은 것

건보 청구 건인데 **거래처에 주민번호가 없어** 여섯 자리를 못 뽑는 **566장**이 있다
((E)김화용ㆍ(E)송창훈A 님 등). 주민번호를 넣으면 저절로 선다 — 목록이 필요하면 뽑는다.
