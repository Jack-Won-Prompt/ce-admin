# 외부로 나가는 환자명에 (E) 와 알파벳 꼬리가 남아 있는가 — 세 자리가 남아 있다

- 날짜 : 2026-10-14
- 지시 : 「토스등 외부에 전달되는 환자명에 (E) 알파벳 제거 후 전달되고 있는지 확인」
- 결과 : **토스ㆍ팝빌은 깨끗합니다. 위드웍스(창고)로 가는 세 자리가 그대로 나갑니다.**

## 두 가지 다듬는 함수

| | 하는 일 | 보기 |
|---|---|---|
| `Patient::bare()` | `(E)` 만 뗀다 | (E)이정빈A → **이정빈A** |
| `Patient::실명()` | `(E)` 와 **동명이인 꼬리**를 뗀다 | (E)이정빈A → **이정빈** |

꼬리(`A`ㆍ`B`ㆍ`C`)는 같은 이름이 여럿일 때 우리가 붙인 표시이고 법적 이름이 아닙니다
(2026-10-06 · SR #90ㆍ#102). 밖으로 나갈 때는 `실명()` 이어야 합니다.

## 깨끗한 자리 ✓

본보기 (E)이정빈A 님으로 모든 길을 재었습니다.

```
토스 결제창 구매자명 (카드ㆍ간편결제)   「이정빈」 ✓
토스 가상계좌 예금주                    「이정빈」 ✓
팝빌 현금영수증 customerName            「이정빈」 ✓
팝빌 세금계산서 공급받는자              「이정빈」 ✓
환자에게 가는 알림톡ㆍ문자              「이정빈」 ✓
```

실제로 나간 값도 확인했습니다.

```
토스에 보낸 구매자명ㆍ예금주 15건 중 더러운 것 : 0건 ✓  (어제 만든 기록)
```

## 그대로 나가는 자리 ✗ — 모두 위드웍스(창고)로 간다

주문 `EUD202610131631121` · 거래처 (E)김연심B 로 창고에 보내는 내용을 그대로 뽑았습니다.

```
patient_name            「(E)김연심B」                                   ✗
recipient_name          「김연심B」                                      ✗
shipping_address        「경기 군포시 삼성로 41 608-603((E)김연심 010-5856-7037)」 ✗
shipping_address_detail 「(E)김연심 010-5856-7037」                       ✗
```

### ㈎ `patient_name` — 날이름 그대로

`WithworksLink::창고내용()` 이 `$patient?->name` 을 그대로 싣습니다. `실명()` 을 거치지
않습니다. 이 값으로 **저쪽에 거래처가 자동 등록**됩니다.

### ㈏ `recipient_name` — 꼬리가 남는다

`orders.shipping_recipient` 는 `Patient::bare()` 로 담겨 `(E)` 만 떨어지고 **꼬리는
남습니다.** 이 값이 **택배 송장의 받는 사람**이 됩니다.

```
배송 수령인에 꼬리가 남은 것 (9월 이후)
   10-13  6건   10-12  8건   10-08  3건   10-07 10건
   10-06  7건   10-02 13건   10-01 10건
```

**오늘 창고로 나간 40건 가운데에도 있습니다** — 이정민B · 김희자A · 김태연D …

### ㈐ 배송지 글 안에 `(E)이름` 이 섞여 있다

주소 상세에 「(E)김연심 010-5856-7037」처럼 이름과 번호가 들어 있고, 그대로 창고로
갑니다. **오늘도 3건** 생겼습니다.

```
배송지에 (E) 가 섞인 주문
   10-14  3건   10-13 33건   10-12 41건   10-08 29건
   10-07 35건   10-06 36건   10-02 33건   10-01 35건
```

어제 만든 `Order::배송지한줄()` 은 **환자에게 보내는 글**에서만 (E) 를 뗍니다.
담긴 값과 창고로 가는 값은 그대로입니다.

## 옛 자료 — 지금은 안 생기지만 남아 있다

```
가상계좌 예금주 292건 중 더러운 것 144건
   10-14 3건 · 10-13 22건 · 10-12 19건 · 10-08 21건 · 10-07 24건
   10-06 23건 · 10-02 15건 · 10-01 17건

현금영수증 고객명 164건 중 더러운 것 9건
   10-06 6건 · 10-02 2건 · 10-01 1건
```

현금영수증은 **10-06 이 마지막**입니다 — 그날 `실명()` 으로 고친 뒤로는 깨끗합니다.

가상계좌 예금주는 **10-14 에도 3건**이 있습니다. 어제 고쳤는데 왜 남았는지 더 봐야
합니다 — 10-12~10-13 에 발급된 계좌가 오늘 입금되며 줄이 갱신된 것일 수 있고, 그렇다면
새로 발급된 것이 아니라 그때 적힌 값이 남은 것입니다. **아직 가리지 못했습니다.**

이미 발행된 증빙과 이미 발급된 계좌의 이름은 **바꿀 수 없습니다** — 다시 발행ㆍ재발급해야
바뀝니다.

## 고칠 자리 (아직 손대지 않았습니다)

1. **`WithworksLink::창고내용()`** 의 `patient_name` 을 `Patient::실명()` 으로.
2. **`shipping_recipient`** 를 담을 때 `bare()` 대신 `실명()` 으로. 담기는 자리가
   여럿이라(`OrderController::store`ㆍ주문 등록 저장) 한 곳으로 모으는 편이 낫습니다.
3. **배송지 글에서 `(E)`** 를 떼고 보낸다 — 담긴 값을 고칠 것인지, 창고로 보낼 때만
   다듬을 것인지 정해야 합니다.
4. 이미 담긴 값(수령인 57건 · 배송지 245건)을 **거슬러 고칠 것인지**.

지시를 기다립니다.
