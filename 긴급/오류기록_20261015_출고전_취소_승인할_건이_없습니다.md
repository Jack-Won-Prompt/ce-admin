# 「승인할 건이 없습니다」 — 출고 전 취소 건을 승인하려 할 때 (2026-10-15)

## 무엇이 보였나

교환ㆍ반품ㆍ취소 목록에서 **출고 전 취소** 한 줄을 체크하고 **반품 승인** 을 누르면
창이 뜨는데 안이 비어 있었다.

```
반품 승인  0건 · 건너뜀 1건
   승인할 건이 없습니다.
   승인을 기다리지 않는 1건은 건너뜁니다 — RN202610130002 (접수)
```

누르려던 사람은 왜 안 되는지, 무엇을 먼저 해야 하는지 알 길이 없다.

## 규칙대로 움직이고 있었다

운영에서 그 세 줄을 직접 읽었다.

```
RN202610130002 · (E)이정현A · 출고 전 취소 · 지금 「접수」
   정해진 흐름 : 접수 → 확인요청 → 반품 승인 → 환불완료 → 완료
   지금 누를 수 있는 것 : 확인요청, 취소
   승인 단추가 보는 값 : (비어 있음 → 건너뜀)

RN202610130001 · (E)김일랑 · 고객 변심 교환 · 지금 「접수」
   지금 누를 수 있는 것 : 수거중, 취소

RN202610080001 · (E)정덕순 · 불량 교환 · 지금 「접수」
   지금 누를 수 있는 것 : 수거중, 취소
```

승인 단추는 `nextStatuses()` 가운데 **승인이 필요한 단계**(`inspected`ㆍ`approved`)가
있을 때만 선다(`OrderReturnController` 의 `ap_next`). 접수 다음은 출고 전 취소가
「확인요청」, 교환이 「수거중」이라 승인 단계가 아니다. 그래서 건너뛴다.

흐름은 절차서와 같다 — `docs/교환·반품·취소.md` 23행.

```
출고 전 취소 | 접수 → 확인요청 → 반품 승인 → 환불완료 → 완료
```

**결함은 흐름이 아니라 안내였다.** 상세 화면에는 「확인요청」 단추가 이미 서 있는데,
목록의 승인 창은 그 사실을 한마디도 하지 않았다.

## 고친 것

건너뛴 줄마다 **지금 단계와 다음에 눌러야 할 단추**를 적는다.

목록 줄에 `ap_step` 을 더했다 — `nextStatuses()` 에서 「취소」를 뺀 첫 단계의 이름이다.

```php
'ap_step' => (function () use ($r) {
    $to = collect($r->nextStatuses())->first(fn ($x) => $x !== 'cancelled');
    return $to ? (OrderReturn::STATUS_LABELS[$to] ?? $to) : '';
})(),
```

창에 뜨는 말이 이렇게 바뀐다.

```
아직 승인할 차례가 아닌 1건은 건너뜁니다.
   RN202610130002 · (E)이정현A · 출고 전 취소   지금 접수
      → 먼저 「확인요청」(으)로 옮겨야 승인할 수 있습니다
   단계는 목록에서 그 줄을 열어 상세 탭에서 옮깁니다.
```

승인할 것이 하나도 없을 때의 말도 바꿨다 — 「승인할 건이 없습니다」 대신
「고른 N건 가운데 지금 승인할 수 있는 건이 없습니다」.

## 남겨 둔 물음

출고 전 취소는 되돌릴 물건이 없어 수거ㆍ검수가 없다. 그래서 **접수에서 바로 승인**
하게 할 수도 있다. 다만 절차서가 「확인요청」을 한 단계로 두었고, 그 단계의 담당이
Care team(상담)으로 적혀 있다 — 고객에게 확인하고 넘기라는 뜻으로 읽힌다.

흐름을 바꾸는 일이라 손대지 않았다. 사람이 정할 일이다.
