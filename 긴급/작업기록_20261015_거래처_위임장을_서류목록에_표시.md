# 거래처의 위임장을 처방전 서류 목록에 함께 표시 (2026-10-15 지시)

## 지시 내용

> 서명위임이 완료되었으면 매번 주문 등록 시 처방전 서류 목록에 거래처의 위임장을
> 함께 표시되게

## 기존 동작

위임 서명 완료 판정(`DelegationGate::서면위임장`)은 **거래처 단위**로 조회하지만,
서류 목록은 **해당 처방전의 첨부만** 표시했다. 따라서 위임장이 지난 처방전에
첨부된 경우 승인은 되지만 서류는 보이지 않았다.

(E)정용순 님 사례.

```
처방전 WW-ADD0047611   2026-07-10 · 위임장 3장 첨부
처방전 RX-20261012-089 2026-10-12 · 거래명세서, 신분증   ← 주문 등록 화면
```

## 변경 내용

`PrescriptionController::show` 의 서류 목록 구성에 **같은 거래처의 다른 처방전에
첨부된 위임장**을 추가했다.

대상 문서 유형은 `DelegationGate::종이서명유형` 과 동일하다.

- `delegation` (위임장)
- `medical_aid_claim_signed` (요양비 지급청구서 서명본)

표시 형식은 다음과 같다.

```
위임장 (지난 처방전) · 정용순님 위임장 수정본.jpg · WW-ADD0047611
```

어느 처방전에서 왔는지 파일명 뒤에 표기한다. 동일 문서가 여러 건인 경우 최신 건을
구분하기 위함이다.

## 첨부번호를 재사용하지 않은 이유

해당 문서는 현재 처방전의 첨부가 아니다. 첨부번호를 그대로 사용하면 삭제, 문서
유형 변경, 팩스 첨부 기능이 **다른 처방전의 서류를 대상으로 동작**한다.

겹치지 않는 식별자(`-5000000 - id`)를 부여하고, 분류는 `src` 값(`other_rx`)으로
명시했다. 2026-10-15 오전에 확인된 「생성 서류와 거래처 종이의 id 범위가 겹쳐
827줄이 잘못 분류된 건」과 동일한 방식이다.

## 적용 범위 (운영 데이터 기준)

```
위임장ㆍ요양비청구서(서명본) 첨부 : 115건
해당 서류를 보유한 거래처        : 98곳
거래처당 최대                   : 3장
```

목록이 과도하게 길어질 우려는 없다.

## 검증

(E)정용순 님 건으로 확인했다.

```
현재 처방전 첨부 : id_card, trade_statement
추가 표시되는 문서
   위임장 (지난 처방전) · 정용순님 위임장 수정본.jpg · WW-ADD0047611
   위임장 (지난 처방전) · 정용순님 위임장 원본2.jpg · WW-ADD0047611
   위임장 (지난 처방전) · 정용순님 위임장 원본1.jpg · WW-ADD0047611
```

커밋 `a15a35be`. 운영 반영 완료.

## 팩스 발송 대상에는 포함하지 않음

팩스 발송 창은 현재 처방전의 첨부(`id > 0`)와 거래처 서류함(`src=patient_doc`)만
수집한다. 이번에 추가한 문서는 `src=other_rx` 이므로 팩스 목록에는 나타나지 않는다.

공단 제출 시 지난 처방전의 위임장을 함께 발송해야 한다면 별도 지시 후 반영한다.
