# 주문 목록에서 주문 제품이 없는 빈 주문을 그 자리에서 지운다

- 날짜 : 2026-10-13
- 지시 : 「주문 등록 화면의 주문 목록에서 그리드 마지막 항목에 라인마다 주문 제품이 없는 상태 삭제 버튼 삭제시 소프트 삭제」
- 올린 것 : `6a1abd1c`

## 만든 것

주문 등록 화면 「주문 목록」 그리드의 **맨 끝에 「삭제」 칸**을 두었습니다.

- **주문 제품이 없는 줄에만 단추가 섭니다.** 지울 수 없는 줄에는 「-」가 서고, 그 위에
  마우스를 올리면 못 지우는 까닭이 뜹니다.
- 누르면 한 번 묻고, **소프트 삭제**합니다 — 줄은 남고 목록에서만 빠지며 되살릴 수 있습니다.
- 주문이 아직 없는 줄(진행 상태 「주문 없음」)에는 지울 것이 없어 단추가 서지 않습니다.

## 가리는 잣대는 한 곳에 — `Order::지울수있나()`

화면이 단추를 가리는 잣대와 서버가 막는 잣대가 **같은 자리**를 씁니다. 두 곳에 따로
적으면 화면은 안 보여 주는데 주소로 바로 불러 지워지는 날이 옵니다 — 주문번호는
위드웍스ㆍ토스ㆍ팝빌ㆍ공단으로 나가는 대외 식별자라 그래서는 안 됩니다.

막는 것은 일곱입니다.

```
주문 제품이 담겨 있다
창고로 보냈다 (withworks_so_no)
결제 줄이 있다 (toss_payments)
교환ㆍ반품ㆍ취소 접수가 있다
결제가 끝난 링크가 있다
세금계산서가 발행되었다
현금영수증이 발행되었다
```

값이 비싼 조회(세금계산서ㆍ현금영수증)는 **맨 뒤**에 두었습니다. 제품이 담긴 줄은 첫
걸음에서 돌아서므로, 오백 줄을 그릴 때 그 조회는 빈 줄에만 갑니다.

## 운영에서 확인했다

### 잣대가 가르는가

```
최근 주문 500건
   삭제 단추가 서는 줄 : 203건  (모두 품목 0 · 창고 없음 · 결제줄 없음)
   서지 않는 줄        : 297건  (모두 「주문 제품이 담겨 있어 지울 수 없습니다」)
   품목이 없는데 막히는 줄 : 0건
```

### 화면이 그리는가 (사람이 보는 그대로)

```
그리드 마지막 칸 : … 등록 일시 · 수정자 · 수정 일시 · **삭제**
화면에 선 삭제 단추 : 11개 (보이는 줄만 그린다)
받아 온 100줄 중 지울 수 있다고 온 줄 : 49줄
못 지우는 줄의 까닭 : 「주문 제품이 담겨 있어 지울 수 없습니다. 제품을 먼저 비우십시오.」
콘솔 오류 : 없음
```

### 서버가 막는가 — 제품이 담긴 줄을 지워 보았다

```
시험한 주문 EUD202610131757381 (품목 1줄)
   응답 422 · success=false
   「주문 제품이 담겨 있어 지울 수 없습니다. 제품을 먼저 비우십시오.」
```

화면을 거치지 않고 주소로 바로 불러도 막힙니다.

## 알려 드릴 것 — 단추가 서는 줄이 203/500 입니다

지울 수 있는 203건은 **버려진 줄이 아니라 일하는 중인 줄**입니다. 「주문등록 이동」을
눌러 주문번호는 났고 아직 제품을 담지 않은 건이 그만큼 있습니다(모두 검수 approved).

- 지워도 되살릴 수 있고, 처방전을 다시 저장하면 주문이 새로 섭니다.
- 다만 **그때는 주문번호가 새로 납니다.** 지운 번호는 다시 쓰지 않습니다.

지시는 「주문 제품이 없는 상태」였으므로 그대로 두었습니다. 좁히려면 잣대를 더 걸 수
있습니다 — 보기를 들면 이런 것들입니다.

- 며칠 지난 것만 (오늘 들어온 건에는 단추를 세우지 않는다)
- 사유가 취소인 것만
- 거래처가 붙지 않은 것만

어느 쪽이 좋을지 알려 주시면 그대로 하겠습니다.

## 짓다가 바로잡은 것 넷

- `지울수있나()` 를 줄마다 **두 번** 불렀습니다 — 비싼 조회가 두 벌 돌았습니다. 한 번만
  셈해 쓰도록 고쳤습니다.
- 주문 없는 처방전 줄에 새 칸을 안 채웠습니다 — 칸이 하나라도 빠지면 그 줄만 표에서
  칸이 밀립니다. 채웠습니다.
- `OL_ROWS` 는 `const` 라 다시 넣을 수 없습니다 — 배열을 그 자리에서 줄이도록 바꿨습니다.
- 확인 창 옵션을 `okText` 로 적었는데 이 화면의 창은 `confirmText` 를 읽습니다. 그리고
  지운 뒤 `olFilter()` 를 부르면 서버에서 1쪽을 다시 받아 와 **보고 있던 쪽이 날아갑니다** —
  그 자리에서 줄만 빼도록 했습니다.
- 글을 사무 용어로 바꾸면서 `
` 이 **진짜 줄바꿈**으로 들어가 홑따옴표 문자열이 줄을
  넘었습니다 — 자바스크립트 문법이 깨져 **주문 등록 화면이 통째로 멈출** 수 있었습니다.
  올리기 전에 바이트로 확인해 잡았고(`cat -A`), 그 묶음을 뽑아 `node --check` 로 문법을
  검사한 뒤 올렸습니다. **운영에는 깨진 채로 올라가지 않았습니다.**
- 이 기록을 고칠 때도 찾는 글이 파일과 달라 한 번 멈췄습니다 — 쓰기 전에 멈춰 파일은
  그대로였고, 실제 글을 읽어 다시 맞췄습니다.
