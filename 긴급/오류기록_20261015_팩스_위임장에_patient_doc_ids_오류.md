# 팩스로 위임장을 보내면 「patient_doc_ids.0 is invalid」가 떴다

- 날짜 : 2026-10-15
- 알린 이 : 운영 담당자 — 「주문등록 › 팩스 발송 › 위임장 png 발송 시 오류 토스트」
- 본 건 : 주문 `EUD202610131057531` · 처방 84862 · (E)이정화D

## 까닭 — 서류 번호의 **범위가 겹쳤다**

문서 칸은 첨부ㆍ생성 서류ㆍ거래처 종이를 **한 배열**에 담는다. 첨부는 번호가 양수이고
나머지는 음수인데, 음수를 짓는 셈이 둘이다.

```
생성 서류    화면 id = -1000 - id
거래처 종이  화면 id = -2000 - id
```

화면은 **「화면 id 가 -2000 아래면 거래처 종이」**로 갈랐다. 그런데 생성 서류의 id 가
**1000 을 넘는 순간 같은 자리로 내려온다.**

```
prescription_documents 의 id 가 2026-10-07 16:51 에 1000 을 넘었다
   #1000 요양비위임장_(E)김종욱D_01049645017_20261007.pdf
```

본 건을 열어 보면 그대로 드러난다.

```
요양비위임장_이정화_…pdf   화면 id -2746
   → 거래처 종이로 읽힌다 → 되셈 pd = -2000 - (-2746) = 746
   → patient_documents 에 746번이 없다 → **invalid**
```

그 처방의 생성 서류 **다섯 장이 모두** -2000 아래였다.

## 얼마나 되나 (운영)

```
거래처 종이로 잘못 읽히는 생성 서류 : 827줄
   가리킬 번호가 없어 오류만 나는 것 : 803건   ← 담당자가 본 토스트
   **다른 거래처의 종이**를 가리키는 것 : 24건
      생성#1029 → 거래처종이#29 (거래처 11189 · 이여재 신분증.jpg)
      생성#1028 → 거래처종이#28 (거래처 11189 · 이여재 위임장.jpg)
      …
```

`patient_documents` 의 id 가 3~29 이므로, 생성 서류 id 1003~1029 가 그 자리를 가리켰다.

## 남의 서류가 나가지는 않았다

싣는 자리 **둘 다** 이미 환자로 걸러내고 있었다.

```php
// faxPdfBytes · collectFaxFiles
->where('patient_id', $prescription->patient_id)   // 남의 서류를 실어 보내지 않는다
```

팩스 기록 81건의 파일 이름을 거래처 종이 27장의 이름과 맞춰 보았다.

```
팩스에 실린 거래처 종이 — 제 것 0장 · 남의 것 0장
```

**한 장도 나가지 않았다.** 다만 그 때문에 **조용히 빠지는** 자리가 생긴다 — 담당자는
위임장을 보냈다고 여기는데 그 장이 들어가지 않고 오류도 뜨지 않는다. 번호가 없는
803건은 검증에서 걸려 토스트가 떴고, 실재하는 24건은 환자가 달라 조용히 빠졌을 것이다.

## 고친 것 — 번호 셈으로 갈래를 알아내지 않는다

서버가 갈래를 적어 보내고 화면은 그것으로 가른다. 보내는 번호도 서버가 준 것을 그대로
쓴다 — 되셈하지 않는다.

```php
// 거래처 종이
'src'  => 'patient_doc',
'pdId' => $줄->id,
// 생성 서류
'src'  => 'generated',
```

```js
const 종이들 = ALL_DOCS.filter(d => d.src === 'patient_doc' && d.type === req.type);
종이들.forEach(h => { … rows.push({ …, pd: h.pdId }); });
```

이제 번호가 아무리 커져도 겹치지 않는다. 올린 것은 `d865a6a0`.

## 함께 고친 것 — **무엇을 보냈는지 남지 않았다**

보내는 자리는 `patient_doc_ids` 를 받아 파일을 싣고 기록을 남길 때도 그 값을 넘겼다.
그런데 `fax_histories` 에 **칸이 없고** 모델의 `fillable` 에도 없어 조용히 버려졌다.
첨부(`attachment_ids`)는 남는데 이것만 빠져 있었다.

공단에 낸 서류가 무엇이었는지는 되짚을 수 있어야 한다. 칸을 더했다(`8720e558`).

## 확인

```
fax_histories.patient_doc_ids : json ✓ (운영에 들어감)
처방 84862 의 생성 서류 다섯 장 모두 src=generated 로 적힌다
거래처 서류함 0장 — 이 건은 patient_doc_ids 가 아예 실리지 않는다
```

**담당자가 그 화면에서 다시 눌러 확인해 주셔야 끝이다.**

## 배운 것

**번호를 셈해서 갈래를 알아내는 방식은 언젠가 깨진다.** 두 자리가 각각 상수를 정해 놓고
그 사이를 암묵으로 나눠 쓰면, 한쪽이 자라는 순간 조용히 겹친다. 자라는 것은 id 이고
id 는 늘 자란다. 갈래는 값으로 밝힌다.
