# 다음 재구매 가능일 — 247장을 식 그대로 검증했다

- 날짜 : 2026-10-13
- 알려 온 것 : 「사용시작일(사용개시일) + 총 처방일수 = 다음 재구매 가능일이고,
  다음 재구매 가능일은 급여종료일(사용종료일) + 1일인데, 정보가 맞는 환자도 있고
  다르게 보이는 환자도 있어서 확인」 ((E)이건우 · EUD202610011025321)

## 값은 맞다 — 규칙이 둘이다

```
급여 종료일 = 사용개시일 + 총처방일수 − 1
다음 재구매 = 사용개시일 + 총처방일수 + (Five/Six 프로그램이고 총처방일수 < 110 이면 20)
```

Five/Six(05ㆍ06)는 한 번에 더 많이 받아 가므로 다음 구매가 그만큼 늦다
(2026-09-08 확인요청 10쪽 · 2026-09-09 확정). **급여 종료일은 그대로 둔다** — 언제까지
쓰는가와 언제 다시 살 수 있는가는 다른 물음이다.

깃발은 `five_program` 이다. 옆의 「Five/Six(110days)」는 날짜를 적는 칸이라 깃발이
아니다(2026-10-07 · SR #103 에서 바로잡았다).

## 알려 준 그 건

```
(E)이건우 · RX-20261001-014 · five_program 「05」
사용개시 2026-10-01 · 총처방일수 90

급여 종료일  2026-10-01 + 90 − 1  = 2026-12-29   ← 화면 그대로
다음 재구매  2026-10-01 + 90 + 20 = 2027-01-19   ← 화면 그대로
```

「맞는 환자도 있고 다르게 보이는 환자도 있다」는 것은 **Five/Six 프로그램 건에만
스무 날이 붙기** 때문이다.

## 247장을 하나씩 맞춰 보았다

사용개시일ㆍ총처방일수ㆍ급여종료일ㆍ다음재구매가 모두 적힌 처방전 전부다.

| 잣대 | 맞음 | 틀림 |
|---|---|---|
| 급여 종료일 = 사용개시일 + 총처방일수 − 1 | **247장** | **0장** |
| 다음 재구매 = 사용개시일 + 총처방일수 (+ Five/Six 20일) | **247장** | **0장** |

| 갈래 | 수 |
|---|---|
| 스무 날이 붙지 않는 건 (= 급여종료일 + 1) | 136장 |
| 스무 날이 붙는 건 (= 급여종료일 + 21) | 111장 |
| Five/Six 인데 총처방일수가 110 이상이라 안 붙는 건 | 0장 |

**고칠 것이 없었다.** 어긋난 장이 하나도 없다.

## 화면에 풀이를 붙였다가 걷었다

값은 맞는데 스무 날이 왜 붙었는지가 화면 어디에도 없어 같은 물음이 되풀이됐다
(SR #186 도 같은 물음이다). 그래서 칸 아래에 셈한 식을 적었다 —
「2026-10-01 + 90일 + 20일 (Five/Six 프로그램)」.

그런데 그 줄이 줄바꿈을 막고 있어 셋이 한 줄을 나눠 가졌고, **날짜 칸이 26px 로
찌그러져 값이 보이지 않았다.** 화면에서 보고 바로 잡았다(`aaa7886a`).

이어서 「풀이 없이」 지시를 받아 세 자리를 모두 되돌렸다(`4a213ec6`) — 주문 등록 칸
아래의 풀이, 그 칸의 마우스 설명, 목록(주문 관리ㆍ공통 칸) 머리말.

되돌린 뒤 화면을 다시 보았다 — 날짜 칸 너비 **248px**, 값 **2027-01-19** 가 온전히
