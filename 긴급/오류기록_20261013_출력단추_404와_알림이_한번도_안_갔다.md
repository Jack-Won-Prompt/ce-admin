## SR #177 — 주문관리 발행 서류 출력이 404

### 알려 온 것

> 주문관리 → 발행 서류 출력 누르면 "not found"로 보임. 주문등록에서는 관련 자료
> 업로드 되어있고 내용도 보이기는 함

### 까닭

주문 상세의 「출력」 단추가 이 두 주소를 열고 있었다.

```
/orders/{id}/tax-invoice/print
/orders/{id}/cash-receipt/print
```

**그런 길이 라우트에 없다.** 있는 것은 셋이다.

| 주소 | 하는 일 |
|---|---|
| `/{order}/tax-invoice-preview` | 세금계산서 PDF 를 그 자리에서 펼친다 |
| `/{order}/cash-receipt-preview` | 현금영수증 PDF 를 그 자리에서 펼친다 |
| `/{order}/cash-receipt-pdf` | 현금영수증을 내려받는다 |

미리보기가 바로 「출력」이 하려던 일이다 — PDF 를 새 창에 펼치고 거기서 인쇄한다.

### 재어 본 것 (운영 · 주문 #539 EUD202610121149412)

| 주소 | 전 | 후 |
|---|---|---|
| `/tax-invoice/print` (옛것) | **404** | — |
| `/tax-invoice-preview` | — | **200 · application/pdf · 54,224바이트** |
| `/cash-receipt-preview` | — | **200 · application/pdf · 37,960바이트** |

화면에서 단추를 눌렀을 때 여는 주소도 확인했다 — 둘 다 `-preview` 로 간다.

## SR #175 — 다시 올리기 요청의 알림이 한 번도 가지 않았다

### 알려 온 것

> 처방전 목록에서 다시 올리기 요청하니 「알림 못감」으로 내용 보여서 확인필요

### 까닭

알리는 길이 **앱 푸시(FCM) 하나**였다. 그런데 요청을 받는 담당자들에게 앱 토큰이 없다.

| 잣대 | 수 |
|---|---|
| 다시 올리기 요청 | 29건 |
| 그 가운데 알림이 간 것 | **0건** |
| 못 간 까닭 | 29건 **모두** 「앱 알림 토큰이 없습니다」 |
| 요청을 받은 사람 | Coco Wang(13건) · Mia Kim(16건) — **둘 다 토큰 없음** |
| 전체 사용자 25명 중 토큰이 있는 사람 | **2명** |

담당자는 **웹으로 일한다.** 앱은 환자가 자료를 올리는 자리다. 그래서 요청을 걸어도
받는 사람은 끝내 알지 못했고, 화면에는 「알림 못 감」만 붉게 남았다. 기능이 한 번도
제구실을 못 한 셈이다.

### 고친 것

창고 소식이 도는 길(Pusher)을 그대로 쓴다. `WithworksStatusChanged` 는 받는 사람을
짚을 수 있어(`userId`) **그 한 사람의 화면에만** 띄운다.

앱으로 갔는지와 **따로 적는다**(`web_sent`) — 섞으면 뒤에 어느 길로 갔는지 물을 수
없다. 목록도 「알림 보냄 (앱)」ㆍ「알림 보냄 (화면)」으로 밝힌다.

### 재어 본 것 (운영)

| 잣대 | 결과 |
|---|---|
| `web_sent` 칸 | 섰다 |
| 알림이 갈 채널 | `private-App.Models.User.19` — 받는 사람 한 명 |
| 알림이 걸어 줄 주소 | `…/prescriptions?search=RX-20261006-087` |
| 보내는 길 | pusher · 열쇠 있음 |

**남은 것** — 실제로 가는지는 담당자가 「다시 올리기 요청」을 한 번 눌러 보아야 끝이다.
누르면 받는 분 화면에 토스트가 떠야 한다.

### 생각해 둘 것

앱 토큰이 없는 것 자체는 고치지 않았다. 담당자가 앱을 쓰지 않는 것이 지금의 운영이고,
웹으로 알리면 닿는다. 다만 **앱으로만 알리는 자리가 여기 말고 또 있다면 같은 꼴로
묻혀 있을 수 있다** — 따로 훑어야 한다.
