# 출고 상태 이름표 저장과 반복 경고 제거 (2026-10-16 지시)

## 1. 출고 상태 이름표

### 문제

출고 상태 이름표를 담은 지도가 두 벌이었다.

| 지도 | 담긴 값 | 쓰는 곳 |
|---|---|---|
| `SHIP_STATUS` | 02ㆍ9ㆍ14ㆍ15ㆍ16ㆍ17ㆍ51ㆍ52ㆍ53ㆍ55ㆍ57ㆍ92ㆍ93ㆍ95ㆍ98 (15가지) | 화면 표기 |
| `DB_SHIP_LABEL` | 02ㆍ95 (2가지) | 창고 표에서 되짚어 **저장할 때** |

`출고맞추기()` 는 뒤쪽 지도에 없는 코드를 **적지 않고 물러났다**. 따라서
**14 부분할당ㆍ17 할당완료ㆍ55 피킹완료ㆍ98 오더종결은 한 번도 저장되지 않았다.**

창고가 피킹까지 끝낸 건이 화면에는 「신규」나 공란으로 섰고, 어긋난 건이 날마다
쌓였다 — 10-15 에 9건, 10-16 아침에 21건.

좁은 지도를 만든 2026-10-06 기록에는 「이름표를 지어내지 않는다」고 적혀 있었다.
그러나 **같은 파일에 창고 화면을 그대로 옮긴 이름표가 이미 있었다**(2026-08-31 확인).
지어내는 것이 아니라 있는 것을 못 쓰고 있었다.

### 조치

```php
private static function 출고이름표(string $코드): ?string
{
    return self::SHIP_STATUS[$코드] ?? null;
}
```

이름이 없는 코드는 여전히 적지 않는다. 그런 코드는 지금 창고에 서 있지 않다.

### 결과

```

고친 뒤     출고 어긋남  2건

이제 적히는 출고 상태
   95 출고완료 412건 · 17 할당완료 11건 · 55 피킹완료 11건
   02 신규      7건 · 98 오더종결  2건 · 14 부분할당 1건 · 공란 26건
```

## 2. 반복 경고 제거

### 문제

출고가 끝나고 송장까지 받은 건이 계속 훑기 대상(`OPEN_STATUSES` 에 `shipping` 포함)에
남아, 정정을 거친 건마다 10분마다 「다른 판매주문의 상태가 왔다」 경고가 쌓였다.

```
10-15 하루 346건 — 주문 6건이 각 57~59회
10-16 09시까지 345건 — 같은 6건
```

진짜 경고가 묻힌다.

### 조치

훑기 대상에서 **출고완료이고 송장이 있는 건**을 뺀다.

```php
->where(function ($q) {
    $q->whereNull('withworks_ship_status')
      ->orWhereNotIn('withworks_ship_status', self::SHIPPED)
      ->orWhereNull('tracking_number')
      ->orWhere('tracking_number', '');
})
```

송장이 아직 없는 건은 남겨 둔다 — 출고 안내가 운송장을 기다리다 멈춰 선 건을 마저
보내는 그물이 그 자리에 걸려 있다.

### 결과

```
고친 뒤 훑기 두 번 동안 경고
   EUD202610131622431  2회
   EUD202610151213281  2회  ((E)조용관 · 오늘 아침 정정)
```

여섯 건은 사라졌다. 남은 둘은 정정을 거쳤으나 아직 송장이 없어 **정상적으로 대상에
남은** 건이다. 출고되어 송장이 붙으면 자동으로 빠진다.

커밋 `27a3759b`. 운영 반영 완료.

## 3. 함께 나간 출고 안내 2건

출고 상태가 비로소 저장되면서, 출고완료로 바뀐 건에 출고 안내가 나갔다.

```
09:39:40  (E)정영애  배송 시작 · 성공
09:39:49  (E)김형석A 배송 시작 · 성공
```

**두 건 모두 본인부담금이 미수다**(각 81,000원). 창고에서는 이미 출고가 끝난 건이라
안내 자체는 사실과 맞으나, 돈을 받기 전에 안내가 나간 것이므로 수납 독촉이 필요하다.

조치 전에 예고한 그대로이며, (E)원경자 건은 아직 출고 상태가 맞춰지지 않아 안내가
나가지 않았다.

## 4. 함께 드러난 것 — 창고가 같은 판매번호로 줄을 하나 더 세운다

판매주문 상태 어긋남 7건을 열어 보니 모두 같은 모양이었다.

```
(E)김양금   682484 · 02 · [CE-ADMIN] RX-…          10-15 10:41  ← 우리가 보낸 줄
            682745 · 95 · (표시 없음)               10-16 06:50  ← 창고가 세운 줄
(E)김봉식   682476 · 02 · [CE-ADMIN] RX-…          10-15 10:25
            682736 · 95 · (표시 없음)               10-16 06:20
(E)정영애   681994 · 02 · [CE-ADMIN] RX-…          10-14 08:57
            682326 · 95 · (표시 없음)               10-15 00:20
(E)김형석A  682458 · 02 · [CE-ADMIN] RX-…          10-15 09:43
            682708 · 95 · (표시 없음)               10-16 03:32
(E)김동하   682491 · 02 · [이관] 원천 처방전        10-15 10:53
            682752 · 95 · (표시 없음)               10-16 07:00
(E)김세종   682763 · 02 · [CE-ADMIN] RX-…          10-16 09:02
            682781 · 95 · 택배                      10-16 09:19
(E)김한극   681110 · 99 · [CE-ADMIN] RX-…          10-12 08:55
            681133 · 95 · 화물                      10-12 09:19
            681523 · 95 · (표시 없음)               10-13 00:19
```

우리가 보낸 줄에는 `[CE-ADMIN]` 과 처방전 번호가 남는다. 확정(95)된 줄에는 그것이
없고, 대부분 **새벽 시간대에 만들어진다**(03:32ㆍ06:20ㆍ06:50ㆍ07:00). (E)김세종 건은
우리가 09:02 에 보낸 뒤 **17분 만에** 창고가 「택배」 줄을 세워 확정했다.

즉 **우리 쪽 02(등록)는 틀린 값이 아니라 우리가 보낸 그 줄의 실제 상태**이고, 창고는
별도의 줄로 확정ㆍ출고한다.

이것이 「돈을 받지 않았는데 물건이 나갔다」((E)정영애ㆍ(E)김한극)의 구조적 원인이다.
우리가 확정하지 않아도 창고가 스스로 줄을 세워 확정하고 출고한다.

**위드웍스에 확인이 필요하다.**
