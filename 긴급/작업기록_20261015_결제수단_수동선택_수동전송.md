# 결제 수단은 담당자가 고르고 손으로 보낸다 (2026-10-15 지시)

## 지시 내용

> 링크페이 누르면 카드결제만 가능 / 가상계좌 누르면 계좌이체만 가능하게
> 그리고 반영 후, 현재는 주문연계 누르면 자동 전송인데 주문연계 누른 후 수동으로 전송하게
> 앞으로 상담 담당자들이 결제 수단 물어봐서 해당 내용으로 선택 후 수동 전송 진행함

## 변경 1 — 링크페이는 카드만

기존에는 링크페이로 보낸 결제 페이지에서 환자가 **카드와 가상계좌 중 선택**할 수
있었다(`toss.virtual_account.selectable` 이 참일 때). 담당자가 링크페이로 안내해도
환자가 가상계좌를 고르면 안내한 수단과 실제 수납 수단이 달라졌다.

결제 페이지(`resources/views/pay/show.blade.php`)에서 선택 항목을 제거하고 카드로
고정했다.

```
변경 전   결제 수단을 선택해 주시기 바랍니다  [ 카드 ] [ 가상계좌 ]
변경 후   카드로 결제합니다
```

가상계좌로 받을 건은 결제전송 창에서 **가상계좌**를 선택해 발급한다. 이 경로는 기존에도
계좌 입금만 가능했으므로 변경 사항이 없다.

## 변경 2 — 주문 연계 후 자동 전송 중단

기존에는 창고 판매주문이 생성되면 `sendOrderConfirmedSms()` 가 곧바로 결제 안내를
발송했다. 발송 수단은 설정값(`order.confirm_pay_method`) 하나로 고정되어 있어, 환자가
카드 결제를 원한 건에도 설정이 가상계좌면 계좌 안내가 나갔다.

자동 발송을 중단했다. 주문 생성과 창고 연계는 그대로 진행된다.

연계 결과 창의 표기도 수정했다.

```
변경 전   결제 안내   [ 발송 안 됨 ]   사유: ...
변경 후   결제 안내   [ 수동 발송 ]    다음 할 일: 「결제전송」에서 결제 수단을 고른 뒤 보내 주십시오.
```

「발송 안 됨」은 실패로 읽혀 담당자가 원인을 찾게 되므로 구분했다.

본인부담금 0원 건의 증빙 자동 발행은 그대로 유지했다(발송할 안내가 없는 건이다).

## 변경 3 — 에스크로 관련 확인

> 에스크로우 사용안할려고함

우리 시스템은 **에스크로를 요청하지 않는다.**

- 카드 결제 : `useEscrow: false` 를 명시적으로 전달
- 가상계좌 발급(`POST /v1/virtual-accounts`) : 에스크로 관련 항목을 전달하지 않음

그럼에도 운영 데이터에 에스크로 건이 존재한다.

```
토스 결제 기록 378건
   useEscrow = true  :  58건  (전부 가상계좌)
   useEscrow = false : 320건
```

발생 경로를 확인했다. 에스크로 건의 주문에 존재하던 결제 링크다.

```
에스크로 58건   card(링크페이)만 54건 · card+virtual 3건 · virtual 1건
아님   156건   card+virtual 101건 · card 52건 · virtual 2건 · bank+card+virtual 1건
```

에스크로 건의 **54/58 이 링크페이 링크만 보유**하고 있다. 즉 **결제 페이지에서 환자가
가상계좌를 선택한 경우**에 발생한 것이며, 이때는 토스 상점에 설정된 에스크로가 적용된다.
은행 분포도 이를 뒷받침한다.

```
에스크로   06ㆍ20ㆍ11ㆍ88ㆍ03ㆍ81ㆍ71 (환자가 결제창에서 선택)
아님       20(우리) 114건 — 우리가 API 발급 시 사용하는 설정값과 일치
```

따라서 **변경 1(링크페이 카드 전용)로 에스크로 발생 경로가 차단된다.** 결제전송에서
발급하는 가상계좌는 에스크로가 적용되지 않는다.

기존 58건은 이미 정산이 완료되었거나 진행 중이므로 그대로 둔다.

## 남은 확인 사항

1. 토스 상점관리자의 **가상계좌 에스크로 설정** 자체를 해제할지 여부 — 우리 코드가
   아니라 토스 쪽 설정이다.
2. 주문 관리 화면의 **「토스 에스크로 엑셀」 버튼** 유지 여부 — 신규 에스크로 건이
   발생하지 않으면 사용할 일이 없다. 기존 58건 처리가 끝날 때까지는 두는 것이 안전하다.
