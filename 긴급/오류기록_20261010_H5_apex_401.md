# 오류 기록 — H5 로그인 뒤 웹 화면이 뜬다 (2026-10-10)

보고 「https://ceadmin.co.kr/m/login => 로그인하면 웹 화면 로그인했을 때 화면으로 보임」

---

## 1. 무엇이 보였나

`https://ceadmin.co.kr/m/login` 에서 로그인을 마치면 모바일 목록이 아니라
**웹 대시보드(`/dashboard`)** 가 뜬다. 주소를 `/m` 으로 다시 쳐도 `/dashboard` 로 넘어간다.

## 2. 처음에 잘못 짚은 것 (기록으로 남김)

| 짚은 것 | 왜 틀렸나 |
|---|---|
| 「그 서버에 옛 코드가 올라가 있다」 | 두 서버의 코드가 같았다 |
| 「노선이 등록되지 않았다」 | 서버가 `/m` 에 **200** 과 모바일 화면을 돌려주고 있었다 |
| 「`session()->regenerate()` 순서 때문」 | 순서를 고쳐 올렸으나 증상이 그대로였다 |

`/m` 에 세션을 달아 `fetch` 하면 **200 · 모바일 화면 30,459자** 가 오고, 그 글 안에
`dashboard` 라는 낱말이 **하나도 없다.** 서버가 넘기는 것도 아니고, 화면에 적힌 주소도 아니었다.

## 3. 참 까닭

브라우저 콘솔 기록의 마지막 줄이 `https://ceadmin.co.kr/dashboard:4819` 였고,
그 앞 네 줄이 **`/api/auth/me` 401** 이었다. 거기서 길이 풀렸다.

1. `GET /m` — 웹 세션이 있으니 모바일 화면이 **200** 으로 그려진다.
2. 모바일 화면이 `mApi('/auth/me')` 로 **`GET /api/auth/me`** 를 부른다.
   (`resources/views/layouts/mobile.blade.php` 318줄)
3. `/api/*` 는 `auth:sanctum` 이고, `bootstrap/app.php` 가 `statefulApi()` 를 쓴다.
   Sanctum 의 `EnsureFrontendRequestsAreStateful::fromFrontend()` 는 요청의
   **Referer / Origin 자리**를 `config('sanctum.stateful')` 목록과 견준다.
   목록에 없으면 세션 미들웨어(`StartSession`)를 아예 끼우지 않는다 →
   세션이 없는 것과 같아져 **401 `Unauthenticated.`**
4. 그 목록은 `APP_URL` 하나에서 나온다.
   - 운영(`/opt/ce-admin`) `APP_URL=https://75.2.99.52` → 목록 `… , 75.2.99.52`
   - 시험기(`ceadmin.co.kr` · `3.34.53.36`) `APP_URL=https://www.ceadmin.co.kr`
   → **`www` 를 뗀 `ceadmin.co.kr` 은 목록에 없다.**
5. 모바일 화면은 401·419 를 보면 `location.assign(route('m.login'))` 로 되돌려 보낸다.
   (`mobile.blade.php` 294~298줄)
6. `/m/login` 은 `guest` 미들웨어다. 이미 로그인한 사람에게
   라라벨 기본값 `RedirectIfAuthenticated::defaultRedirectUri()` 가
   `dashboard` 라는 노선 이름을 찾아 **`route('dashboard')`** 로 보낸다.
   (`vendor/laravel/framework/.../Auth/Middleware/RedirectIfAuthenticated.php` 60~78줄)

→ **폰에 웹 대시보드가 뜬다.**

### 실측

| 확인 | 값 |
|---|---|
| `fetch('/api/auth/me')` at `ceadmin.co.kr` | **401** · `{"message":"Unauthenticated."}` |
| `fetch('/m/login')` 최종 주소 | **`https://ceadmin.co.kr/dashboard`** |
| 운영 서버 `config('sanctum.stateful')` | `localhost / localhost:3000 / 127.0.0.1 / 127.0.0.1:8000 / ::1 / 75.2.99.52` |
| `ceadmin.co.kr` · `www.ceadmin.co.kr` DNS | 둘 다 `3.34.53.36` (같은 서버) |

## 4. 어디까지 번지는 결함인가

`/api/*` 가 통째로 401 이므로 **H5 의 모든 화면**이 먹지 않는다 — 처방전 목록·상세·
업로드·채팅·알림·공지·문의·설정이 모두 `mApi` 를 쓴다. 겉으로는 「웹 화면이 뜬다」
하나로 보이지만 실제로는 H5 전체가 그 주소에서 못 쓰이는 상태였다.

운영(`75.2.99.52`)은 IP 로만 들어오니 지금은 멀쩡하다. 다만 운영 도메인을
`mycolo.co.kr` 로 옮기면 **같은 자리에서 똑같이 끊긴다** — apex 와 www 중 `APP_URL` 에
적지 않은 쪽이 죽는다.

## 5. 고친 것

### (1) `config/sanctum.php` — 세션을 받아 줄 자리를 명시

```php
'stateful' => explode(',', env('SANCTUM_STATEFUL_DOMAINS', sprintf(
    '%s%s%s',
    'localhost,localhost:3000,127.0.0.1,127.0.0.1:8000,::1',
    Sanctum::currentApplicationUrlWithPort(),
    ',75.2.99.52,ceadmin.co.kr,www.ceadmin.co.kr,mycolo.co.kr,www.mycolo.co.kr',
))),
```

`Sanctum::currentRequestHost()` 를 켜는 길도 있으나, 그것은 **어떤 Host 로 들어와도**
세션 자리로 삼는다(Sanctum 기본 설정에서도 주석으로 꺼져 있다). 우리가 쓰는 자리만
적는 쪽을 골랐다. 도메인이 늘면 이 줄에 더한다.

### (2) `bootstrap/app.php` — 이미 로그인한 사람이 `/m/login` 을 열었을 때

```php
$middleware->redirectUsersTo(fn ($request) =>
    $request->is('m', 'm/*') ? route('m.prescriptions') : route('dashboard'));
```

`redirectGuestsTo` 는 손님을 모바일 로그인으로 보내 주는데, 그 반대쪽이 비어 있었다.
(1) 만 고쳐도 이번 증상은 사라지지만, 로그인한 사람이 `/m/login` 을 즐겨찾기로 열면
여전히 웹 화면이 떴다 — 그 자리도 함께 막았다.
