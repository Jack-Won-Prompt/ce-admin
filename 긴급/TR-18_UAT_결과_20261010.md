## 2. 수행 중에 찾아 고친 결함 둘

### 2-1. www 를 뗀 주소에서 H5 가 통째로 막혔다 (`bc2e50cf`)

`/api/*` 는 `auth:sanctum` + `statefulApi()` 라, Sanctum 이 요청의 Referer/Origin 자리를
`config('sanctum.stateful')` 과 견주어 **적힌 자리에만** 세션 미들웨어를 끼웁니다.
그 목록은 `APP_URL` 하나에서 나오므로 `ceadmin.co.kr`(www 없음)은 빠져 있었고,
`/api/auth/me` 부터 401 이었습니다. 모바일 화면은 401 을 보면 `/m/login` 으로 되돌려
보내고, `/m/login` 은 이미 로그인한 사람을 `route('dashboard')` 로 보냅니다 —
그래서 **폰에 웹 대시보드가 떴습니다.**

고친 것 — `config/sanctum.php` 에 우리가 쓰는 자리를 www 있는 것·없는 것 모두 적고
(`75.2.99.52 · ceadmin.co.kr · www.ceadmin.co.kr · mycolo.co.kr · www.mycolo.co.kr`),
`bootstrap/app.php` 에 `redirectUsersTo()` 를 더해 로그인한 사람이 `/m/login` 을 열면
모바일 목록으로 보냅니다. 자세한 기록은 `긴급/오류기록_20261010_H5_apex_401.md`.

### 2-2. 상세의 환자 성명이 비었다 (`d27612b4`)

| 자리 | 성명을 어디서 읽나 |
|---|---|
| 목록 `PrescriptionApiController::index` **386줄** | `$p->patient?->name ?? $p->patient_name_ocr` |
| 조회 `lookup` **546줄** | `$p->patient?->name ?? $p->patient_name_ocr` |
| **상세 `formatOcrResult` 897줄 (고치기 전)** | **`$p->patient_name_ocr` 하나만** |

앱·H5 업로드는 환자를 **거래처에서 골라** 붙이고 `createWith()` 는 `patient_name_ocr` 을
채우지 않습니다. 그래서 올린 그 사람이 자기 건을 열면 전화만 있고 성명이 빈 칸이었습니다.
`formatOcrResult()` 는 **SR 모바일 앱도 같이 먹습니다** — 앱 상세도 같았습니다.

```php
// PrescriptionApiController::formatOcrResult() 897줄
'patient_name' => $p->patient_name_ocr ?: $p->patient?->name,
```

앱은 이 칸을 **읽기만** 하고 되저장하는 자리가 없어(`ce_app/lib/models/prescription.dart`),
거래처 이름이 OCR 칸으로 넘어가 적힐 걱정은 없습니다. 자료를 소급해 고치지 않습니다.

**운영에서 확인** — `RX-20261010-001` 은 `patient_name_ocr = NULL`, `patient_id = 1641`
인데 화면과 API 모두 **(E)이원형** 을 돌려줍니다. OCR 칸이 채워진 건은 그 값을 그대로
씁니다(`RX-20261008-070` → (E)이원형).

### 2-3. 같은 뿌리 — 실시간 알림 (`e96cc6fe`)

`app/Events/PrescriptionUploaded.php` 36줄도 OCR 칸 하나만 보고 있어, 앱·H5 로 올라온
건이 웹 담당자 실시간 알림에 **늘 「미인식」**으로 떴습니다. 같은 잣대로 맞췄습니다.
운영에서 `RX-20261010-001` 의 알림 내용이 **(E)이원형** 으로 나오는 것을 확인했습니다.
