## 2. 찾은 결함 — 상세의 환자 성명이 빈 칸이다

### 무엇이 보이나

`RX-20261010-001`(H5 로 올린 건) 상세의 「환자 정보」에 **전화만 있고 성명이 없습니다.**
한 화면 앞 목록에는 같은 건이 **(E)김감기** 로 보입니다. 같은 건인데 화면마다 다릅니다.

### 까닭 (소스)

| 자리 | 성명을 어디서 읽나 |
|---|---|
| 목록 `PrescriptionApiController::index` **386줄** | `$p->patient?->name ?? $p->patient_name_ocr` |
| 조회 `lookup` **546줄** | `$p->patient?->name ?? $p->patient_name_ocr` |
| **상세 `formatOcrResult` 897줄** | **`$p->patient_name_ocr` 하나만** |

H5·앱으로 올린 건은 환자를 **거래처에서 골라** 붙이므로 `patient_name_ocr` 가 비어 있습니다.

```
RX-20261010-001  patient_id=12986  patient_name_ocr=NULL  patient->name=(E)김감기
RX-20260930-011  patient_id=12986  patient_name_ocr='(E)김감기'
RX-20260930-004  patient_id=12986  patient_name_ocr='(E)김감기'
```

2026-09-30 두 건은 `patient_name_ocr` 가 채워져 있어 성명이 보입니다 — 그래서 여태 드러나지
않았습니다. **올린 그 사람이 자기 건을 열었을 때만 비어 보입니다.**

### 번지는 곳

`formatOcrResult()` 는 **SR 모바일 앱도 같이 먹습니다.** 앱 상세에도 같은 빈 칸이 뜹니다.
화면 하나가 아니라 두 화면입니다.

### 고칠 안 (아직 손대지 않음)

```php
// PrescriptionApiController::formatOcrResult() 897줄
'patient_name' => $p->patient_name_ocr ?: $p->patient?->name,
```

OCR 로 읽힌 값을 먼저 쓰고(이 묶음이 「OCR 결과」이므로), 없으면 고른 환자 이름으로 받칩니다.
목록·조회와 **보이는 값이 같아집니다.**

함께 볼 것 — 앱이 이 칸을 **고쳐 저장**하는 자리가 있다면, 거래처 이름이 `patient_name_ocr`
로 넘어가 적힐 수 있습니다. 앱 쪽 저장 경로를 확인한 뒤 올려야 합니다.

**지시 「내용을 소스를 직접 확인해서 다른 부분이 있으면 보고하면 확인 후 진행하겠음」에 따라
보고만 하고 고치지 않았습니다.**
