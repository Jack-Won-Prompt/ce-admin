## 2. 시험 중에 찾아 고친 결함 — 상세의 환자 성명이 비었다

### 무엇이 보였나

`RX-20261010-001`(H5 로 올린 건) 상세의 「환자 정보」에 **전화만 있고 성명이 없었습니다.**
한 화면 앞 목록에는 같은 건이 **(E)김감기** 로 보였습니다. 같은 건인데 화면마다 달랐습니다.

### 까닭 (소스)

| 자리 | 성명을 어디서 읽나 |
|---|---|
| 목록 `PrescriptionApiController::index` **386줄** | `$p->patient?->name ?? $p->patient_name_ocr` |
| 조회 `lookup` **546줄** | `$p->patient?->name ?? $p->patient_name_ocr` |
| **상세 `formatOcrResult` 897줄 (고치기 전)** | **`$p->patient_name_ocr` 하나만** |

앱·H5 업로드는 환자를 **거래처에서 골라** 붙이고, `createWith()` 는 `patient_name_ocr` 을
채우지 않습니다. 그래서 그 칸이 비어 있었습니다.

```
RX-20261010-001  patient_id=12986  patient_name_ocr=NULL  patient->name=(E)김감기
RX-20260930-011  patient_id=12986  patient_name_ocr='(E)김감기'
RX-20260930-004  patient_id=12986  patient_name_ocr='(E)김감기'
```

2026-09-30 두 건은 `patient_name_ocr` 가 채워져 있어 성명이 보였습니다 — 그래서 여태 드러나지
않았습니다. **올린 그 사람이 자기 건을 열었을 때만** 비어 보였습니다.

`formatOcrResult()` 는 **SR 모바일 앱도 같이 먹습니다.** 앱 상세에도 같은 빈 칸이 떴습니다.

### 고친 것 (`d27612b4`)

```php
// PrescriptionApiController::formatOcrResult() 897줄
'patient_name' => $p->patient_name_ocr ?: $p->patient?->name,
```

OCR 로 읽힌 값을 먼저 쓰고(이 묶음이 「OCR 결과」이므로), 없으면 고른 환자 이름으로 받칩니다.
앱은 이 칸을 **읽기만** 하고 되저장하는 자리가 없어(`ce_app/lib/models/prescription.dart`),
거래처 이름이 OCR 칸으로 넘어가 적힐 걱정은 없습니다. 자료를 소급해 고치지 않습니다.

### 고친 뒤 확인

| 건 | 상세의 성명 |
|---|---|
| `RX-20261010-001` (H5 업로드 · OCR 칸 빈 것) | **(E)김감기** |
| `RX-20260930-011` (OCR 칸 채워진 것) | (E)김감기 — 그대로 |
| `RX-20260930-004` (OCR 칸 채워진 것) | (E)김감기 — 그대로 |

## 3. 같은 뿌리의 자리도 함께 고쳤다

`app/Events/PrescriptionUploaded.php` **36줄** 이 아래처럼 OCR 칸 하나만 보고 있었습니다.

```php
'patient_name'  => $p->patient_name_ocr ?? '미인식',
```

앱·H5 로 올라온 건은 그 칸이 비어 있으므로, 웹 담당자 화면에 뜨는 실시간 알림이
**늘 「미인식」**으로 보였습니다. 상세 화면과 같은 잣대로 맞췄습니다.

```php
'patient_name'  => $p->patient_name_ocr ?: ($p->patient?->name ?? '미인식'),
```
