# 다시 발행한 현금영수증이 「취소거래」로 그려졌다 (2026-10-16 확인요청)

## 신고 내용

(E)김종욱A 님 현금영수증을 취소하고 환자가 요청한 번호로 재발행했다.
팝빌에는 **승인거래**로 떠 있는데, 주문 등록 화면의 현금영수증 이미지는
**취소거래**로 보인다.

## 확인 결과

```
10-15 10:42:32  현금영수증 발행 K00024646
10-16 10:11:48  취소          K00013366
10-16 10:12:01  재발행        K00013415   ← 지금 살아 있는 증빙
```

우리 주문 칸은 재발행 건으로 정확히 갱신되어 있었다.

```
cash_receipt_status      issued
cash_receipt_no          K00013415
cash_receipt_issued_at   2026-10-16 10:12:01
cash_receipt_cancelled_at 2026-10-16 10:11:48   ← 비워지지 않고 남음
```

서식은 **취소 시각 하나만** 보고 문서형태를 정했다.

```php
'docKind' => $order->cash_receipt_cancelled_at ? '취소거래' : '승인거래',
```

그래서 승인번호와 거래일시는 재발행 건인데 **문서형태만 「취소거래」**가 되었다.

## 원인

현금영수증을 발행할 때 `cash_receipt_cancelled_at` 을 비우지 않았다. 취소한 뒤 다시
발행하면 앞 건의 취소 시각이 그대로 남는다.

## 같은 증상 3건

```
EUD202610061259111 · (E)김지수B · K00043959 · 취소 10-06 14:12 → 재발행 14:41
EUD202610121542471 · (E)김정수C · K00129161 · 취소 10-13 12:20 → 재발행 12:20
EUD202610151021081 · (E)김종욱A · K00013415 · 취소 10-16 10:11 → 재발행 10:12
```

세 건 모두 팝빌에는 **승인거래**로 살아 있고, 우리 승인번호도 그 승인거래와 같다.
우리 종이만 취소로 그려져 있었다.

## 고친 것

### ① 발행할 때 취소 시각을 비운다

```php
'cash_receipt_issued_at'    => $issuedAt,
'cash_receipt_cancelled_at' => null,
```

취소된 앞 건의 기록은 팝빌과 우리 `cashbill_records` 에 그대로 남는다.

### ② 서식은 상태 칸을 먼저 본다

```php
'docKind' => ((string) $order->cash_receipt_status === 'cancelled'
              || (! $order->cash_receipt_no && $order->cash_receipt_cancelled_at))
             ? '취소거래' : '승인거래',
```

시각 하나로 가리면 같은 일이 되풀이된다. 지금 살아 있는 증빙이 무엇인지는 상태 칸이
말한다.

커밋 `19c99af7`. 운영 반영 완료.

## 자료 바로잡기

세 건의 취소 시각을 비우고 서식을 다시 그려 붙였다. **팝빌에는 손대지 않았다** —
우리 쪽 칸과 종이만 바로잡았다.

움직이기 전에 잣대를 세 가지로 확인했다.


세 건 모두 세 조건을 만족했다.

## 함께 눈에 띈 것

(E)김정수C 님 건은 서식의 **거래일시가 팝빌과 다르다**.

```
우리 서식   2026-10-13 12:20:49   (cash_receipt_issued_at — 우리가 발행을 요청한 시각)
팝빌        2026-10-12 16:12:51   (trade_dt — 저쪽이 적은 거래일시)
```

서식은 우리 발행 시각을 쓰고 팝빌은 저쪽 거래일시를 쓴다. (E)김종욱A 님 건은 두 값이
같아 드러나지 않았다.

어느 쪽을 정본으로 할지 정해야 한다. 국세청에 신고된 값은 팝빌 쪽이므로 **팝빌의
거래일시를 쓰는 것이 맞다**고 본다. 지시를 기다린다.

## 거래일시를 팝빌 값으로 바꿈 (2026-10-16 지시 「반영」)

### 고친 것

서식의 거래일시를 **팝빌이 적은 값**(`cashbill_records.trade_dt`)으로 적는다. 승인번호로
그 줄을 찾는다. 저쪽 기록이 없으면 우리 발행 시각으로 갈음한다 — 비워 두는 것보다 낫다.

```php
$팝빌  = self::팝빌줄($order);          // confirm_num 으로 찾는다
$거래일시 = self::시각($팝빌->trade_dt ?? null)
        ?? $order->cash_receipt_issued_at?->format('Y-m-d H:i:s')
        ?? '-';
```

### 서식을 모두 다시 그렸다


초 단위 차이가 있던 120건까지 함께 맞췄다. 서식은 언제든 다시 그릴 수 있는 종이이고,
홈택스와 나란히 놓고 볼 때 한 글자라도 다르면 담당자가 멈춰 선다.

**팝빌에는 손대지 않았다.** 국세청에 신고된 값은 그대로이고, 우리 종이를 그 값에
맞춘 것이다.
