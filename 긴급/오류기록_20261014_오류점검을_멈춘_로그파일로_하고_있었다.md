# 오늘 오류 점검을 **9월 23일에 멈춘 로그 파일**로 하고 있었다

- 날짜 : 2026-10-14
- 찾은 자리 : 토스 웹훅 서명 생김새를 재려고 로그를 뒤지다가
- 성격 : **내가 낸 잘못**이다. 코드가 아니라 내 점검 방법이 틀렸다.

## 무엇이 틀렸나

```
LOG_CHANNEL=daily   → 오늘 것은 laravel-2026-10-14.log 에 쌓인다

storage/logs/
   laravel-2026-10-14.log   514,891 바이트   ← 지금 쌓이는 곳
   laravel.log            7,027,221 바이트   ← **2026-09-23 에 멈춘 파일**
```

나는 오늘 하루 종일 `laravel.log` 를 보며 **「오늘 자 ERRORㆍCRITICAL 0건」**이라고
보고했다. 그 파일은 3주 전에 멈춘 것이라 **무엇이 있어도 0건**이었다.

올바른 파일로 보니 **26건**이 있었다.

## 실제로는 26건이었다

```
[Toss] 이미 입금된 결제 줄을 덮으려 했다 — 멈춘다      8건  ← 보호 장치가 막은 것
[Toss] API 오류                                        8건
[결제전송] 승인 실패                                   7건
Writing to directory /var/www/.config/psysh …          2건  ← 내가 돌린 tinker 가 낸 것
PHP Parse error …                                      1건  ← 내가 돌린 tinker 가 낸 것
```

### 하나 — 보호 장치가 일한 것 8건 (좋은 소식)

어제 넣은 「이미 입금된 결제 줄은 덮지 않는다」가 **오늘만 8번** 막았습니다. 레벨이
ERROR 이지만 **막아 낸 것**이지 탈이 난 것이 아닙니다.

### 둘 — 결제 승인 실패 15건 (8+7) — **돈은 모두 제대로 들어가 있다**

```
ALREADY_PROCESSED_PAYMENT   이미 처리된 결제   (돌아오는 화면 새로고침ㆍ웹훅과 겹침)
DUPLICATED_ORDER_ID         이미 쓴 주문번호
ALREADY_CANCELED_PAYMENT    이미 취소된 결제
```

해당 링크 다섯(453ㆍ491ㆍ496ㆍ500ㆍ514)의 주문을 토스에 다시 물어 하나씩 확인했습니다.

| 링크 | 주문 | 환자 | 받을 돈 | 받은 돈 | 토스 |
|---|---|---|---|---|---|
| 453 | EUD202610081716351 | (E)김대한 | 81,000 | 81,000 | DONE |
| 491 | EUD202610071205401 | (E)장성태 | 81,000 | 81,000 | DONE |
| 496 | EUD202610141339211 | (E)김지수B | 81,000 | 81,000 | DONE |
| 500 | EUD202610131336341 | (E)김순환 | 78,750 | 78,750 | DONE |
| 514 | EUD202610121001141 | (E)백은서 | 81,000 | 81,000 | DONE |

**다섯 건 모두 돈이 들어가 있고 증빙과 출고도 걸렸습니다.** 같은 결제를 두 번 승인하려다
토스가 거절한 것이라, 거절이 맞습니다.

### 셋 — 내가 낸 것 3건

`psysh` 디렉터리 쓰기 불가 2건과 PHP 파싱 오류 1건은 내가 서버에서 돌린 `tinker` 가
낸 것입니다. 업무와 무관합니다.

## 고친 것

점검 스크립트가 **날마다 갈리는 파일**을 보도록 했습니다. 보는 파일 이름도 함께 적어,
다시 엉뚱한 것을 보면 바로 드러납니다.

```
━━━ 4. 오늘 오류 ━━━
   보는 파일 : laravel-2026-10-14.log
   모두 26건
      [Toss] 이미 입금된 결제 줄을 덮으려 했다 — 멈춘다  8건  ← 보호 장치가 막은 것
      …
```

막아 낸 것은 「보호 장치가 막은 것」이라 적어, 탈과 섞이지 않게 했습니다.

## 돌아보면

로그 파일이 둘 있고 하나가 멈춰 있다는 것을 **확인하지 않고** 썼습니다. 9월 23일 자
오류가 보였을 때 「오늘은 없구나」로 읽었는데, **그 파일의 마지막 줄이 3주 전이라는 것**이
곧 그 파일이 죽었다는 신호였습니다. 그것을 놓쳤습니다.

오늘 보고드린 「ERROR 0건」은 모두 이 잘못 위에 있었습니다. 다만 **자료에 탈이 난 것은
따로 전수로 확인했고**(받은 돈ㆍ취소액ㆍ빈 주문ㆍ입금 대기), 그쪽은 어긋난 데가 없습니다.
