# 「가상계좌 입금 완료 콜백 호출이 실패했습니다」 메일

- 날짜 : 2026-10-15
- 알린 이 : 운영 담당자 — 「토스에서 계속 메일이 많이 오고 있음 ⇒ 근본적인 해결 필요」
- 메일이 짚은 건 : `CE-EUD202610121331501-20261014121448` · 실패 시각 **2026-10-14 15:39** ·
  재시도 4회

## 왜 실패했나 — **우리가 막았다. 그날 고쳤다.**

```
날짜별 토스 웹훅 응답 (운영)
   10-15  200 53건 · 401 1건(내가 시험으로 부른 것)
   10-14  200 154건 · **401 41건**
   10-13  200 158건 · **401 6건**
   10-12 이전  모두 200
```

401 은 **10-14 15:26 ~ 15:44 에 몰려 있다.** 그때 우리 쪽 서명 검증이 토스 웹훅을
막고 있었고, 같은 날 그것을 고쳤다(서명이 우리 셈과 달라도 막지 않고 지나보낸다).
**그 뒤로 401 이 한 건도 없다.**

메일이 짚은 그 건도 이미 맞춰져 있다.

```
주문 EUD202610121331501 · (E)류기현 · 81,000원
   상태 DONE · 입금 2026-10-14 15:18:20
```

그때 놓친 돈을 사람이 하나씩 찾아 맞춘 486,000원 가운데 하나다.

**지금 오는 메일은 그때 실패한 건의 통보다.** 새로 실패하는 것이 아니다.

## 호출 주소는 멀쩡하다

```
https://75.2.99.52/toss/webhook/hgauksh7rq0p8wkag1h9ox66zjji1uzorg5l92ts
```

밖에서 그대로 불러 보았다 — TLS 검증 통과(인증서 SAN 에 IP 가 들어 있다), 열쇠도 맞다.
오늘도 같은 주소로 53건이 200 으로 들어왔다.

인증서는 IP 전용이라 수명이 엿새(10-12 ~ 10-19)지만, certbot 갱신 타이머가 돌고 있다
(오늘 01:04 에 돌았다).

## 근본 해결 — **받는 길 하나에 돈을 걸지 않는다**

고친 것은 「이번 401」의 원인이다. 그러나 웹훅이 끊기는 길은 그 하나가 아니다 —
저쪽 재시도가 다 끝나거나, 우리 서버가 잠깐 멈추거나, 인증서가 끊기면 똑같이 놓친다.
**토스는 묻지 않으면 다시 알려 주지 않는다.**

그래서 입금을 기다리는 줄을 **토스에 되묻는** 명령을 만들었다(`9d4d42b0`).

```
php artisan toss:sync-deposits        열 분마다
   입금 대기 + 결제키 있음 + 기한이 지난 지 이틀 안쪽인 줄을 토스에 묻는다
   저쪽이 DONE 이면 **웹훅이 하는 바로 그 자리**를 부른다
   --dry 로 무엇이 반영될지 먼저 볼 수 있다
```

두 길이 각자 처리하면 언젠가 갈린다 — 들어오는 문만 둘이고 하는 일은 하나다.
본문을 지어내 넣는 것도 아니다. 그 자리는 결제키로 토스에 다시 물어 확인한 값으로만
움직인다.

운영에서 살펴보기로 돌려 보니 **지금 놓친 입금은 없다.**

```
물어볼 줄 8건 · 반영될 것 0건 · 아직 대기 8건
```

## 그런데 — **운영에 예약 장치가 없다**

만든 명령이 돌려면 `schedule:run` 이 일 분마다 돌아야 한다. 그런데 운영 서버에
**그것이 걸려 있지 않다.**

```
root·ubuntu·www-data 의 crontab   모두 비어 있다
/etc/crontab · /etc/cron.d        artisan 을 부르는 줄이 없다
systemd 타이머                     laravel·schedule 이름이 없다
```

그래서 `routes/console.php` 에 적어 둔 **네 가지가 모두 예약으로는 돌지 않는다.**

```
cashbill:sync --days=1      매시간    현금영수증 팝빌 동기화
cashbill:sync --status      15분마다  국세청 전송 상태 갱신
fax:sync-pending            5분마다   팩스 전송 결과 반영
withworks:sync              10분마다  창고 상태 동기화
```

**그런데도 자취는 갱신되고 있다.**

```
팩스 synced_at 가장 늦은 때      2026-10-15 09:58
현금영수증 synced_at             2026-10-15 12:23
창고 번호가 선 주문 438건 중 오늘 상태가 바뀐 것 59건
```

**사람이 화면을 열 때 함께 도는 길**이 따로 있기 때문이다. 담당자가 일하는 동안은
돌고, **밤이나 주말에는 멈춘다.** 그리고 새로 만든 입금 대사는 화면에서 부르는 자리가
없어 **영영 돌지 않는다.**

## 지시를 기다리는 것

예약을 세우려면 운영 서버에 한 줄을 건다.

```
* * * * * cd /opt/ce-admin && php artisan schedule:run >> /dev/null 2>&1
```

`www-data` 로 걸어야 한다 — artisan 은 그 사용자로 돈다.

세우면 멈춰 있던 넷이 함께 돌기 시작한다. 모두 조회ㆍ반영이라 돈을 쓰거나 지우는 일은
없지만, **갑자기 많은 일이 도는 것**이므로 알리고 받는다. 세우기 전에 넷을 손으로
하나씩 돌려 보는 것이 좋겠다.
