# 위드웍스 처방 서류 이미지가 이관 뒤로 따라오지 않았다 (SR #196)

- 날짜 : 2026-10-13
- 알려 온 것 : 「처방 서류 없음 - 위드웍스 연계건. 우선 위드웍스 이미지 다운받아 CEadmin
  주문등록에 업로드했습니다. 일부 처방 서류 이미지 연결 안 된 게 있는 것 같아 확인 요청」

## 무엇이 보였나

(E)한순이 님 `WW-ADD0073171`(위드웍스 추가정보 179967 · 등록 2026-09-30) —
위드웍스에는 처방전 그림이 있는데 우리 쪽 `image_path` 가 비어 있었다. 그 건의 첨부 4장은
**오늘 담당자가 손으로 올린 것**이다(`ww_detail_id` 가 없다).

## 까닭

둘이다.

1. **최근 3개월치만 받기로 했다** (2026-09-29 지시). 그때 운영 디스크가 29GB 중 23GB 만
   남아 3년치(약 94GB)가 들어가지 않았다.
2. **받는 명령이 한 번 돌고 끝이다.** `prescriptions:fetch-ww-attachments` 가 어느 일정에도
   올라 있지 않다. 그래서 이관 뒤 위드웍스에 새로 올라온 그림은 따라오지 않았다 —
   한순이 건이 이관 **바로 다음 날** 등록이다.

## 한 일 — 최근 한 달치를 받았다

```
php artisan prescriptions:fetch-ww-attachments --months=1 --force --sleep=120
```

`--sleep=120` 으로 한 장마다 쉬어 저쪽 서버에 짐을 덜 지웠다.

| 잣대 | 결과 |
|---|---|
| 받은 것 | **271장** (처방전 그림 117 · 첨부 154) |
| 못 받은 것 | **0** |
| 받은 크기 | 0.20 GB |
| 2026-09-29 뒤 등록분 가운데 없는 것 | 110장 → **19장** |
| (E)한순이 건 | `image_path` 가 섰다 (`prescriptions/ww/2026/09/…jpg`) |

남은 19장은 **위드웍스 쪽에도 그림이 없는 건**이다. 명령은 저쪽에 등록된 파일만 세고
받으므로, 그 19장은 받을 것이 애초에 없었다.

## 달라진 것 — 디스크가 넓어졌다

2026-09-29 에는 29GB 중 23GB 였는데 지금은 **96GB 중 79GB** 가 남아 있다.
범위를 넓힐 수 있다.

| 범위 | 받을 것 | 크기 |
|---|---|---|
| 최근 1년 | 28,912장 | 약 26 GB |
| 3년 전체 | — | 약 94 GB (아직 안 들어간다) |

## 지시를 기다린다

1. 받는 범위를 1년치로 넓힐지
2. 새로 등록되는 그림이 저절로 따라오도록 **날마다 도는 일**로 올릴지 — 지금은 사람이
   손으로 받아 올려야 한다
