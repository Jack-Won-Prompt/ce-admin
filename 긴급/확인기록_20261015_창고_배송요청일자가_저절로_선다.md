# 출고요청일을 비워 두어도 창고에는 「등록일 +3일」이 선다

- 날짜 : 2026-10-15
- 알린 이 : 운영 담당자 — 「배송예정일자 선택 안 했음에도 판매일자가 10/14 인데
  위드웍스 배송요청일자가 10/17 로 보임」
- 보기 : 판매번호 `S2610140429` · etc SoNo `EUD202610141743521` · (E)정지현

## 우리 표에는 비어 있다

```
orders #768  EUD202610141743521
   ship_request_date   NULL        ← 출고요청일. 사람이 적는 칸. 비어 있다
   estimated_delivery  2026-10-17  ← 예상 배송일
   created_at          2026-10-14 17:43:52
   withworks_so_no     S2610140429
```

창고에 선 `2026-10-17` 은 `estimated_delivery` 와 같다.

## 어디서 들어갔나 — 화면이 빈 칸을 예상 배송일로 갈아 넣는다

주문 등록 화면이 창고로 보낼 내용을 지을 때 이렇게 되어 있다.

```js
/* 적어 둔 출고요청일이 먼저다. 없으면 여태처럼 예상 배송일로 나간다
   (2026-09-11 확인요청 5쪽). */
delivery_date: document.getElementById('shipRequestDate')?.value
                 || res.estimated_delivery || null,
```

`shipRequestDate` 는 사람이 고르는 칸이고, 비우면 `res.estimated_delivery` 가 대신 간다.

그 `estimated_delivery` 는 주문을 세울 때 **아무 근거 없이 사흘 뒤로 박는다.**

```php
'estimated_delivery' => now()->addDays(3)->format('Y-m-d'),
```

```
2026-10-14 (주문 등록) + 3일 = 2026-10-17 → 창고의 배송요청일자
```

**서버 쪽은 비워 보낸다** — `WithworksLink::창고내용` 은 `ship_request_date` 를 쓰므로
NULL 이다. 날짜를 끼워 넣는 것은 **화면 한 줄뿐**이다.

## 얼마나 되나 (운영 `unicorn_mycolo`)

```
주문 모두                      627건
   출고요청일을 적은 것         135건
   비워 둔 것                   492건
   그 가운데 창고에 선 것       290건   ← 모두 날짜가 저절로 들어간 건들

비워 둔 290건의 예상 배송일 — 등록일과의 차이
   +3일 184건
   +4일 24 · +5일 11 · +7일 11 · +8일 10 · +9일 18 · +10일 9 … (모두 106건)
```

`+3` 이 아닌 건들은 주문을 **다시 세운** 건들이다. 껍데기를 채울 때
`$existing->update($attrs)` 가 `estimated_delivery` 를 그때의 「오늘 +3」으로 다시 박는데
`created_at` 은 처음 그대로라 차이가 벌어진다.

## 무엇이 문제인가

1. **우리 화면과 창고가 어긋난다.** 우리 주문 상세의 출고요청일은 비어 있는데 창고에는
   날짜가 서 있다. 담당자가 둘을 견주면 맞지 않는다 — 이번에 눈에 띈 것이 그것이다.
2. **그 날짜에 근거가 없다.** 「사흘」은 어디서 온 수가 아니다. 창고 리드타임도,
   택배 일수도, 영업일도 보지 않는다. 토요일ㆍ일요일ㆍ공휴일도 그대로 센다.
3. 같은 값이 **주문 상세 화면의 「예상 배송일」**ㆍ**주문 등록 성공 알림**ㆍ**앱의 주문
   목록**에도 그대로 나간다. 환자가 보는 날짜이기도 하다.

## 고치는 길 셋 — 어느 쪽인지 알려 주십시오

### ㈎ 비워 두면 **비워서** 보낸다 (가장 단순)

화면의 `|| res.estimated_delivery` 를 걷는다. 그러면 창고로 `delivery_date` 가 가지 않고,
위드웍스가 자기 기준으로 채우거나 빈 채로 선다. 우리 화면과 창고가 **늘 같아진다.**

다만 저쪽이 빈 값을 어떻게 다루는지 먼저 물어봐야 한다 — 필수 칸이면 등록이 거절될 수
있다.

### ㈏ 비워 두면 **판매일자(주문 등록일)** 로 보낸다

담당자 말씀의 「판매일자가 10/14 인데」가 이 뜻으로 읽힌다. 날짜가 반드시 있어야 하는
칸이라면 이 쪽이 맞다.

### ㈐ 지금 그대로 두되 **화면에도 같은 날짜를 보인다**

창고로 보낸 날짜를 `ship_request_date` 에 함께 적어, 우리 화면과 창고가 어긋나지 않게
한다. 「사흘」이라는 근거 없는 수는 그대로 남는다.

## 아직 고치지 않았다

2026-09-11 확인요청 5쪽에 따라 **일부러 넣은 동작**이라, 되돌리는 것은 업무 규칙을
바꾸는 일이다. 지시를 받고 하겠다.

이미 선 290건의 창고 날짜를 어떻게 할지도 함께 알려 주시면 좋겠다 — 그대로 둘지,
맞출지.
