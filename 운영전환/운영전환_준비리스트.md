## 2. 밖에 등록해야 하는 것 (조용히 멈추는 자리)

콜백은 틀려도 화면에 아무 표시가 없다. 담당자는 「왜 상태가 안 바뀌지」로만 겪는다.

### 2-1. 토스 — **운영 상점에 따로 등록**
테스트와 운영 개발자센터가 분리되어 있다. 테스트에 등록한 것은 쓰이지 않는다.

```
결제ㆍ가상계좌   https://<도메인>/toss/webhook/<인증키>
```

### 2-2. 팝빌 — **운영 팝빌(popbill.co.kr)에 다섯 곳**
테스트베드에 등록한 것은 쓰이지 않는다.

```
팩스 · 문자 · 알림톡 · 세금계산서 · 현금영수증
https://<도메인>/popbill/webhook/<인증키>/{fax|sms|kakao|taxinvoice|cashbill}
```

### 2-3. 위드웍스
```
https://<도메인>/api/webhook/withworks
```
`webhook_secret` 이 운영도 같은 값인지 확인한다.

### 2-4. 도메인을 바꾸면 **콜백 넷을 다시 등록**한다
```
toss/webhook · nhis/fax-callback · webhooks/shop-order · consent/*/nice/callback
```
**옛 도메인도 한동안 함께 받게 둔다.** 한 번에 끊으면 그 사이 것이 사라진다.

### 2-5. 「인증 키 확인」 토글 — **순서를 지킨다**
지금 토스 `꺼짐` · 팝빌 `켜짐`.
**새 주소를 등록한 뒤에** 켠다. 먼저 켜면 그 사이 수신분이 401 로 버려진다.

## 3. 설정 화면에서 바꿀 것 (순서대로)

되돌리기 쉬운 것부터, 국세청 신고는 맨 뒤로.

### ① 위드웍스 — 설정 › 위드웍스
1. **운영 API 토큰 입력** (위 1번)
2. 사용 환경 = **운영 (위드웍스)**
3. 판매유형 코드 `1501·1504·1505·1506·1092` 가 운영 `code_list` 에도 같은지 확인

### ② NICE — 설정 › 본인확인(NICE)
- **본인확인 필수 = 켬**
- NICE 는 test/live 구분이 없다. **지금 자격증명이 곧 운영**이고, 켜는 순간 건당 요금이 붙는다.
- 「연결 테스트」는 표준창을 열지 않아 요금 없이 토큰 발급까지만 본다.

### ③ 토스 — 설정 › 토스페이먼츠
1. 운영 웹훅 주소 등록 (위 2-1)
2. 「웹훅 보안 키」를 **운영 상점 값**으로 교체
3. 사용 환경 = **운영**
4. 「인증 키 확인」 켬
- 이때부터 카드 승인은 **실제 청구**, 환불도 실제다.
- 가상계좌를 쓰려면 **운영 상점에 가상계좌 계약**이 붙어 있어야 한다(없으면 2003 오류).

### ④ 팝빌 — 설정 › 팝빌 · 테스트 설정
**여기가 가장 위험하다.** `env=live` + 발행 시뮬레이션 꺼짐이면 세금계산서ㆍ현금영수증
발행이 **국세청 실신고**다. 시험으로 한 장 내면 취소 신고를 또 내야 하고 콜로플라스트
이름으로 남는다.

권하는 차례 —
1. 운영 발신번호 승인 확인 (문자·팩스가 **따로** 승인된다)
2. 문자 환경 = **사용 환경 따름** 으로 되돌림 ※ 지금 시험용으로 「운영」이다
3. 사용 환경 = **운영**
4. 세금계산서·현금영수증만 서비스별 환경을 **테스트로 남겨 두고** 흐름 확인
5. 확인이 끝나면 그 둘도 「사용 환경 따름」으로

### ⑤ 테스트 설정 (설정 › 테스트 설정)
| 항목 | 지금 | 운영 |
|---|---|---|
| 웹 화면 | 테스트 | **운영 (번호 직접 입력)** |
| 문자 발송 | 실제 | 실제 (그대로) |
| 팩스 발송 | **우리에게만** | **실제 (관할 지사로)** |
| 본인확인 시뮬레이션 | 꺼짐 | 꺼짐 (그대로) |

## 8. 전환 직후 반드시 눈으로 볼 것

한 건을 끝까지 태워 본다. **처음 한 건은 우리 사람으로**.

1. 주문 등록 → 결제 링크 → **실제 카드 승인** (실제 청구된다)
2. 가상계좌 발급 → 입금 → **웹훅이 들어오는지**
3. 세금계산서 발행 → **국세청 승인번호가 오는지** · 종이 두 벌이 맞는지
4. 현금영수증 발행
5. 팩스 발송 → **공단으로 실제로 갔는지**
6. 위드웍스 판매주문 등록 → **운영 위드웍스에 섰는지** · 주소·거래명세서 발행일
7. 위임동의 서명 → **NICE 본인확인이 실제로 뜨는지**
8. Microsoft 계정으로 로그인 (SSO)

## 9. 되돌리는 길

전환 뒤 문제가 생기면 **설정 화면에서 되돌린다** — `.env` 를 고치거나 배포할 필요가 없다.

| 무엇 | 되돌리기 |
|---|---|
| 토스 | 사용 환경 = 테스트 |
| 팝빌 전체 | 사용 환경 = 테스트 |
| 팝빌 일부 | 서비스별 환경만 테스트로 |
| 국세청 신고만 막기 | 발행 시뮬레이션 켬 |
| 팩스만 막기 | 팩스 발송 = 우리에게만 / 시뮬레이션 |
| 위드웍스 | 사용 환경 = 테스트 |
| NICE | 본인확인 필수 끔 |

**이미 나간 것은 되돌아오지 않는다** — 카드 승인, 국세청 신고, 팩스, 문자.
그래서 위 3번의 차례가 「되돌리기 쉬운 것부터」다.

## 알아 둘 것 — 설정 캐시

배포할 때 도는 `php artisan optimize` 가 **DB 설정값을 config 캐시에 함께 굽는다**
(`ServiceSettings::applyToConfig()` 가 부팅 때 돌고, `config:cache` 가 그 뒤에 덤프한다).

- 설정 화면에서 바꾼 값은 **요청마다 다시 적용되므로 즉시 반영**된다.
- 위험한 쪽은 반대다 — **`.env` 만 고치고 DB 를 그대로 두면 아무 일도 일어나지 않는다.**
