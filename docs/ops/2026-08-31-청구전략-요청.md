# CE Admin 청구전략 — 확인 결과와 요청

2026-08-31 · CE Admin → 위드웍스 팀

---

## 0. 요약

세 가지를 부탁드립니다.

1. **청구전략 두 줄을 만들어 주십시오** — 차상위경감(공단 100%)과 기초·의료급여(지자체 100%). 지금 없어서 그 자격의 주문이 엉뚱한 전략으로 청구됩니다.
2. **기초의 청구 대상 계정을 정해 주십시오** — 지자체(시군구청)로 쓸 계정이 마스터에 없습니다. 저희가 정할 수 있는 것이 아니라 여쭙습니다.
3. **운영(위드웍스)의 `billing_strategies.id` 를 알려 주십시오** — 데모웍스에서 읽은 id 를 그대로 옮기면 엉뚱한 줄을 가리킵니다.

## 1. 확인한 것 — `billing_strategy` 는 코드가 아니라 id 였습니다

저희는 `so_store` 에 `billing_strategy` 를 **25** 로 보내고 있었습니다. 「청구전략 코드」라고 생각했는데, 데모웍스 DB 를 읽어 보니 그것은 **`billing_strategies` 표의 id** 였습니다.

그리고 **25 번 줄은 `account_id = 0` 의 빈 줄입니다.** 코드도 이름도 비어 있습니다 — 아무것도 가리키지 않습니다.

```
id=25  account_id=0  strategy_code=''  strategy_name=''  use_yn=''
```

지금까지 사고가 나지 않은 것은 저쪽이 조용히 받아 주었기 때문입니다.

```php
// CeAdminController::resolveBillingStrategyId()
// "전자세금계산서(100%)" 전략을 우선 사용하고, 없으면 가장 오래된 전략을 사용한다.
```

실제 판매주문을 보면 그 흔적이 그대로 남아 있습니다.

| 판매주문 | 유형 | billing_strategy_id | 이름 |
|---|---|---|---|
| S2608280001 | 1501 | 25 | **(없는 줄)** |
| S2608250001 | 1501 | 25 | **(없는 줄)** |
| S2608240006 | 1501 | 25 | **(없는 줄)** |
| S2608240003 | 1501 | 25 | **(없는 줄)** |
| S2608240013 | 1501 | 136 | 현금영수증(10%)+전자세금계산서(90%) |
| S2608240011 | 1501 | 136 | 현금영수증(10%)+전자세금계산서(90%) |

즉 **저희가 정한 청구전략은 지금껏 한 번도 위드웍스에 닿은 적이 없습니다.** 저희 잘못입니다 — 고쳤습니다(아래 4장).

## 3. CE Admin 의 청구전략 여섯 가지

저희는 **유형 × 자격**으로 청구전략을 정합니다. 유형은 `10 처방전` 과 `20 처방외` 둘입니다.

> 원내(`30`)는 따로 두지 않습니다. 부담 비율도 발행 방식도 원외와 한 글자도 다르지 않아, 저희 쪽에서 `10` 으로 모읍니다.

| 열쇠 | 이름 | 본인부담 | 청구 대상 | 기관부담 | 현금영수증 | 세금계산서 |
|---|---|---:|---|---:|---:|---:|
| `10\|일반` | 처방전 · 일반 | 10% | 건강보험공단 | 90% | 0% | 90% |
| `10\|차상위경감` | 처방전 · 차상위경감 | 0% | 건강보험공단 | 100% | 0% | 100% |
| `10\|기초` | 처방전 · 기초 | 0% | **지자체(시군구청)** | 100% | 0% | 100% |
| `10\|산재` | 처방전 · 산재 | 100% | — | 0% | 0% | 100% |
| `10\|자동차보험` | 처방전 · 자동차보험 | — | — | — | — | — |
| `20\|` | 처방외 | 100% | — | 0% | 100% | 0% |

- **산재**는 본인부담 100% 인데 발행은 세금계산서 100% 입니다. 낸 사람과 세금계산서를 받는 자리가 같지 않습니다.
- **현금영수증은 처방외에만** 나갑니다(2026-08-24 확정). 일반(10/90)도 본인부담이 있지만 그 몫으로 현금영수증을 내지 않고 세금계산서 90% 하나로 끝냅니다.
- **자동차보험**은 저희 쪽 비율이 아직 확정되지 않았습니다. 정해지면 다시 알려 드리겠습니다.

| `10\|차상위경감` | — | ❌ **만들어야 합니다** |
| `10\|기초` | — | ❌ **만들어야 합니다** |

## 5. 만들어 주셨으면 하는 청구전략 두 줄

### ① 차상위경감 — 공단 100%

| 칸 | 값 |
|---|---|
| `account_id` | 136155 (콜로플라스트 코리아) |
| `strategy_code` / `strategy_name` | `공단 전자세금계산서(100%)` *(이름은 편하신 대로)* |
| `type` | `10` (일반) |
| `use_yn` | `Y` |

상세 한 줄:

| 칸 | 값 |
|---|---|
| `line_number` | 1 |
| `to_account_id` | **168924** (국민건강보험공단) |
| `default_yn` | `Y` |
| `billing_rate` | `100` |
| `invoice_yn` | `Y` (세금계산서 발행) |
| `include_tax_yn` | `Y` |

### ② 기초(의료급여) — 지자체 100%

①과 모양은 같고 **청구 대상만 다릅니다.** 그런데 **지자체(시군구청)로 쓸 계정이 마스터에 없습니다.**

찾아본 것: `국민건강보험공단`(168924) · `국민건강복지공단`(168925) 둘뿐이고, 지자체·의료급여·시군구로 쓸 만한 계정은 없었습니다.

기초는 실제로 **시군구청마다 청구처가 다릅니다**(저희는 「관할 청구처」로 건마다 들고 있습니다). 그래서 위드웍스에서 이것을 어떻게 다루실지가 저희가 정할 수 있는 일이 아닙니다. 세 가지 길이 있어 보입니다.

1. **대표 계정 하나** — 「지자체(시군구청)」 계정을 하나 만들고 그리로 청구. 실제 어느 청에 내는지는 CE Admin 이 압니다
2. **시군구청마다 계정** — 정확하지만 마스터가 크게 늘어납니다
3. **판매처(환자) 자리에 0%** — 청구서를 아예 만들지 않고 저희가 알아서 청구

**저희는 1번이 무난해 보입니다만**, 위드웍스 쪽 청구·정산 흐름을 저희가 다 알지 못합니다. 정해 주시면 그대로 따르겠습니다.

> 데모웍스 DB 에 저희가 직접 만들려 했으나, 다른 팀의 마스터 데이터라 손대지 않았습니다. 만들어 주시면 id 를 저희 설정에 넣겠습니다.

## 6. 운영(위드웍스) id 를 알려 주십시오

`billing_strategy` 가 id 이므로 **서버마다 값이 다릅니다.** 데모웍스의 133·136·137 을 운영에 그대로 보내면 엉뚱한 줄을 가리킵니다.

그래서 저희 설정을 테스트·운영으로 갈라 두었습니다.

```php
'withworks_billing_strategy' => [
    'test'       => ['default' => 133, 'map' => [ '10|일반' => 136, … ]],
    'production' => ['default' => null, 'map' => []],   // ← 아직 비어 있습니다
],
```

운영에서 아래 다섯의 id 를 알려 주시면 채우겠습니다.

| 필요한 것 | 데모웍스 id |
|---|---|
| 현금영수증(10%)+전자세금계산서(90%) | 136 |
| 전자세금계산서(100%) | 133 |
| 현금영수증(100%) | 137 |
| 공단 전자세금계산서(100%) *(신규)* | — |
| 지자체 전자세금계산서(100%) *(신규)* | — |

## 곁들여 — 아직 열리지 않은 것 둘

지난번에 여쭌 것과 이어집니다.

1. **데모웍스에 취소·교환이 아직 배포되지 않았습니다.** `return_store` 에 `return_type: "cancel"` / `"exchange"` 를 보내면 422 로 「처리할 수 없는 반품 구분입니다」가 옵니다. 코드(1504·1506)는 `config/ceadmin.php` 에 들어갔는데 데모웍스 서버에는 아직입니다.
   - 재현: `ce_order_number: ORD-0019` · `so_no: S2608240011` · `items: [{item_code:"33560", qty:1}]`
2. **`config/ceadmin.php` 의 주석이 낡았습니다.** 배열에는 1504·1506 이 들어갔는데 바로 위 주석은 아직 「취소·교환은 아직 유형이 없어 매핑하지 않는다 … 요청이 오면 422 로 거절된다」입니다.

그리고 새로 더해 주신 **`ro.rcpt_completed`** 는 CE Admin 쪽에 붙였습니다. `receiving.received_date` 를 접수 건의 「입고일」로 적고, 접수 단계를 「검수중」으로 옮깁니다. 만들어 주셔서 고맙습니다 — 반품주문 확정만 보고 있었더니 물건이 이미 들어왔는데도 「수거중」에 멈춰 있었습니다.
