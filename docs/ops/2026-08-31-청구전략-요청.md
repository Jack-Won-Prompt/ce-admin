## 1. 확인한 것 — `billing_strategy` 는 코드가 아니라 id 였습니다

저희는 `so_store` 에 `billing_strategy` 를 **25** 로 보내고 있었습니다. 「청구전략 코드」라고 생각했는데, 데모웍스 DB 를 읽어 보니 그것은 **`billing_strategies` 표의 id** 였습니다.

그리고 **25 번 줄은 `account_id = 0` 의 빈 줄입니다.** 코드도 이름도 비어 있습니다 — 아무것도 가리키지 않습니다.

```
id=25  account_id=0  strategy_code=''  strategy_name=''  use_yn=''
```

지금까지 사고가 나지 않은 것은 저쪽이 조용히 받아 주었기 때문입니다.

```php
// CeAdminController::resolveBillingStrategyId()
// "전자세금계산서(100%)" 전략을 우선 사용하고, 없으면 가장 오래된 전략을 사용한다.
```

실제 판매주문에 그 흔적이 남아 있습니다.

| 판매주문 | 유형 | billing_strategy_id | 이름 |
|---|---|---|---|
| S2608280001 | 1501 | 25 | **(없는 줄)** |
| S2608250001 | 1501 | 25 | **(없는 줄)** |
| S2608240006 | 1501 | 25 | **(없는 줄)** |
| S2608240003 | 1501 | 25 | **(없는 줄)** |
| S2608240013 | 1501 | 136 | 현금영수증(10%)+전자세금계산서(90%) |
| S2608240011 | 1501 | 136 | 현금영수증(10%)+전자세금계산서(90%) |

즉 **저희가 정한 청구전략은 지금껏 한 번도 위드웍스에 닿은 적이 없습니다.** 저희 잘못이고, 고쳤습니다.

## 2. CE Admin 의 청구전략 여섯 가지

**유형 × 자격**으로 정합니다. 유형은 `10 처방전` 과 `20 처방외` 둘입니다.

> 원내(`30`)는 따로 두지 않습니다. 부담 비율도 발행 방식도 원외와 한 글자도 다르지 않아 저희 쪽에서 `10` 으로 모읍니다.

| 열쇠 | 이름 | 본인부담 | 청구 대상 | 기관부담 | 현금영수증 | 세금계산서 |
|---|---|---:|---|---:|---:|---:|
| `10\|일반` | 처방전 · 일반 | 10% | 건강보험공단 | 90% | 0% | 90% |
| `10\|차상위경감` | 처방전 · 차상위경감 | 0% | 건강보험공단 | 100% | 0% | 100% |
| `10\|기초` | 처방전 · 기초 | 0% | 지자체(시군구청) | 100% | 0% | 100% |
| `10\|산재` | 처방전 · 산재 | 100% | — | 0% | 100% | 0% |
| `10\|자동차보험` | 처방전 · 자동차보험 | 100% | — | 0% | 100% | 0% |
| `20\|` | 처방외 | 100% | — | 0% | 100% | 0% |

- 가르는 잣대는 **「누가 내는가」**입니다. 기관(공단ㆍ지자체)이 내면 세금계산서로, 개인이 전액을 내면 현금영수증으로 갑니다.
- 그래서 **처방외ㆍ자동차보험ㆍ산재** 셋이 현금영수증 100% 로 같습니다 — 보험사도 근로복지공단도 환자가 따로 받습니다. 산재는 2026-08-31 에 세금계산서에서 현금영수증으로 고쳤습니다.
- **일반(10/90)만 예외**입니다. 본인부담 10% 가 있지만 그 몫으로 현금영수증을 따로 내지 않고 세금계산서 90% 하나로 끝냅니다.

| 저희 열쇠 | 데모웍스 전략 | id |

만들어 주신 셋을 값까지 읽어 확인했습니다.

```
[245] 공단 전자세금계산서(100%)      type 10   줄1  국민건강보험공단 100%  세금계산서 Y

```

이 둘은 부탁드린 값 그대로입니다.

### 다만 — 249ㆍ250 은 상세 줄이 비어 있습니다

246(지자체 직접청구)을 지우시고 **249 지자체 기초(100%)** · **250 산재 현금영수증(100%)** 을
새로 만드셨는데, 둘 다 상세 줄에 값이 들어오지 않았습니다.

```
전략 133  줄1    to=NULL      rate=100  invoice='Y'    tax='Y'      ← 정상
전략 245  줄1    to='168924'  rate=100  invoice='Y'    tax='Y'      ← 정상
전략 247  줄1    to=NULL      rate=100  invoice='N'    tax='Y'      ← 정상
전략 249  줄62   to=NULL      rate=0    invoice=NULL   tax=NULL     ← ⚠
전략 250  줄63   to=NULL      rate=0    invoice=NULL   tax=NULL     ← ⚠
```

이름과 비고는 100% 라 적혀 있는데 실제 줄은 아무것도 청구하지 않습니다.
`line_number` 도 62ㆍ63 입니다 — 다른 것은 모두 1 입니다. 화면에서 저장하실 때
상세가 함께 실리지 않은 듯합니다. **채워 주십시오.**

**250 산재**는 비고를 고쳐 주셔서 이름ㆍ비고ㆍ저희 표가 이제 한 말을 합니다 —
본인 100% · 현금영수증 100% · 세금계산서 없음. 저희 표도 그에 맞춰 고쳐
133(전자세금계산서 100%)에서 **250 으로 옮겼습니다.** 낸 사람이 개인인데
세금계산서를 내고 있었습니다.

다만 **250 의 상세 줄은 아직 비어 있습니다.** 247(자동차보험)과 같은 모양이
되어야 합니다 — `판매처(환자) 100% · invoice_yn = 'N'`.

## 4. CE Admin 설정 — 테스트·운영을 갈라 두었습니다

`billing_strategy` 가 id 이므로 서버마다 다릅니다. 그래서 붙어 있는 곳에 따라 갈라 씁니다.

```php
'withworks_billing_strategy' => [
    'test' => [                    // 데모웍스 — 여섯 다 채웠습니다
        'default' => 133,
        'map' => [
            '10|일반'       => 136,
            '10|차상위경감' => 245,
            '10|기초'       => 249,   // ⚠ 상세 줄이 비어 있다
            '10|산재'       => 250,   // ⚠ 상세 줄이 비어 있다
            '10|자동차보험' => 247,
            '20|'           => 137,
        ],
    ],
    'production' => [              // 위드웍스 — 셋만 받았습니다
        'default' => null,
        'map' => [
            '10|일반'       => null,   // ← id 필요
            '10|차상위경감' => 650,
            '10|기초'       => 651,
            '10|산재'       => null,   // ← id 필요
            '10|자동차보험' => 652,
            '20|'           => null,   // ← id 필요
        ],
    ],
],
```

`default` 도 비워 두었습니다 — 운영의 `전자세금계산서(100%)` id 를 받으면 채우겠습니다. 산재는 이제 그것이 아니라 「산재 현금영수증(100%)」이 됩니다.

## 5. 만들어 주신 세 줄 (기록)

부탁드린 값이고, 데모웍스에서 그대로 들어간 것을 확인했습니다.

| | 전략 | type | 청구 대상 | 비율 | 세금계산서 | 데모웍스 | 위드웍스 |
|---|---|---|---|---:|---|---:|---:|
| ① | 공단 전자세금계산서(100%) | 10 일반 | 168924 국민건강보험공단 | 100 | Y | 245 | 650 |
| ② | ~~지자체 직접청구(0%)~~ → 지자체 기초(100%) | 10 일반 | ⚠ 비어 있음 | — | — | ~~246~~ 249 | 651 |
| ③ | 자동차보험 현금영수증(100%) | 10 일반 | (비움) 판매처 | 100 | N | 247 | 652 |

**② 기초**는 지자체(시군구청) 계정이 마스터에 없어 **청구서를 내지 않는 모양**으로 두었습니다. 지자체 청구와 세금계산서는 CE Admin 이 관할 청구처로 직접 합니다. 나중에 「지자체(시군구청)」 계정을 만드실 생각이 있으시면 알려 주십시오 — 그때는 그 줄을 그 계정 100% · 세금계산서 Y 로 바꾸면 됩니다.

**③ 자동차보험**은 이미 있는 `현금영수증(100%)`(137·운영은 미상)과 값이 같습니다. 그래도 이름을 갈라 둔 것은 청구·정산 목록에서 자동차보험과 처방외를 가릴 수 있어야 하기 때문입니다.

## 곁들여 — 아직 열리지 않은 것 둘

1. **데모웍스에 취소·교환이 아직 배포되지 않았습니다.** `return_store` 에 `return_type: "cancel"` / `"exchange"` 를 보내면 422 로 「처리할 수 없는 반품 구분입니다」가 옵니다. 코드(1504·1506)는 `config/ceadmin.php` 에 들어갔는데 데모웍스 서버에는 아직입니다.
   - 재현: `ce_order_number: ORD-0019` · `so_no: S2608240011` · `items: [{item_code:"33560", qty:1}]`
2. **`config/ceadmin.php` 의 주석이 낡았습니다.** 배열에는 1504·1506 이 들어갔는데 바로 위 주석은 아직 「취소·교환은 아직 유형이 없어 매핑하지 않는다 … 요청이 오면 422 로 거절된다」입니다.

그리고 새로 더해 주신 **`ro.rcpt_completed`** 는 CE Admin 쪽에 붙였습니다. `receiving.received_date` 를 접수 건의 「입고일」로 적고, 접수 단계를 「검수중」으로 옮깁니다. 만들어 주셔서 고맙습니다 — 반품주문 확정만 보고 있었더니 물건이 이미 들어왔는데도 「수거중」에 멈춰 있었습니다.
