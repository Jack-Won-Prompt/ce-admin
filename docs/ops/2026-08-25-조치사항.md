## 배포 절차

### `migrate` 가 필요한 이유 — 16개

돌리지 않으면 이번 주에 만든 것이 대부분 500 으로 떨어진다.

| 마이그레이션 | 안 돌리면 |
|---|---|
| `create_billing_offices` · `add_manager_name_to_billing_offices` | **청구처 정보** 화면이 통째로 뜨지 않는다 |
| `add_billing_office_to_prescriptions` | 주문 등록에서 관할 청구처를 고를 수 없다 |
| `add_deposit_confirm_to_orders` | **담당자 입금 확인**이 500. 정산/회계 목록의 단추가 죽는다 |
| `add_pay_method_to_orders` | **결제 방식** 칸이 죽고, 고르는 순간 500 |
| `add_billing_strategy_to_prescriptions` | **청구전략**을 고를 수 없다 — 자동 발행이 무엇을 낼지 가리지 못한다 |
| `widen_doc_type_on_prescription_attachments` | 거래명세서 첨부가 **저장에서 잘린다**(`doc_type` 이 짧다) |
| `create_common_codes_table` | **공통코드 관리**와 서류 유형 목록이 뜨지 않는다 |
| `add_counsel_order_to_prescriptions` | 상담을 주문에 이을 수 없다 |
| `add_ats_template_code_to_message_templates` | 알림톡 템플릿 코드를 담을 칸이 없다 |
| `move_orders_to_current_so_type` | 옛 판매유형(5001)으로 저장된 주문이 남는다 |
| `add_review_requested_to_prescription_status` | 「검수 요청」 상태를 담지 못해 검수 흐름이 막힌다 |
| 나머지 4개 | 우편번호·사업부 구분·상병 구분 폭·동의 환자 잇기 |

### 배포에 함께 올라가야 하는 것

| 무엇 | 왜 |
|---|---|
| `public/vendor/pdfjs/` (1.4MB) | **문서 칸의 PDF 확대·이동**이 여기 기댄다. 없으면 예전처럼 브라우저 뷰어로 떨어진다(기능은 살아 있다) |
| `storage/fonts/` | 세금계산서·현금영수증·거래명세서 PDF 의 한글. 없으면 글자가 깨진다 |

### 서버 `.env`

| 열쇠 | 값 | 상태 |
|---|---|---|
| `BILLING_AUTO_ISSUE` | `true` | **미확인** — 켜야 입금 확인 시 증빙이 자동으로 나간다. 꺼 두면 거래명세서만 붙는다 |
| `CEADMIN_WEBHOOK_URL` · `CEADMIN_WEBHOOK_SECRET` | — | 위드웍스 쪽에 설정 완료(08-24) |

### `storage` 권한

거래명세서가 `storage/app/public/attachments/` 아래에 쌓인다. 쓰기 권한이 없으면
발행은 되고 첨부만 조용히 빠진다(로그에는 남는다).

## 위드웍스 저장소 배포

`E:\xampp\htdocs\withworks` 쪽도 배포가 필요하다. CE-Admin 만 올리면 **수량이 열 배로
등록되던 것이 그대로다.**

| 무엇 | 왜 필요한가 |
|---|---|
| `qty_unit` (RB → EA) | 낱개로 세어 보낸 수량을 낱개로 받는다. 지금 서버는 박스로 읽어 540 → 5,400 |

| 단가는 `item_prices` 로 | 창고가 가진 값을 쓴다 |
| `/ce-admin/sso` · 판매주문 자동조회 | 판매번호를 눌렀을 때 로그인 없이 그 번호로 열린다 |

## 확인해 둘 것

- **NICE 본인확인** — 운영 키·서버 IP 등록은 끝났다. 배포 뒤 「연결 테스트」를 한 번
  눌러 토큰 발급까지 확인한다.
- **팝빌은 운영이다**(`POPBILL_IS_TEST=false`). 세금계산서·현금영수증 발행과 취소가
  모두 국세청 실신고·실취소다. 시험 발행을 하지 않는다.
- **입금 확인 취소는 증빙까지 취소한다.** 실취소라 되살릴 수 없다.
