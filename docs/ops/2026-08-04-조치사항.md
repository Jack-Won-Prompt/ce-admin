# 개발·운영 조치사항 — 2026-08-04

주간 보고에는 넣지 않는다. 배포·서버 설정처럼 개발과 운영 사이에서 처리하는 일이다.
주간 보고는 무엇이 달라졌는지를 전하는 자리이고, 이 문서는 무엇을 해야 하는지를 담는다.

## ⚠ 위험 1 — 예약 작업이 하나도 돌지 않고 있다

**증상**

운영 로그에 같은 오류가 매분 쌓인다. 하루 1,440건, 로그 파일 약 677KB.

```
[2026-08-04 10:07:02] production.ERROR: There are no commands defined
in the "notification:daily" namespace.
```

**원인**

서버 크론이 `php artisan notification:daily` 를 **직접** 호출한다.
스택 트레이스의 `artisan(16): handleCommand()` 가 근거다 — `schedule:run` 을 거치지 않는다.

그런 명령은 저장소에 없다. `app/Console/Commands/` 에도, `routes/console.php` 에도 없고,
`git log -S` 로 전체 이력을 뒤져도 **한 번도 존재한 적이 없다**. 서버 크론탭에만 있는 항목이다.

**진짜 문제 — 로그가 쌓이는 게 아니라 기능이 멈춰 있다**

`routes/console.php` 에는 예약 작업이 이미 두 개 등록돼 있다.

```php
Schedule::command('cashbill:sync --days=1')->hourly()              // 현금영수증 팝빌 동기화
Schedule::command('cashbill:sync --status')->everyFifteenMinutes() // 국세청 전송상태 갱신
```

크론이 `schedule:run` 을 부르지 않으니 **이 둘이 한 번도 실행되지 않았다**.
로그에 `cashbill` 흔적이 0건이다. **현금영수증 상태가 팝빌·국세청과 동기화되지 않고 있다.**

앞으로 예약 작업을 추가해도 같은 이유로 돌지 않는다.

**조치**

```bash
crontab -e
```

`notification:daily` 줄을 지우고 표준 항목 하나로 바꾼다.

```
* * * * * cd /home/ubuntu/www/lcpoint && php artisan schedule:run >> /dev/null 2>&1
```

재가동은 필요 없다. cron 이 크론탭 수정시각을 보고 다시 읽으며, 다음 분부터 적용된다.

**확인**

```bash
crontab -l
php artisan schedule:list                       # 등록된 작업과 다음 실행 시각
tail -f storage/logs/laravel-$(date +%F).log    # cashbill:sync 가 도는지
```

1시간 안에 로그에 `cashbill:sync` 흔적이 나타나야 정상이다. 지금은 0건이다.

오류가 계속 찍히면 지운 항목이 다른 곳에도 있다. `crontab -e` 는 실행한 계정의 것만 고친다.

```bash
sudo crontab -l
ls -la /etc/cron.d/
grep -rn "notification:daily" /etc/cron* /var/spool/cron 2>/dev/null
```

## ⚠ 위험 2 — 서비스 연동 설정은 마이그레이션 전까지 열리지 않는다

새 화면이 `settings` 테이블을 읽는데, 배포만 하고 마이그레이션을 돌리지 않으면
**설정 › 서비스 연동 설정** 화면이 500 으로 뜬다.

다른 화면은 영향이 없다. 부팅 시 설정을 얹는 코드는 테이블이 없으면 조용히 넘어가고
기존 `.env` 값을 그대로 쓴다.

**배포 절차 — migrate 를 빠뜨리지 말 것**

```bash
cd /home/ubuntu/www/lcpoint
git pull
php artisan migrate        # ← 이번 배포에서 반드시 필요
php artisan view:clear
```

OPcache 를 쓰면 `sudo systemctl reload php8.x-fpm` 까지.

## 확인 — `APP_ENV`

로그가 한때 `local.ERROR` 로 찍혔다. 지금은 `production.ERROR` 로 나오니 정상이나,
운영 서버의 `.env` 가 `APP_ENV=production` 인지 한 번 확인해 둔다.
바꿨다면 `php artisan config:clear` 가 필요하다.

디버그 노출은 없다 — 없는 주소를 요청해도 일반 404 페이지가 나오고 스택 트레이스가 보이지 않는다.
