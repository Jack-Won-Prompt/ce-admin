# 문제와 해결 방안

## P14 · 팝빌이 콜로플라스트 계정이 아니라 개발사 계정에 물려 있다 — 가장 먼저

`coloplast` 를 등록했는데도 SMS 가 계속 막히길래 사업자번호부터 맞춰 봤다. 팝빌 콘솔은
**콜로플라스트 코리아 주식회사 [101-86-34660]** 인데, `.env` 의
`POPBILL_TEST_CORP_NUM` 은 **4908601851** 이다. 서로 다른 회사다.

| | **1018634660** (콜로플라스트) | **4908601851** (`.env` 현재값) |
|---|---|---|
| 테스트베드 가입 | **미가입** | 가입 |
| 운영 가입 | 가입 | 가입 |
| 담당자 | **`coloplast`** | `linkthelab` |
| 운영 잔액(문자·현금영수증·팩스) | 각 **9,990P** | 각 **0P** |
| 세금계산서 인증서 만료 | 2027-06-26 (유효) | 2027-08-21 (운영) / 테스트베드는 폐기 |
| 발신번호 | 1588-7866 — **반려**(2026-08-12 신청) | 070-7537-3329 승인 |

이것이 P2 의 진짜 원인이다. `coloplast` 는 **1018634660 의 담당자**인데, 앱은 그 아이디를
**4908601851 로** 보내니 "회원의 아이디가 아닙니다" 가 나온다. 계정과 담당자가 섞여 있었다.

파장이 크다.

- **운영으로 돌리면 아무것도 못 보낸다.** 4908601851 의 운영 잔액이 문자·현금영수증·팩스
  모두 0P 다.
- **시연에서 발행한 현금영수증 10건은 개발사 사업자번호(4908601851) 가맹점 명의로 나갔다.**
  팝빌 테스트 환경이라 국세청 신고는 일어나지 않았지만, 이대로 운영 전환하면 **콜로플라스트가
  아닌 명의로 현금영수증·세금계산서가 발행된다.**

**해결 방안.**

```dotenv
POPBILL_IS_TEST=false            # 1018634660 은 테스트베드에 없다
POPBILL_TEST_CORP_NUM=1018634660
POPBILL_TEST_USER_ID=coloplast
POPBILL_TEST_SENDER_NUM=<승인된 발신번호>
```

### 2026-08-13 — 사업자번호만 바꿨을 때

`POPBILL_TEST_CORP_NUM=1018634660` 으로 고치고 `POPBILL_IS_TEST=true` 를 그대로 두니
**전 서비스가 막혔다.**

```
문자 · 현금영수증 · 팩스 잔액 조회
→ [-99003008] 연동회원으로 가입된 사업자 번호가 존재하지 않습니다. [POPBILL_TEST]
```

콜로플라스트 계정은 **운영에만** 있다. 사업자번호와 `IS_TEST` 는 함께 움직여야 한다.

운영(`IS_TEST=false`)으로 돌렸을 때 1018634660 이 실제로 할 수 있는 것은 이렇다.

| 서비스 | 상태 |
|---|---|
| 문자 | **불가** — 발신번호 1588-7866 이 반려, 승인된 번호가 하나도 없다 |
| 팩스 | 가능 — 승인된 발신번호는 **02-722-6002** (1588-7866 이 아니다) |
| 현금영수증 | 가능 · 잔액 9,990P — 단 **국세청에 실제 발행된다** |
| 세금계산서 | 인증서 유효(2027-06-26) — 단 **국세청에 실제 발행된다** |

`.env` 의 `POPBILL_TEST_SENDER_NUM` 하나를 문자와 팩스가 같이 쓰는 것도 문제다. 이 계정에서
문자 승인번호와 팩스 승인번호가 다르므로 **키를 나눠야 한다**
(`POPBILL_SMS_SENDER_NUM` / `POPBILL_FAX_SENDER_NUM`).

다만 그 전에 두 가지가 먼저다.

1. **발신번호.** 1018634660 계정에 등록된 번호는 1588-7866 하나이고 **반려 상태**다
   (팝빌 `state=5`, 콘솔 목록에서도 '반려'). 승인된 발신번호가 하나도 없어 문자가 나가지
   않는다. 콘솔 '보기'에서 반려 사유를 확인하고 다시 신청해야 한다. → P6
2. **테스트 환경.** `POPBILL_IS_TEST=false` 로 두면 세금계산서가 **국세청에 실제 발행**된다.
   시연·검증을 계속하려면 팝빌 테스트베드에 1018634660 을 연동회원으로 가입시켜, 개발은
   테스트베드·운영은 운영으로 나눠 써야 한다.

`.env` 키 이름이 `POPBILL_TEST_*` 인데 운영 값을 담게 되는 것도 헷갈린다. 옮길 때
`POPBILL_CORP_NUM` / `POPBILL_USER_ID` / `POPBILL_SENDER_NUM` 으로 바꾸는 편이 낫다.

## P1 · 세금계산서를 환자 주민번호로 발행할 수 없다 — 심각

시연에서 10건 모두 실패했다.

```
POST /orders/{id}/tax-invoice
→ 500  발행 실패: [-11001021] 공급받는자 사업자 번호가 유효하지 않습니다.
```

**원인.** `OrderController@issueTaxInvoice` 는 공급받는자를 사업자로 못 박는다.

```php
// app/Http/Controllers/OrderController.php:379-380
$inv->invoiceeType    = '사업자';
$inv->invoiceeCorpNum = preg_replace('/\D/', '', $data['tax_invoice_biz_no']);
```

주민번호를 `tax_invoice_biz_no` 에 넣으면 하이픈만 지워져 13자리가 사업자번호 자리로
들어가고, 팝빌이 자릿수에서 거절한다. 개인(주민번호) 분기가 이 컨트롤러에 아예 없다.

### 2026-08-13 — 고쳤고, 운영 계정에서 실제로 발행해 확인했다

```
POST /orders/{id}/tax-invoice   (invoicee=개인, 번호 비움 → 처방전 주민번호 사용)
→ 200  세금계산서가 발행되었습니다.
   문서번호 TI20260813000010 · 국세청승인번호 202608134100020300000e92 · stateCode 300(발행완료)
   공급자   콜로플라스트 코리아 주식회사
   공급받는자 정하준 / 주민등록번호
   orders.tax_invoice_biz_no 저장값 = 130218-3******   ← 평문이 아니라 마스킹
```

고친 곳은 세 군데다.

1. `config/rrn.php` — 복호화 사유 `tax_invoice` 추가(부가가치세법 시행령 §68).
2. `OrderController@issueTaxInvoice` — `tax_invoice_invoicee`(사업자/개인)를 받아
   `invoiceeType` 에 그대로 넘기고, 개인 13자리·사업자 10자리를 팝빌에 가기 전에 거른다.
   **개인인데 번호를 비워 보내면 서버가 처방전의 주민번호를 열어 쓴다** — 번호를 화면으로
   내려보내지 않고, 복호화에는 감사로그가 남는다. 저장할 때는 마스킹한다.
3. `prescriptions/order.blade.php` — 세금계산서 팝오버에 '공급받는자 구분' 을 두되
   **이 화면은 환자가 사 간 건이라 '개인' 이 기본**이다. 개인을 고르면 상호·대표자에
   환자명이 채워지고 번호 칸은 비워 두면 된다. 사업자는 대리점·병원이 사가는 예외에만 쓴다.

### 발행된 세금계산서를 이미지로 남기고 공단 팩스에 싣는다

공단에 보내는 팩스 합본은 dompdf 로 만드는데, **dompdf 는 외부 PDF 를 페이지로 끼워 넣지
못한다**(첨부 PDF 가 합본에서 빠지는 것과 같은 이유다). 그래서 세금계산서를 **장표 이미지**로
남긴다. 이러면 처방전 사진·신분증과 똑같은 방법으로 한 장씩 실린다. 팝빌 팩스도 이미지를 받는다.

이 서버에는 Imagick 도 Ghostscript 도 없어 PDF→이미지 변환을 쓸 수 없다. `app/Support/TaxInvoiceImage.php`
가 GD 와 `storage/fonts/NanumGothic.ttf` 로 장표를 직접 그린다 — 승인번호·작성일자·공급자
(등록번호·상호·대표자·주소·업태/종목)·공급받는자(구분·번호·성명·대표자)·금액·품목.

- 저장 위치 `storage/app/tax_invoices/{order_id}/세금계산서_{성명}_{주문번호}.png` (PDF 와 같은 폴더)
- `prescription_documents` 에 서류로 등록 → 검수 화면 '생성 서류' 와 서류 관리에서 바로 보인다
- `TaxInvoiceImage::ensure()` 한 곳으로 모았다. 발행 직후·팩스 합본·팝빌 전송 세 군데가 모두
  이 함수를 부르므로, **이미지가 없던 옛 발행 건도 팩스를 보내는 순간 되살아난다**

팩스 쪽은 네 곳을 고쳤다.

- `sendFax` 검증에 `tax_invoice` 추가
- `collectFaxFiles` 에 `case 'tax_invoice'` — 팝빌로 보내는 파일 목록에 장표 PNG 를 넣는다
- `saveFaxPdf` → `fax-pdf.blade.php` 에 ⑤ 세금계산서 페이지 추가(페이지 구분도 함께 조정)
- 검수 화면 팩스 팝오버에 '세금계산서' 항목 추가 — 미발행이면 잠기고, 발행하면 그 자리에서 열린다

**확인.** 같은 처방전으로 포함/미포함을 만들어 비교했다.

```
세금계산서 미포함  2,785,096B  페이지 5 · 이미지 4
세금계산서 포함    2,851,696B  페이지 6 · 이미지 5
```

팝빌로 나간 파일 목록에도 들어갔다.

```
auth_RX-20260813-004.html, cashreceipt_RX-20260813-004.html,
세금계산서_정하준_ORD-0009.png, 20260813_112142_….png, 20260813_112142_….png
```

아래는 그때 적어 둔 원안이다.

**해결 방안.** 팝빌은 `invoiceeType` 에 `개인` 을 받는다. 화면에 구분을 두고 서버에서
갈라 준다.

```php
$data = $request->validate([
    'tax_invoice_type'      => 'required|in:electronic,manual',
    'tax_invoice_invoicee'  => 'nullable|in:사업자,개인,외국인',   // ← 추가
    'tax_invoice_biz_name'  => 'required|string|max:100',
    ...
]);

$type = $data['tax_invoice_invoicee'] ?? '사업자';
$num  = preg_replace('/\D/', '', $data['tax_invoice_biz_no']);

// 개인은 주민번호 13자리, 사업자는 10자리다. 여기서 걸러야 팝빌까지 안 간다.
if ($type === '개인' && strlen($num) !== 13) {
    return response()->json(['success' => false, 'message' => '주민등록번호 13자리를 입력해 주세요.'], 422);
}
if ($type === '사업자' && strlen($num) !== 10) {
    return response()->json(['success' => false, 'message' => '사업자번호 10자리를 입력해 주세요.'], 422);
}

$inv->invoiceeType    = $type;
$inv->invoiceeCorpNum = $num;
```

화면(`prescriptions/order.blade.php` 세금계산서 팝오버)에는 `사업자 / 개인` 선택을 두고
`개인` 이면 라벨을 `주민등록번호` 로 바꾸고 환자 주민번호를 기본값으로 채운다.

> 참고: `POST /api/popbill/taxinvoice/regist-issue` 에는 이미 `invoicee_type` 입력이 있다
> (`Popbill/TaxinvoiceController.php:305-306`). 다만 검증이 전혀 없고 주문과 묶이지 않아
> `orders` 표에 아무것도 남기지 않는다 — 이 경로를 쓰는 것은 답이 아니다.

## P2 · 팝빌 회원 아이디가 등록돼 있지 않아 SMS·세금계산서가 전부 막힌다 — 심각

시연 첫 시도에서 위임동의 SMS·안내 SMS·세금계산서가 모두 이렇게 떨어졌다.

```
[-10000038] 회원의 아이디가 아닙니다.
```

**원인.** `POPBILL_TEST_USER_ID=coloplast` 인데 이 아이디는 팝빌에 등록된 회원 아이디가
아니다. 그런데 서비스마다 이 값이 가는 자리가 다르다.

| 호출 | SDK 시그니처 | `coloplast` 가 들어가는 자리 | 결과 |
|---|---|---|---|
| SMS `SendXMS` | `(…, $UserID, …)` | **UserID** | ✗ `-10000038` |
| SMS `SendSMS` | `(…, $UserID)` | UserID | 통과 (이 API 는 검증하지 않는다) |
| 세금계산서 `RegistIssue` | `($CorpNum, $Taxinvoice, $UserID, …)` | **UserID** | ✗ `-10000038` |
| 현금영수증 `RegistIssue` | `($CorpNum, $Cashbill, $Memo, $UserID, …)` | **Memo** | 통과하지만 **메모에 `coloplast` 가 찍힌다** |

앱의 SMS 발송 경로(`MessageService::send()`)는 `SendXMS` 를 쓰므로,
`POPBILL_SMS_SIMULATE=false` 인 운영에서는 **문자가 한 통도 나가지 않는다.**
현금영수증은 인자 자리가 어긋나 회원 아이디가 메모 칸에 들어간다.

**확인.** 발신번호를 등록된 번호로 두고 세 가지를 직접 쏴 봤다.

```
sendXms(userId: 'coloplast') → ERR [-10000038] 회원의 아이디가 아닙니다.
sendXms(userId: null)        → OK  접수번호 026081310000000988
sendXms(userId: '')          → OK  접수번호 026081310000001043
```

### 2026-08-13 추가 확인 — 등록했는데도 그대로다

`coloplast` 를 연동 회원으로 등록한 뒤 다시 쐈지만 결과는 같았다.

```
SendXMS(userId='coloplast')  → ERR [-10000038] 회원의 아이디가 아닙니다.
SendXMS(userId='linkthelab') → OK  접수번호 026081312000000885
```

팝빌에 직접 물어보니 이유가 나온다.

| | 가입 여부(4908601851) | `coloplast` | 담당자 목록 |
|---|---|---|---|
| **테스트베드** | 가입 | 사용중이 아님 | `linkthelab`(최연아) |
| **운영** | 가입 | 사용중 | `linkthelab`(최연아) |

되어 있어 테스트베드에서는 여전히 없는 아이디다.

한 가지 더 짚어야 한다. 운영에서도 `coloplast` 는 "사용중"으로 나오지만 **담당자 목록에는

### 진짜 원인은 계정이 섞인 것이다 → P14

`coloplast` 는 **콜로플라스트 계정(1018634660)의 담당자**이고, 앱은 그 아이디를

## P4 · 주문에서 발행한 현금영수증이 현금영수증 화면 목록에 나오지 않는다

## P5 · 위임장·동의서 PDF 생성이 메모리 128MB 를 넘는다

조용히 두지 말고 화면에 알린다.

```php
return response()->json([
```

문제는 화면이다. 팩스 화면에서 **'대기건 동기화'를 누르기 전까지는 실패한 건도 접수 상태로

```php
SyncFaxResult::dispatch($history->id)->delay(now()->addMinutes(3));
```

큐를 쓰지 않는다면 스케줄러에 `fax:sync-pending` 을 5분 주기로 걸고, 실패 건은 처방전
검수 화면 상단 팩스 버튼에 빨간 배지로 세운다.

## P13 · 전자세금계산서용 인증서가 폐기 상태다 — 심각

담당자 아이디를 `linkthelab` 으로 바꿔 P2 를 넘긴 뒤, **사업자번호**(주민번호가 아니라)로

**P1 을 고쳐도 발행되지 않는다** — 인증서가 먼저다.

전자세금계산서는 국세청 전송에 공동인증서(전자세금계산서용)가 필요하고, 그 인증서를 팝빌에
등록해 둔다. 현금영수증·팩스·문자는 인증서를 쓰지 않아 시연에서 모두 통과했다.

주의할 점이 있다. 만료일만 보면 멀쩡해 보인다.

```
GetCertificateExpireDate(4908601851)  →  20260821235959
```

**만료 전인데 폐기된 상태다.** 만료일 확인만으로는 이 장애를 못 잡는다. 게다가 그 만료일도
8일 뒤(2026-08-21)라, 폐기가 아니었더라도 곧 다시 등록해야 한다.

**해결 방안.** 팝빌 테스트베드 콘솔에서 사업자번호 4908601851 계정의 전자세금계산서용
인증서를 새로 등록한다. 운영 전환 시에는 운영 계정에도 유효한 인증서가 있어야 한다.
만료일은 `PopbillTaxinvoice::GetCertificateExpireDate($corpNum)` 로 볼 수 있지만, 폐기
여부는 실제로 발행을 시도해 봐야 안다.

# 작업 중 사고와 조치

시연 첫 시도에서 **기존 처방전 1건(`RX-20260811-003`, 한여름)을 덮어썼다.**
`GET /prescriptions/create` 가 빈 초안을 재사용하는데(P11), 스크립트가 리다이렉트 주소를
읽지 않고 `latest('id')` 로 처방전을 잡아 엉뚱한 건을 집었다.

**조치.** 활동로그로 원래 값을 확인해 되돌렸다.

- 이 건에 붙은 첨부 2건·제품 2줄·서류 4건·팩스 이력 1건·주문 ORD-0006 삭제
- 잘못 만들어진 환자 1명 삭제
- 처방전 32개 필드를 원래대로(이름 `한여름`, 번호 `01032790790`, 상태 `pending`) 복구
- **한여름 님의 위임동의 서명(동의 #32)은 손대지 않았고 그대로 남아 있다** — 위임장 서명
  화면에서 확인했다

회수하지 못한 것: 팝빌 테스트 환경에 발행된 현금영수증 1건(`TB0000077`)과 팩스 접수 1건.
테스트 환경이라 국세청 신고나 실제 발송은 일어나지 않았다.

**재발 방지.** 스크립트를 리다이렉트 `Location` 에서 처방번호를 읽도록 고쳤다. 근본적으로는
P11 을 고쳐야 한다.
