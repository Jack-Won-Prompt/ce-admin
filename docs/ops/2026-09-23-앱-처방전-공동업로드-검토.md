# 검토 — 앱에서 남이 올린 처방전에 서류를 보태기 (2026-09-23)

## 1. 요청

> 처방전 목록 위에 **이름ㆍ생년월일**로 찾는 칸을 두고, **내가 올린 건이 아니어도**
> 골라서 서류를 보탤 수 있게. (오늘 A 가 처방전을 올리고, 내일 B 가 등록신청서를 보탬)

---

## 2. 지금은 이렇게 되어 있다

| 자리 | 지금 |
|---|---|
| 앱 목록 | **내가 올린 것만** — API 가 `created_by = 로그인한 사람` 으로 걸러 낸다 (`PrescriptionApiController::index`) |
| 목록 검색 | 환자 **이름**만. 생년월일 칸은 없다 |
| 서류 보태기ㆍ지우기 | **올린 사람 본인**만, 그리고 **검수 완료 전**에만 (`Prescription::editableByUploader`) |
| 아니면 | 「본인이 업로드한 처방전만 수정할 수 있습니다.」로 막는다(403) |

**이미 갖춰진 것도 있다.**

- 서류마다 **누가 올렸는지**(`prescription_attachments.uploaded_by`) 적어 둔다.
- 웹 파일 검수 창은 서류마다 올린 사람 이름을 딱지로 보여 준다.
- 「다시 올리기 요청」 알림은 **그 서류를 올린 사람**에게 간다. 없으면 건을 만든 사람에게 간다
  (`ReuploadRequestService:111`). 한 건에 여러 사람이 붙는 앞날을 이미 셈해 둔 자리다.

즉 **자료 구조는 준비되어 있고, 막고 있는 것은 목록 조건과 권한 한 줄**이다.

### 운영 자료 (2026-09-23 서버)

- 환자 73명 중 **생년월일이 있는 사람 68명(93%)** — 이름+생년월일로 찾는 길이 쓸 만하다.
- 처방전 112건, 앱ㆍ웹 통틀어 올린 사람 **5명**.
- 한 건에 서류를 올린 사람이 둘 이상인 건 **0건** — 아직 그렇게 쓰지 못했기 때문이다.

---

## 3. 손대야 할 곳 (세 겹)

### 가) 찾기 — 서버

지금 목록 API 를 그대로 열면 앱을 쓰는 사람 누구나 **전체 환자 목록을 훑을 수 있게** 된다.
그래서 목록을 여는 대신 **찾기 API 를 따로 두기**를 권한다.

```
GET /api/prescriptions/lookup?name=홍길동&birth=1990-01-01
  → 이름과 생년월일이 **둘 다** 맞는 건만 내준다 (최근 것부터 몇 건)
```

- 이름만으로는 내주지 않는다 → 환자 이름을 긁어 모으는 일이 막힌다.
- 검수 완료 전(`UPLOADER_EDITABLE_STATUSES`)인 건만 내준다 → 이미 확정된 건은 애초에 안 보인다.
- 누가 남의 건을 찾아봤는지 **이력에 남긴다**(`user_activity_logs`).

### 나) 권한 — 서버

`editableByUploader()` 한 가지를 **둘로 가른다.**

| 할 일 | 지금 | 바꾼 뒤 |
|---|---|---|
| 서류 **보태기** | 올린 사람만 | **앱에 들어올 수 있는 사람 누구나** (검수 완료 전) |
| 서류 **지우기** | 올린 사람만 | **그 서류를 올린 사람만** (내가 보탠 것만 지운다) |
| 처방전 그림 갈아 끼우기 | 올린 사람만 | 그대로 — 건의 주인만 |
| 검수 재요청 | 올린 사람만 | 정해야 함 (아래 4-③) |

### 다) 화면 — 앱

- 목록 위에 **이름ㆍ생년월일** 칸과 「찾기」.
- 찾은 결과에 **「내 건 / 남의 건」**을 구분해 보인다. 남의 건에는 올린 사람 이름을 적는다.
- 상세에서 남의 건이면 **「서류 추가」만** 열고 🗑(삭제)는 내가 올린 서류에만 보인다.

## 4. 정해 주셔야 할 것

1. **누구까지 남의 건에 손댈 수 있나** — 앱에 들어오는 사람 전부입니까, 아니면 같은 팀ㆍ같은 거래처끼리입니까?
   지금 앱으로 올리는 사람은 5명이라 전부 열어도 크게 어지럽지 않습니다.
2. **찾는 방법** — 이름만으로 목록이 나오게 할지, **이름+생년월일이 둘 다 맞아야** 한 건이 나오게 할지.
   개인정보 쪽으로는 뒤엣것이 훨씬 안전합니다(권장).
3. **남의 건에서 검수 재요청까지 되게 할지** — 서류만 보태고 재요청은 원래 올린 사람이 하게 할 수도 있습니다.
4. **알림** — 남이 내 건에 서류를 보태면 나에게 알릴지. (보태는 일이 잦아지면 알림도 잦아집니다)

---

## 5. 개인정보ㆍ안전에서 짚어 둘 것

- 앱 목록에는 **환자 이름ㆍ병원ㆍ상병**이 보입니다. 지금은 자기 것만이라 노출이 좁습니다.
  이 문을 열면 **앱 사용자 = 전체 환자 조회 가능**이 되므로, 4-② 를 「둘 다 일치」로 잡아
  **아는 사람을 확인하러 오는 길**로만 두는 편이 낫습니다.
- 남의 건을 연 자취를 남겨야 합니다. 나중에 「누가 왜 봤나」를 물을 때 댈 것이 있어야 합니다.
- 서류를 **지우는 것**은 열지 않기를 권합니다. 남이 올린 자료가 말없이 사라지면 검수자가 무엇을
  보고 승인했는지 알 수 없게 됩니다.

## 6. 일감 크기 (어림)

| | 할 일 | 시간 |
|---|---|---|
| 서버 | 찾기 API 1개, 권한 규칙 가르기, 조회 이력 남기기 | 반나절 |
| 앱 | 목록 위 찾기 칸ㆍ결과 화면, 상세에서 남의 건 분기 | 반나절 ~ 하루 |
| 시험 | 계정 둘로 오가며 (A 가 올리고 B 가 보태기) | 2~3시간 |

---

## 7. 권하는 모양

> 목록 위 **「이름 + 생년월일로 찾기」** → 둘 다 맞는 건만 한 장 카드로 → **서류 추가만** 열기
> (지우기는 내가 올린 것만) → 보태면 **원래 올린 사람과 검수자에게 알림** → 이력에 남김.
> 검수 완료된 건은 찾기 결과에 아예 나오지 않음.

이대로면 「어제 A 가 올린 건에 오늘 B 가 등록신청서를 보탠다」가 되고, 노출은 지금보다
거의 넓어지지 않습니다.
