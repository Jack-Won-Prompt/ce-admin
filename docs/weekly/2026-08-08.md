## 1. 요약

이번 기간은 **위임동의·전자서명 업무**를 한 화면으로 모으는 데 집중했습니다.

함께 **처방전 검수 화면**을 Figma 시안 구조로 다시 세웠고, 주민등록번호를
**쓰기 전용**으로 바꿔 화면에서 다시 읽을 수 없게 했습니다.

## 2. 개발 — 적용한 업무

### 2.1 위임장 서명 관리 — 신규 화면

**서류ㆍ동의 › 위임장 서명**

위임동의 서명은 처방전 검수 화면 안에만 있었습니다. 누가 언제 서명했는지 훑어보거나
서류를 모아 받으려면 처방전을 하나씩 열어야 했습니다.

담긴 기능

| 구분 | 내용 |
|---|---|
| 목록 | 상태 · 서명자 · 전화번호 · 처방번호 · 서명일시 · 본인확인 · 요청일시 |
| 상태 구분 | 동의 완료 / 대기 중 / 거절 / 만료 — 건수와 함께 탭으로 |
| 검색 | 이름 · 전화번호 · 처방번호 (하이픈 있든 없든 찾음) |
| 기간 | 서명일 기준. 아직 서명 전인 건은 요청일로 검색됨 |
| 서류 받기 | 행마다 **서명 PNG · 위임동의서 PDF · 요양비 위임장 PDF** |
| 재발송 | 행마다 위임동의 SMS 다시 보내기 |
| 신규 발송 | 이름과 전화번호만 넣고 바로 보내기 |

받을 수 없는 서류는 눌리지 않게 두고 **왜 없는지**를 알려줍니다 — 동의 완료 건이
아니거나, 서명이 없거나, 서류가 아직 만들어지지 않은 경우입니다.

행을 더블클릭하면 해당 처방전이 새 탭으로 열립니다.

> **신규 발송은 처방전을 한 건 만듭니다.** 위임동의는 처방전에 매달리는 구조라
> 동의만 따로 만들 수 없습니다. 입력한 이름·번호로 처방전을 만들고 그 위에 동의를 겁니다.
> 나중에 그 처방전을 열어 나머지를 채우면 됩니다. 문자 발송이 실패하면 만들어진
> 처방전도 함께 지워지므로 빈 껍데기가 쌓이지 않습니다.

### 2.2 위임동의 발송 — 이름을 고쳐 보낼 수 있음

기존에는 환자명이 읽기 전용이라, OCR이 이름을 잘못 읽었거나 비어 있으면 **그대로**
문자가 나갔습니다.

환자명 칸을 열었습니다. 보낸 이름은 SMS 문구 · 환자가 여는 서명 페이지 ·
위임동의서 PDF까지 그대로 이어집니다. 비워 두면 처방전에 적힌 이름을 씁니다.

수신 번호는 자릿수를 확인해, 오타로 동의 건이 생기고 문자가 나가는 것을 막습니다.

---

### 2.3 서명 이미지 내려받기 — 신규

서명은 데이터로만 보관돼 파일로 꺼낼 방법이 없었습니다. 서류 첨부나 대조에 쓸 수 있도록
**서명 PNG 다운로드**를 추가했습니다. 처방전 검수 화면의 서명 확인 창과 위임장 서명
목록 양쪽에 있습니다.

서명도 개인정보이므로 **누가 언제 받아 갔는지 기록**됩니다.

---

### 2.4 개인정보 보호

#### 주민등록번호 — 읽기 제거, 쓰기만

지난 기간에 암호화·마스킹·감사 로그를 붙였고, 담당자가 '표시'를 누르면 원문을
복호화해 볼 수 있었습니다. 이번에 **읽는 경로 자체를 없앴습니다.**

- 화면의 '표시' 버튼과 복호화 요청 제거
- 서버의 조회 경로 삭제 — 주소를 직접 입력해도 읽을 수 없음
- 입력은 언제나 가능. 저장된 번호는 **마스킹으로만** 표시됨
- 비운 채 저장하면 기존 값이 유지됨 (실수로 지워지지 않음)

읽을 방법이 없으면 복호화가 일어날 일도 없습니다.

#### 처방전 이미지·첨부 파일 접근 통제

처방전 이미지와 첨부 파일이 **웹 주소만 알면 로그인 없이 열리던** 상태였습니다.
로그인과 권한 확인을 거친 뒤에만 열리도록 바꿨습니다.

---

### 2.5 처방전 검수 화면 — 시안 구조로 재정비

Figma 시안과 화면 구조가 어긋나 있어, 겉모습이 아니라 **무엇이 어디에 놓이는지**를
맞췄습니다.

| 항목 | 내용 |
|---|---|
| 아코디언 | 6개 → **3개**로 병합 (시안 구성) |
| 신규 입력 항목 | **14개** — 전화번호2 · Email · 건보 등록일/재등록 기한 · 기초(의료급여) 재평가 대상자/기한 · 판매 거래처 유형 · 결제일 · 구입일 · 인마켓 마감일 · 마지막 확정 수량 · 하루 사용 수량 |
| 배치 | 모든 항목을 2열로 |
| 처방전 뷰어 | 화면을 스크롤해도 **항상 제자리에 고정** — 오른쪽을 채우는 동안 처방전이 계속 보임 |
| 항목 이름 가림 | 이름이 길면 입력칸을 덮던 것을 두 줄로 |
| 주민등록번호 | 입력이 막혀 있던 것을 입력 가능하게 |
| 재구매일 | 글자만 있고 칸이 없어 보이던 것을 입력칸으로 |
| 등록자 카드 | **누가 마지막으로 수정했는지** 표시 |

#### 처방자료 업로드 화면

파일 선택을 **문서 구분별 영역**으로 나눠, 어떤 서류를 어디에 올리는지 화면에서
바로 보이게 했습니다.

#### 전 화면 공통

화면 탭바를 시안에 맞추고, 탭에서 아이콘을 뺐습니다. 환자 정보 줄을 두 줄에서
한 줄로 줄여 본문 영역을 넓혔습니다.

## 3. 확인·결정이 필요한 사항

| 구분 | 내용 |
|---|---|
| **권한 설정** | 신규 화면 **위임장 서명**을 권한 그룹에 체크해야 담당자에게 보입니다. 목록 조회(`조회`)와 위임동의 발송(`발송`) 두 가지를 따로 줄 수 있습니다. 체크 전까지는 관리자 계정에만 보입니다 |
| **정책 확인** | 서류(서명 PNG·PDF 2종)는 **그 처방전의 가장 최근 동의 건**으로 발행됩니다. 재발송으로 동의가 여러 건 쌓여도 최신 것이 나옵니다. 이 기준이 맞는지 확인 부탁드립니다 |
| 기능 미동작 *(이어짐)* | 위임동의 링크의 **휴대폰 본인확인**이 꺼져 있습니다. NICE 자격증명(클라이언트 ID·상품 ID) 발급이 필요합니다. 발급 전까지는 기존 서명 흐름으로 동작합니다 |
| 데이터 오류 *(이어짐)* | 회사 정보의 **상호** 자리에 사업자번호가 들어 있어 세금계산서에 상호가 잘못 나갑니다 |
| 정책 결정 *(이어짐)* | 디자인 시스템에 **의미 색상**(성공·경고·오류)이 정의돼 있지 않습니다. 확장 요청서 회신 대기 |
