## 1. 요약

**창고(위드웍스)와 주고받는 일이 주문 하나에서 되돌림·샘플까지 넓어졌습니다.**
지금까지는 주문을 넘기는 것만 되고, 교환·반품·취소는 CE-Admin 안에서만 돌아
창고는 물건이 돌아온다는 것을 몰랐습니다. 이제 접수하면 창고에 반품 주문이 서고,
창고에서 상태가 바뀌면 담당자 화면에 알림이 뜹니다.

**공단 청구는 화면에서 옮겨 적는 일을 돕는 자리가 생겼습니다.** 요양비 청구(2221)와
위임 등록(2225)을 공단 서식과 같은 구조로 그려, 보고 치는 대신 화면에서 값을 확인해
넣습니다. 청구를 팩스로 보내던 길은 걷어냈습니다 — 공단은 사이트 입력이 원칙이고,
팩스는 환자 등록·재등록 전용으로 되돌렸습니다.

**제품 검색이 멈추던 원인을 잡았습니다.** 「제품 API 서버에 연결할 수 없습니다」는
창고 장애가 아니라 우리 화면이 재고를 한꺼번에 물어 창고를 막던 것이었습니다.

**결제전송을 새로 만들었습니다.** 카드·가상계좌·무통장입금 중에 골라 환자에게
보내고, 보낸 것과 낸 것이 한자리에 쌓입니다. 지금까지는 가상계좌 하나뿐이라
카드로 내겠다는 사람에게 줄 것이 없었습니다.

## 2. 개발 — 적용한 업무

### 2.1 창고 연동 — 되돌림과 샘플까지

되돌아온 물건이 창고에 알려지지 않아, 담당자가 전화로 따로 알리고 있었습니다.

| 무엇이 가능해졌나 | 지금 상태 |
|---|---|
| **교환·반품·취소 접수** | 접수하면 창고에 반품 주문이 섭니다. 종류마다 창고가 하는 일이 달라 코드를 따로 둡니다 |
| **출고 전 취소** | 반품 주문을 세우지 않고 원 판매주문을 취소합니다. 우리 주문도 함께 닫힙니다 |
| **CE 샘플주문** | 화면을 새로 만들었습니다. 처방 없이 나가는 건이라 판매와 갈라 둡니다. 거래처는 고객(환자)입니다 |
| **물류 상태 받기** | 출고·배송·취소·반품 사건을 받아 상태를 옮기고, 보고 있는 사람 화면에 알림이 뜹니다 |
| **연동 값 관리** | API 주소·토큰·판매유형을 화면(설정 › 서비스 연동)에서 고칩니다. 그전에는 서버 파일을 고쳐야 했습니다 |

배송지도 바로잡았습니다. 창고에 등록되던 배송지가 중개 거래처 앞으로 잡혀 있었는데,
**환자 주소**로 돌렸습니다. 상세주소가 두 번 붙던 것도 함께 고쳤습니다.

### 2.2 공단 청구

공단 사이트에 값을 옮겨 적을 때 어느 칸에 무엇이 들어가는지 매번 서식을 봐야 했습니다.

- **요양비 청구(2221)·위임 등록(2225)** — 공단 서식과 같은 구조로 화면을 그려,
  주문에 있는 값을 그 자리에 채워 보여 줍니다.
- **신환·구환** — 처음 청구하는 사람과 이어 청구하는 사람은 낼 서류가 다릅니다.
  청구 서류를 둘로 갈라 보여 줍니다.
- **청구 준비 여부** — 배송이 끝나야 청구할 수 있으므로, 준비된 건과 아닌 건을
  미리 갈라 둡니다. 시작점을 배송완료에서 **출고완료**로 옮겼습니다.
- **팩스** — 청구를 팩스로 보내던 경로를 걷어내고 환자 등록·재등록 전용으로
  되돌렸습니다. 보낸 결과는 스스로 받아 적습니다.

### 2.3 판매유형 코드 개편 대응

창고 쪽에서 판매유형 코드를 바꿨습니다(08-18). 5000·6000번대가 **지워지고**
1500·1600번대가 그 자리를 받았습니다.

| 구분 | 옛 코드 | 새 코드 |
|---|---|---|
| 판매 | 5001 | **1501** |
| 반품 | 5005 | **1505** (샘플 반품 1605) |
| 샘플 | 6001 | **1601** |
| 취소 · 교환 | 5004 · 5006 | **없음** — 창고에 유형이 없습니다 |

우리 설정은 지워진 코드를 그대로 들고 있어 새 주문이 서지 않을 상태였습니다.
새 코드로 바꾸고, 앞으로 창고가 코드를 바꿔도 **화면에서 적어 넣으면 되도록**
고쳤습니다. 코드를 프로그램에 박아 두면 바뀔 때마다 배포해야 하고, 그 사이에는
지워진 코드로 주문이 나갑니다.

### 2.4 제품 검색 속도

「제품 API 서버에 연결할 수 없습니다」로 검색이 멈추는 일이 있었습니다.
창고 장애가 아니라 **우리 화면이 창고를 막고 있었습니다** — 창고의 재고 조회는
한 건에 7초인데, 검색 결과 열 건이면 열 번을 한꺼번에 물었습니다.

| 무엇 | 전 | 후 |
|---|---|---|
| 제품 검색 「Cath」 | 10초 뒤 실패 | **0.23초** · 10건만 오던 것이 **57건 전부** |
| 재고 조회 1건 | 6.7초 | **0.15초** |

재고는 목록에서 묻지 않고 제품을 고른 뒤 그 한 건만 묻습니다. 창고 쪽에는
CE 전용 조회를 새로 두어, 나눠 오던 결과가 한 번에 옵니다.

### 2.5 결제전송 *(신규 기능)*

주문 등록 화면 위쪽에 **결제전송**을 두었습니다.

1. 카드결제 · 가상계좌 · 무통장입금 중 하나를 고르고 보냅니다.
2. 환자에게 문자가 갑니다 — 알림톡을 먼저 쓰고 막히면 문자로 잇습니다.
3. 환자는 받은 주소에서 결제합니다. 카드 정보는 우리 서버를 지나지 않습니다.
4. 보낸 것과 낸 것이 그 자리 이력에 쌓입니다. 다시 보낼지 전화할지를 보고 정합니다.

무통장입금은 콜로플라스트 입금계좌를 문자로 안내하고, 입금 확인은 사람이 합니다.

### 2.6 화면 정리

- **상단 칩 → 검색 필터** (12화면) — 화면 맨 윗줄을 통째로 차지하던 칩을 필터 안으로
  옮겼습니다. 고르는 일은 아래 필터가 함께 하고 있어 같은 일을 두 자리에서 하던
  셈입니다. 건수는 괄호로 함께 적습니다.
- **화면 탭으로 열기** — 대시보드의 링크, 계산서 발행의 「주문 상세」, 주문현황의
  「신청 등록」. 보던 화면이 통째로 바뀌지 않습니다.
- **옆 탭에서 상세 보기** — 교환/반품/취소 목록과 거래처 관리. 찾던 조건이 끊기지
  않아 목록으로 돌아와 다시 찾을 일이 없습니다.
- **주문 등록** — 제품은 검색 창에서 찾습니다(세 글자 이상). 큰 창에서 그림을 끌어
  옮기고 휠로 키웁니다. 처방전을 넘길 때 흰 화면이 끼지 않습니다.
- **처방자료 업로드** — 한 번에 올릴 수 있는 파일을 10개에서 **40개**로 늘렸습니다.
