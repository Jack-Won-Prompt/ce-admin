## 2. 개발 — 적용한 업무

### 2.1 개인정보 보호 (최우선 과제)

#### 주민등록번호 암호화 — P0-1 완료

개인정보보호법상 주민등록번호는 **암호화 저장이 의무**입니다. 기존에는 환자 정보와
처방전 OCR 결과에 평문으로 저장돼 있었습니다.

적용 내용

- 전용 암호화 키 도입 — 애플리케이션 키(`APP_KEY`)와 **분리**해, 한쪽이 노출돼도 다른 쪽이 열리지 않게 함
- 암호화 컬럼 + 마스킹 컬럼 + 검색용 해시 컬럼 3종 구성
  - 마스킹(`531019-2******`)은 화면 표시용 — 복호화 없이 목록·상세를 그린다
  - 해시(HMAC-SHA256 + 페퍼)는 검색용 — 평문 없이 동일인 조회가 된다
- 기존 데이터 이관 명령(`rrn:backfill`) 작성 후 **평문 컬럼 삭제**
- 복호화는 **사유 코드**를 받아야만 동작하고, 누가·언제·무엇을·왜 열었는지 **감사 로그**에 기록
- 모델 직렬화에서 제외 — API·JSON 응답으로 새어나갈 경로 차단

현황: 환자 11건 · 처방전 11건 이관 완료, 평문 컬럼 제거 완료.

#### 소스 코드 노출 차단

서버 설정에서 애플리케이션 소스가 웹으로 직접 열리던 경로를 차단했습니다.
`app`, `config`, `database`, `routes`, `storage` 등 디렉터리와 `.env`, `composer.json`,
`artisan` 접근을 막았습니다.

#### 외부 서비스 키 암호화 보관

관리자 화면에서 저장하는 키·시크릿·비밀번호 13종을 **암호화해서 보관**합니다.
화면에는 원문을 내려보내지 않고 '설정됨' 여부만 표시합니다.

> 데이터베이스 접속 정보와 암호화 키는 의도적으로 제외했습니다. 설정을 읽으려면
> 데이터베이스가 먼저 연결돼야 하고, 데이터를 푸는 열쇠를 그 데이터 옆에 두면
> 암호화가 의미를 잃기 때문입니다.

### 2.2 접근 권한 체계 신규 도입

기존에는 로그인한 사용자 모두가 22개 화면을 동일하게 볼 수 있었습니다.
권한 검사가 일부 화면에 흩어져 있어 일관성이 없었습니다.

적용 내용

- **권한 그룹** 개념 도입 — 사용자마다 그룹을 부여
- 화면별 **5개 액션** 분리 — 조회 / 등록 / 수정 / 삭제 / 발송
- 권한 없는 메뉴는 **사이드바에서 아예 보이지 않음**
- 권한 없는 버튼은 **화면에 출력되지 않음** (숨김이 아니라 미생성)
- 서버 측 차단 — 주소를 직접 입력해도 막힘 (미들웨어 1개로 249개 경로 커버)
- 신규 화면: **설정 › 권한 그룹** — 그룹 목록 + 페이지×액션 매트릭스 편집
- **관리자 관리** 화면에 권한 그룹 배정 기능 추가

안전장치: 관리자(`admin`) 계정은 항상 전권이라 설정 실수로 잠기는 사고가 없습니다.
도입 시 '전체 권한' 그룹을 만들어 기존 사용자 전원에 부여했으므로 **무중단**으로 적용됐습니다.

### 2.4 업무 화면 신규·개선

#### SR(서비스 요청) 관리 — 신규

기존 'AI 유지보수' 메뉴를 실무에 맞는 **SR 관리**로 교체했습니다.
요청 등록·답변, 상단 요약 패널, 전용 목록 화면을 제공합니다.

#### 처방전 관리 — 신규

빈 화면에서 새 처방전을 등록하는 진입점을 **환자·처방** 메뉴에 추가했습니다.

#### 서류 관리 — 개선

- 조회 결과 / 서류 등록을 **패널 탭**으로 분리
- 처방전별 **전체 서류를 한눈에 확인·등록**
- 처방전 검수 화면을 새 탭으로 여는 흐름 연결

#### 관리자 관리 — 개선

관리자 목록 / 초대 현황을 위아래 카드에서 **탭 전환**으로 바꿔 화면 길이를 줄였습니다.

#### 처방전 검수 화면 — 개선

- **신규 등록**을 '새 처방번호 발급'으로 변경 — 기존에는 현재 처방전을 덮어쓸 위험이 있었음
- 초기화 범위 확대 — 뷰어·위임동의·가상계좌·연계 상태·등록자·검수 메모·생성 서류까지
- 저장 계열 버튼(원본 복원·저장·승인요청)을 **탭바 한 곳으로 통합** (기존 8곳 분산)
- 아코디언 항목의 입력 시작 위치 정렬

#### 전 화면 공통

- 상세 화면 **'새 탭으로 열기'**를 10개 화면에 전파 — 목록을 잃지 않고 상세를 본다
- 브라우저 기본 `alert`/`confirm`을 **커스텀 다이얼로그로 전면 교체**
- 탭 제목을 **'화면 이름 - 식별자'** 형식으로 통일 (예: `처방전 관리 - RX-20260803-004`)

### 2.5 외부 서비스 설정 관리 — 신규

팝빌·토스·알림톡·건강보험공단·AWS·메일·NICE 설정이 **서버 파일에만** 있어,
값 하나를 바꾸려면 서버에 접속해야 했습니다.

신규 화면 **설정 › 서비스 연동 설정** — 탭 8개, 관리 항목 41개.

| 탭 | 관리 항목 |
|---|---|
| 회사 정보 | 상호·대표자·업태·종목·주소·연락처 |
| 팝빌 | 링크아이디·시크릿 키·테스트 모드·문자 시뮬레이션 |
| 토스페이먼츠 | 클라이언트/시크릿 키·웹훅 보안 키·가상계좌 |
| 카카오 알림톡 | API 키·발신 프로필 키·채널·발신번호 |
| 건강보험공단 | 기관 정보·팩스 방식·하이팩스/eFax 키 |
| AWS Textract | 액세스 키·시크릿·리전 |
| 본인확인(NICE) | 자격증명 3종·본인확인 정책 |
| 메일(SMTP) | 주소·포트·계정·비밀번호 |

**저장한 항목만** 서버 설정을 덮어쓰므로, 손대지 않은 값은 그대로 유지됩니다.

## 4. 확인·조치가 필요한 사항

| 구분 | 내용 | 담당 |
|---|---|---|
| **운영 장애** | 서버 예약 작업이 없는 명령(`notification:daily`)을 매분 호출해 실패 중. 그 결과 **현금영수증 팝빌·국세청 동기화가 전혀 실행되지 않음**. 크론을 `schedule:run`으로 교체 필요 | 서버 |
| 설정 미완료 | NICE 자격증명 중 `client_id`·`product_id`가 비어 있어 **휴대폰 본인확인이 꺼져 있음** | 운영 |
| 데이터 확인 | 회사 정보의 **상호** 자리에 사업자번호(`123-456-7890`)가 들어 있어 세금계산서에 상호가 잘못 나감. 건강보험공단 탭의 사업자번호를 채우면 정상화 가능 | 운영 |
| 정책 결정 | 디자인 시스템 **의미 색상**(성공·경고·오류) 미정의 — 확장 요청서 회신 대기 | 디자인 |
