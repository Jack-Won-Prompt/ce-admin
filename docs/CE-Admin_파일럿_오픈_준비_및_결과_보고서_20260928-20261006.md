## 4. 드러난 문제와 조치

### 4.1 가상계좌 재발급이 입금을 잃게 했다 (가장 무거움)

**무슨 일** — 환자가 결제 링크를 네 번 열자 토스가 가상계좌를 네 번 냈다. 우리는 한
주문에 결제 줄을 하나만 두므로 뒤 발급이 앞을 덮었고, **첫 계좌로 들어온 81,000원이
이을 곳을 잃었다.** 입금 통지는 두 번 왔지만 둘 다 「이어진 주문 없음」으로 지나갔고,
나흘 뒤 담당자가 토스 화면을 보고서야 찾았다.

**조치**

| | |
|---|---|
| 그 건 | 입금 확인(2026-10-02 14:05:42) · 세금계산서 729,000 · 현금영수증 81,000 · 거래명세서 발행 |
| 막기 | 살아 있는 계좌가 있으면 **결제창을 다시 열지 않고 그 계좌를 다시 보여 준다** |
| 넓히기 | 대기 중인 결제 줄을 **전부** 토스에 물어 같은 사고가 더 있는지 확인 — 이 한 건뿐 |

### 4.2 위드웍스에서 이미 끝난 처방전에 주문이 섰다

**무슨 일** — 위드웍스에서 온 처방전 84,189장 가운데 **80,163장(95.2%)이 이미
구매확정되었거나 취소된 건**인데, 전부 「주문등록 이동」을 누를 수 있는 상태로 목록에
서 있었다. 담당자는 쓸 수 있는 4,026장을 그 속에서 눈으로 골라냈고, 실제로 **50건**이
눌려 주문번호가 났다 — 2023년 처방전에서 선 것도 있었다.

**조치** — 처방전과 판매주문을 잇는 길(상담)을 찾아 마감 여부를 우리 표에 적고,
목록에서 **기본으로 감춘다**(세우는 줄 84,189 → 4,012). 이미 선 주문 50건 가운데
사람 손이 닿지 않은 **46건을 소프트 삭제**했다(되살릴 수 있다).

### 4.3 위드웍스 자료 이관이 멈춰 있었다

운영 자료 가져오기는 **예약이 없고 사람이 눌러야 돈다.** 09-29 대이관 뒤 아무도 돌리지
않아 일주일치가 밀려 있었다. **2026-09-30 까지만** 가져오도록 날짜 제한을 두고
(10-01 부터는 CE-Admin 이 직접 받으므로 대상이 아니다) 158줄을 메웠다.

### 4.4 설정 두 칸이 글자 「Array」로 깨져 있었다

`위임동의 발송 시간`과 `주문 확정 안내` 두 칸에 문자 그대로 `'Array'` 가 들어 있어
**시간 제한이 전혀 작동하지 않았고**, 확정 안내는 늘 무통장입금으로 나갔다. 10-01
12:19 부터 10-06 까지였다. 값을 바로잡고(09:00-23:30 · 링크페이), 설정 저장이 글이
아닌 값을 받으면 뭉개지 않고 건너뛰도록 고쳤다.

### 4.5 Finance 화면

- 모든 탭의 셈을 서로 견주어 **어긋난 자리 없음**을 확인(주문·환자결제·기관청구·
  미정산·부가세신고·교환반품취소 + PG 네 갈래)
- 「카드」가 결제 링크에 적힌 수단을 보던 것을 **토스가 알려 준 수단**으로 고쳐
  1,351,500원 이중 계상을 바로잡음
- 부가세신고 탭의 공급가액+부가세가 **공단 몫만** 담던 것을 전체 기준으로 고침
- PG 탭의 「PG수수료」가 갈래마다 다른 값을 뜻하던 것을 통일
- 환자결제·미정산 탭의 PG 정산 세 칸이 **늘 비어 있던 것**을 고침
  (토스에 날짜를 하이픈 없이 보내 400 으로 떨어지고 있었다)
- 탭 하나를 여는 데 질의 641회·1.75초 → **24회·0.43초**

### 4.6 그 밖

- 공단 팩스가 엉뚱한 지사로 간 건 — 처방전에 담당 지사가 비어 있었다(182건 중 1건)
- 오류 이력 화면을 관리자 계정만 보도록 제한
- 「신규 등록」 단추가 새 주문을 만드는 것으로 오해되던 것을 「신규 상담 등록」으로
- 담당자 배정 팝업이 체크하지 않은 줄까지 바꾸는 것으로 보이던 것
- 그리드 칸 너비를 조절하면 다른 칸도 함께 바뀌던 것

올리도록 바꾸고 붙임 파일·내용 수정을 더했다. 링크 단추가 눌리지 않던 것도 같은 날
고쳤다(말풍선이 창 밖으로 밀려 잘리고 있었다).

## 7. 남은 일

### 7.1 급한 것

| | |
|---|---|
| 등록신청서 저장 막힘 (#27) | 담당자가 지금 막혀 있다 |
| 병원 목록이 위드웍스와 다름 (SR #75) | 요양기관코드 불일치 · 조회 안 됨 |
| 출고 완료인데 「취소」로 보임 (SR #110ㆍ#106ㆍ#81) | 정정·취소를 거친 주문의 상태 표시 — 한 뿌리로 보인다 |

### 7.2 이어서

- 주문등록 이동에서 **마감 처방전을 막는 마지막 그물**(지금은 목록에서 감추는 것까지)
- 간편결제(카카오페이) 결제기관 연결 — 증빙 이미지가 붙지 않는다 (SR #89ㆍ#107)
- 환자 이름 용어 통일 (SR #99ㆍ#102ㆍ#90)
- 위드웍스 자료 가져오기 **예약** — 지금은 사람이 눌러야 돈다

### 7.3 판단이 필요한 것

- 현금영수증 거래일시는 팝빌이 **당일·전일만** 받는다. 입금을 뒤늦게 확인한 건은
  거래일이 실제 입금일과 달라진다 — 홈택스 지연발급으로 처리할지 정해야 한다
- 처방기간이 끝난 처방전을 주문으로 올리는 것을 막을지 (지금은 위드웍스 마감 여부만
  본다)

## 8. 맺음

파일럿 기간에 **기능이 서지 않아 멈춘 일은 없었다.** 주문·결제·증빙·창고·팩스가 모두
끝까지 돌았고, 드러난 문제는 자료가 어긋나거나 화면이 사실과 다르게 보이는 쪽이었다.

가장 값진 발견은 **「조용히 어긋나는 자리」**였다. 입금이 들어왔는데 이을 곳을 잃고,
설정이 깨졌는데 화면은 멀쩡해 보이고, 쓸 수 없는 처방전 8만 장이 쓸 수 있는 것처럼
서 있었다. 모두 사람이 눈으로 알아채기 어려운 것들이라, 앞으로도 **재어 보는 일**을
계속해야 한다.
