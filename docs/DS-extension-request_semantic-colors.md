# 디자인 시스템 확장 요청 — 의미색(Semantic Colors)

**대상 파일** 콜로플라스트_CE Admin_pc (`3YKbPEfMiYfeWYGLSvRtMT`) · `🔒 Design System` 캔버스
**요청일** 2026-08-03
**요청 사유** 구현에 필요한 상태 표현 색이 DS에 정의돼 있지 않아, 개발 측이 임시값을 만들어 쓰고 있습니다. 그 임시값을 DS로 승격하거나 DS 기준값으로 대체해 주시기를 요청드립니다.

---

## 1. 현재 상태

DS에 정의된 색은 세 계열입니다.

| 계열 | 단계 |
|---|---|
| Primary | 50 · 100 · 200 · 300 · 400 · **500\*** · 600 · 700 · 800 · 900 · 1000 (11단계) |
| Grayscale | 0 · 50 · 100 · 200 · 300 · 400 · 500 · 600 · 700 · 800 · 900 · 1000 (12단계) |
| Alert | 50 · 100 · **500-warning** (3단계) |

화면에는 이 세 계열로 표현할 수 없는 상태가 있습니다. 대표적으로 **"검수 완료"와 "반려"를 같은 화면에서 구분**해야 하는데, Alert 한 계열로는 둘 다 빨강이 됩니다.

그래서 구현에서 5개 색을 임시로 정의해 쓰고 있습니다. **DS에 근거가 없는 값이므로, 시안과 구현이 어긋나는 원인이 됩니다.**

---

## 2. 요청 내용

아래 4개 계열을 DS에 추가해 주시기를 요청드립니다. **Alert와 같은 3단계 구조(50 / 100 / 500)** 로 맞춰 주시면 구현이 그대로 매핑됩니다.

| 요청 계열 | 화면에서의 역할 | 사용 빈도 |
|---|---|---|
| **Success** | 완료·정상·승인 상태 | 269회 |
| **Warning** | 진행 중·주의·확인 필요 | 118회 |
| **Danger** | 실패·삭제·반려 | 252회 |
| **Info** | 안내·중립 진행 상태 | 56회 |

> 사용 빈도는 `resources/views` 와 `public/vendor` 에서 해당 토큰 참조를 센 실측값입니다(2026-08-03 기준).

### 2-1. Danger 와 기존 Alert 의 관계

`alert/500-warning (#D73D3F)` 은 **이름은 warning 이지만 값은 빨강**입니다. 구현에서 빨강은 "실패·삭제·반려"에 쓰이고, 주황은 "진행 중·주의"에 따로 씁니다.

두 가지 중 하나로 정리해 주시기 바랍니다.

- **(A)** `alert` 를 `danger` 로 이름 변경하고, `warning` 을 별도 계열로 신설
- **(B)** `alert` 를 그대로 두고 `warning`(주황)·`success`·`info` 를 신설

개발 측은 **(A)** 를 권합니다. 현재 이름과 값이 어긋나 있어 오용 위험이 있습니다.

### 2-2. Purple

구현에 `#7C3AED` 가 9회 쓰입니다(처방 제품 섹션 아이콘 등 장식 용도). **의미를 갖는 색이 아니므로 DS 추가는 요청드리지 않습니다.** DS 확정 후 개발 측에서 Primary 또는 Grayscale 로 흡수하겠습니다.

---

## 3. 색 결정에 참고하실 사항

값은 디자인 측에서 정해 주시기를 요청드립니다. 개발 측 임시값은 범용 팔레트에서 가져온 것이라 **DS의 톤과 맞지 않습니다** — 임시값보다 채도를 낮춰 `alert/500-warning` 과 같은 결로 맞춰 주시면 화면이 하나로 읽힙니다.

| 계열 | 개발 측 임시값 (참고용) | 비고 |
|---|---|---|
| Success | `#12B76A` / light `#ECFDF5` | 임시값이 DS 대비 채도가 높습니다 |
| Warning | `#F59E0B` / light `#FFFBEB` | 〃 |
| Danger | `#EF4444` / light `#FEF2F2` | `alert/500-warning #D73D3F` 과 다릅니다 |
| Info | `#0EA5E9` / light `#F0F9FF` | Primary 와 색상이 가까워 혼동 위험이 있습니다 |

**제약 조건 두 가지**를 지켜 주시기 바랍니다.

1. **흰 배경 위 본문 대비** — 상태 배지의 글자색으로 쓰이므로 `#FFFFFF` 위에서 4.5:1 이상이 필요합니다.
2. **Primary 와 구분** — 특히 Info 는 Primary(`#28798B`) 와 색상이 가까우면 "진행 중"과 "선택됨"이 구별되지 않습니다. 색상환에서 충분히 떨어뜨려 주시기 바랍니다.

---

## 4. 실제 사용 맥락

색을 정하실 때 참고하실 수 있도록, 화면에서 어떤 상태에 어떤 색이 붙는지 정리했습니다.

### 처방전 상태

| 상태 | 현재 색 |
|---|---|
| 대기 중 | Grayscale (secondary) |
| OCR 처리중 | Warning |
| OCR 완료 | Info |
| 검수 필요 | Danger |
| 검수 완료 | Success |
| 반려 | Danger |
| 주문 완료 | Success |

### 주문 상태

| 상태 | 현재 색 |
|---|---|
| 주문 대기 | Grayscale (secondary) |
| 주문 확정 | Primary |
| 배송 중 | Info |
| 배송 완료 | Success |
| 취소 | Danger |

### 그 외

- **버튼** — `btn-success`(승인·발행), `btn-warning`(보류), `btn-danger`(삭제·반려)
- **알림 토스트** — 성공/경고/오류 3종
- **워크플로우 단계 표시** — 완료(Success) / 진행(Warning) / 대기(Grayscale)

## 5. 함께 확인 부탁드리는 사항

의미색과 별개로, 분석 과정에서 확인된 항목입니다.

1. **타이포그래피 정의 부재** — DS 캔버스에 색상 섹션만 있습니다. 화면 시안에서 Pretendard Medium 13 / Bold 16 / Bold 20 이 쓰이는 것을 확인했으나, **정의된 스케일이 없어** 새 화면을 만들 때마다 시안을 역추적해야 합니다. 타입 스케일을 DS에 명시해 주시면 좋겠습니다.

2. **간격·radius 스케일 부재** — 시안에서 4·6·8·12·16·24px 간격과 6·8·12·16·20px radius 가 관찰됩니다. 규칙으로 정리해 주시면 구현이 일관됩니다.

3. **그리드 컴포넌트** — 목록 화면 전체가 공통 그리드 컴포넌트를 씁니다. 현재 그 컴포넌트의 강조색이 DS와 무관한 파랑(`#3c82c4`)입니다. Primary 기준으로 바꿀 예정이니, 그리드의 헤더·선택행·정렬 아이콘 색을 DS에서 지정해 주시면 그대로 반영하겠습니다.

---

## 6. 회신 후 개발 측 처리

DS가 확정되면 다음 순서로 반영합니다.

1. Primary 11단계 · Grayscale 12단계 · 의미색 4계열을 CSS 변수로 도입
2. 기존 임시 토큰을 새 토큰으로 매핑 (참조 지점 700곳 이상 — 변수 정의만 교체하면 일괄 반영)
3. 그리드 컴포넌트 강조색을 Primary 로 연결
4. 사이드바 폭 320px · 헤더 68px 등 치수 정렬
