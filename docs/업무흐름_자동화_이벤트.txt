0. 자동화를 켜고 끄는 스위치
================================================================================

설정 > 서비스 설정 > 주문
  rx_received_sms_on_first_save   첫 저장에 접수 안내 문자
  consent_sms_on_first_save       첫 저장에 위임동의 문자
  consent_sms_hours               위임동의 문자를 보내는 시간대 (기본 09:00-20:00)
  nhis_fax_on_consent             동의가 끝나면 공단 팩스 자동 발송
  nhis_fax_on_id_card             신분증이 들어오면 공단 팩스 다시 시도
  ship_notice_on_shipped          출고되면 배송 안내
  confirm_pay_method              주문 확정 안내를 무엇으로 보낼지
                                  (링크페이 / 가상계좌 / 무통장입금)

설정 > 서비스 연동 설정 > 테스트 설정
  popbill.sms_mode                live | redirect(우리에게만) | simulate
  popbill.fax_mode                위와 같음
  popbill.issue_simulate          세무 발행을 팝빌에 보내지 않고 성공 처리
  nice.enforce                    본인확인 필수 여부
  toss.env                        test | live

  ※ 운영 데이터 > 위임장 서명은 이 스위치를 따르지 않습니다.
     문자는 늘 적힌 번호로 나가고, NICE 본인확인도 늘 받습니다.
     그 화면에서 받은 서명이 공단에 내는 서류가 되기 때문입니다.

주기 작업 (스케줄러)
  매 5분     fax:sync-pending        팩스 전송 결과 확인
  매 10분    withworks:sync          위드웍스 판매주문 상태 확인
  매 15분    cashbill:sync --status  현금영수증 상태 확인
  매 30분    bank:sync               입금 내역 확인
  매시       cashbill:sync --days=1  현금영수증 내역 확인
  매시       claim:refresh           청구 준비 상태 갱신
  매일 09시  nhis:renew-notice       공단 재등록 기한 알림

2. 파일 검수 — 처방전 목록
================================================================================

[사람] 처방전 목록 > [파일 검수] > 올라온 파일을 보고 판단

--- 2-A. 다시 올려 달라고 요청할 때 -------------------------------------------

[사람] 파일 검수 창에서 파일 한 장을 짚어 [다시 올리기 요청]

[자동] 처방전 상태 → "검수 보류"
[발신] 그 파일을 올린 사람에게 앱 알림 (FCM)
       ReuploadRequestService::걸기 → 알리기
       · 받는 사람: 그 첨부를 올린 이, 없으면 처방전을 만든 이
       · 앱 토큰이 없으면 보내지 않고 까닭을 줄에 적습니다
       · 보낸 값: type=rx_reupload, rx_number, attachment_id, reason

[사람] 앱에서 알림 확인 → 이미지 삭제 → 다시 업로드
       DELETE /api/prescriptions/{rx}/image
       DELETE /api/prescriptions/{rx}/attachments/{id}

[자동] 새 파일이 붙는 순간 그 요청이 저절로 닫힙니다
       PrescriptionAttachment::created → ReuploadRequestService::닫기
       Prescription::saved (본 그림 교체 시) → 닫기
       · 사람이 손으로 닫게 하면 닫히지 않습니다. 올린 사람은 끝났다고 여기고
         검수자는 "요청 중"이 그대로인 것만 봅니다

[사람] 앱에서 [검토 요청]
       POST /api/prescriptions/{rx}/request-review
[발신] 승인 권한자에게 알림  ReviewNotice::askReview

--- 2-B. 검수를 마칠 때 -------------------------------------------------------

[사람] 파일 검수 창에서 [검수 확인]

[자동] 처방전 상태 → "검수 완료"(approved), reviewed_at · reviewed_by 기록
[발신] 요청한 담당자에게 알림  ReviewNotice::tellApproved

3. 주문 등록 — 상세 목록 · 병원/처방 정보
================================================================================

[사람] 주문 등록 화면에서 건을 열고 환자·병원·처방 정보를 입력
       ※ 거래처를 고르기 전에는 탭줄 단추가 모두 잠깁니다

[자동] 저장할 때마다
       · 주문 줄의 금액·수량이 함께 맞춰집니다 (OrderSync)
       · 동의를 아직 못 받았으면 화면에 한 번 알립니다 (막지는 않습니다)
       · 처방 총계·청구 한도를 넘으면 알립니다 (저장은 됩니다)

[사람] [입력 검수 요청]
       POST /prescriptions/{rx}/input-review/request
[발신] 승인 권한자에게 알림  ReviewNotice::askReview

[사람] [입력 검수 승인]
       POST /prescriptions/{rx}/input-review/approve
[발신] 요청한 담당자에게 알림  ReviewNotice::tellApproved

  ※ 입력 검수는 파일 검수와 다른 칸에 적힙니다 (input_review_*).
     파일만 승인해도 입력 검수는 열려 있습니다.
     파일 검수 = 올라온 이미지를 본다
     입력 검수 = 적어 넣은 값을 본다

5. 주문 제품 등록 → 주문 생성 및 연계
================================================================================

[사람] 주문 제품 탭에서 제품·수량·배송지 입력
       ※ 추가 주문이면 단추가 [추가 주문 생성 및 연계] 로 섭니다

[사람] [주문 생성 및 연계]

[자동] 화면이 여섯 문을 먼저 봅니다 — 하나라도 막히면 진행되지 않습니다
       ① 검수
       ② 동의 (위임 서명 · 개인정보)
       ③ 총계      1일 처방개수 × 총 처방일수
       ④ 청구 한도  하루 금액 한도
       ⑤ 수량      원 주문 + 추가 주문 합이 처방 총계를 넘지 않는가
       ⑥ 배송지
[발신] 막히면 담당자에게 알림 + 주문 이력에 기록
       POST /orders/blocked → OrderNotice::tellOwner
       · 1분에 다섯 번까지만 남깁니다

[자동] ① 우리 주문 저장
       POST /orders

[자동] ② 위드웍스 판매주문 등록
       [발신] so_store
       · 서버가 한 번 더 봅니다
         재구매 기한 · 위임 서명 · 배송지 · 받는 사람 · 제품 코드
       · confirm=0 으로 보냅니다 (확정은 창고가 합니다)
       · qty_unit=EA (낱개). 밝히지 않으면 저쪽이 박스로 읽습니다
       [발신] 연계 확인 메일 — 보낸 값 그대로 (WithworksNotice)

[자동] ③ 판매주문이 실제로 선 뒤에만 고객 안내가 나갑니다
       · 주문 접수 안내 문자 — 누구에게나
       · 결제 안내 — [설정] confirm_pay_method
           링크페이 → 결제 페이지 주소를 문자로
           가상계좌 → 계좌를 발급해 문자로
       ※ 본인부담금이 0원이면 결제 안내는 보내지 않습니다
          (차상위경감 · 기초는 본인부담이 없습니다)

[자동] ④ 본인부담금 0원 건은 이 자리에서 증빙을 냅니다
       DepositAutoIssue::run('주문 연계(본인부담금 없음)')
       · 입금 확인이 영영 서지 않는 건이라 여기가 그 건의 확정입니다
