## 겪은 것

### ① 처방전의 병원명과 저장된 병원명이 다르다 — 시험자료 탓이다

처방전은 「대한새봄대학교병원」인데 요양기관번호가 **37100017** 이다. 그 번호는
마스터에서 이미 **경북대학교병원**이 쓰고 있다.

새 병원 등록은 **막혔다**. 막은 것이 옳다 — `HospitalController::store()` 가
요양기관번호를 겹치지 못하게 한다(「번호가 겹치면 청구가 남의 병원으로 간다」).
그래서 **번호를 믿고** 경북대학교병원을 골랐다.

**결함이 아니다.** 시험용 가상 처방전이 실재하는 요양기관번호를 빌려 쓴 탓이다.
다만 **다음 회차 자료를 만들 때는 쓰이지 않는 번호를 쓰는 것이 좋다** — 병원명과
번호가 어긋나면 청구 서류를 눈으로 볼 때 헷갈린다.

### ② 위드웍스 판매주문의 「확정자」가 빈다

`so_confirm` API 로 확정하면 화면 사용자가 없어 **확정자가 남지 않는다.**
판매상태·확정판매금액·확정일자는 정상이고, **CE Admin 활동 기록에는**
「위드웍스 판매주문 S2609070005 확정」이 남는다. 급하지 않지만, 누가 확정했는지
저쪽에서도 보이게 하려면 연동 계정명을 남기도록 위드웍스 쪽을 손봐야 한다.

### ③ 공단 팩스 자동 발송이 꺼져 있다

`ORDER_NHIS_FAX_ON_CONSENT` 가 꺼져 있어 동의 완료 뒤에도 자동으로 나가지 않는다.
**설정값대로 동작한 것이라 결함이 아니다.** 김태오·박도겸 모두 손으로 보냈다.
자동 갈래(TC-013)를 보려면 설정을 켜고 한 사람은 그 길로 밟아야 한다.

### ④ 본인부담 0원 건이 끊기는 데가 없었다

이 사람으로 보려던 것이 이것이다. **네 자리 모두 제대로 갈라졌다.**

| 자리 | 0원일 때 |
|---|---|
| 결제 안내 문자 | **보내지 않는다** — 까닭을 화면에 적어 보여 준다 |
| 가상계좌 | 발급하지 않는다 (0원을 진작 막고 있었다) |
| 확정 메시지 | 「입금 확인」이 아니라 **「주문을 확정했습니다」** |
| 창고 확정 | **그대로 간다** — 돈과 상관없이 물건은 나가야 한다 |
