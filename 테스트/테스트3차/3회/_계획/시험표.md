## 팩스는 「닿지 않는 번호로 진짜 보낸다」 (2026-09-05 지시)

처음에는 시늉 스위치(`POPBILL_FAX_SIMULATE`)를 새로 만들어 켜 두었습니다(`cd516c7`).
그러나 **팝빌 화면에서 직접 확인한 뒤 지우겠다**는 지시가 있어 **운영 전송으로 되돌렸습니다.**

| | |
|---|---|
| 받는 팩스번호 | **`02-0000-0000`** |
| 왜 이 번호인가 | 국내 유선 번호는 **가입자 국번이 0 으로 시작하지 않습니다.** 곧 이 번호는 누구에게도 할당되지 않아, 실제로 종이가 나오는 곳이 없습니다 |
| 어디에 적어 두었나 | 관할 청구처(공단 종로지사, `billing_offices.id=10`)의 팩스번호 |
| 확인 | 김지훈 건이 운영 접수번호 **`026090512574800001`** 로 접수되었습니다 |

> **팝빌 화면에서 확인한 뒤 지워 주십시오.** 시험이 끝나면 그 번호를 실제 지사
> 번호로 되돌려야 합니다.
>
> 시늉 스위치는 **꺼진 채로 남겨 둡니다**(기본값도 꺼짐). 운영에서 조용히 안 나가는
> 일이 없어야 하고, 나중에 「보내지 않고 화면만 훑고 싶을 때」 켤 수 있습니다.

### 주문등록증은 올리지 않는다

CE Admin 의 서류 유형은 **열네 갈래**이고 그 안에 **주문등록증이 없다.**

```
처방전 · 등록신청서 · 결과지 · 신분증 · 개인정보 동의서 · 요양비위임장 ·
요양비 지급청구서 · 의료용품구입확인서(지자체용) · 등기처리 영수증 ·
거래명세서 · 세금계산서 · 현금영수증 · 카드매출 · 기타
```

그러므로 자료의 `01_주문등록증_TEST.png` 는 **어디에도 올리지 않는다.**
「기타」로 밀어 넣지도 않는다 — 갈래가 없다는 것은 그 서류를 이 시스템이 다루지
않는다는 뜻이지, 아무 데나 담아 두라는 뜻이 아니다.

**참고 자료로만 쓴다** — 거기 적힌 180 EA 를 넣어 5.4 가 걸리는지 보고, 확인한 뒤
처방전 수량으로 되돌린다. 환자 폴더에도 넣지 않는다.

### 처방 정보는 처방전에서만 읽는다 (2026-09-05 지시)

**처방에 관한 값은 처방전 한 장에서만 가져온다.** 등록신청서ㆍ결과지ㆍ주문등록증에서
처방 정보를 끌어오지 않는다.

이 자료의 처방전에 적혀 있는 것은 **열 가지**다.

| 처방전에 있는 것 | 화면의 어느 칸으로 |
|---|---|
| 가상 환자명 | 이름 |
| 테스트 주민번호 | 주민등록번호 |
| 가상 의료기관 | 병원명 |
| 발행일 | 처방전 발행일 |
| 처방 품목 | 제품 |
| 테스트 규격 | (제품 고를 때 견줌) |
| **1일 사용량** | **1일 처방 개수** |
| **테스트 처방기간** | **총 처방일수 · 처방전 사용 기간** |
| **총 테스트 수량** | **총계 — 주문 수량의 근거** |
| 처방 상태 | (참고) |

**처방전에 없는 칸**은 화면을 다 채우라는 지시에 따라 시험값으로 넣는다 —
요양기관 코드ㆍ진단 확인일ㆍ상병 구분ㆍ상병코드ㆍ상병명ㆍ요류역학검사일ㆍ
전문과목ㆍ담당 의사명ㆍ의사면허번호.
**어느 값이 자료에서 왔고 어느 값이 시험값인지 사람마다 정리.md 에 갈라 적는다.**

### 주문 수량은 처방전을 따른다

| 환자 | 처방전 총 수량 | 주문등록증 |

| 01 김지훈 | 1일 4개 × 30일 = **120** | 180 |
| 02 이서연 | 1일 5개 × 30일 = **150** | 180 |
| 03 박현준 | (열어 보고 적는다) | 180 |

주문은 **처방전 총 수량**으로 넣습니다. 주문등록증의 180 은 **5.4(처방 총계 초과 차단)를
한 번 확인하는 데만** 쓰고, 막히는 것을 본 뒤 처방전 수량으로 되돌립니다.

> 처음에는 이 어긋남을 「일부러 심은 경계 자료」로 보았으나, 셋 다 180 으로 같은 것을
> 보면 **서식의 고정값**일 가능성이 큽니다. 어느 쪽이든 5.4 는 그대로 확인됩니다.
