## ⑪ 교환이 창고로 가지 못한다 — **위드웍스 기준정보에 교환 코드가 없다**

접수하자 화면이 **「접수했습니다. 접수번호 RT-20260906-0001 — 위드웍스 전달은
실패했습니다.」**라 했다. 「발행ㆍ연계」 탭에 까닭이 그대로 적혀 있다.

```
처리할 수 없는 반품 구분입니다: exchange
  — return(반품)/cancel(취소)/exchange(교환) 중 하나로 보내주세요.
```

**말이 스스로 모순이다** — exchange 를 보냈는데 exchange 중 하나로 보내라 한다.
위드웍스 코드를 읽어 까닭을 찾았다.

```php
// resolveReturnSoType()
$code = (string) $map[$alias[$value]];          // exchange → 1506
return self::typeCodeExists($code) ? $code : null;   // ← 여기서 null
```

**교환 주문 유형 코드 `1506` 이 이 계정의 기준정보(`code_lists`.TYPE)에 없다.**
취소 `1504` 도 마찬가지일 것이다(주석이 「뒤늦게 넣기로 한 것」이라 말한다).

- **CE 는 제 몫을 다했다** — 실패를 접수 건에 적고(`withworks_error`),
  화면에 까닭을 보여 주고, 「다시 보내기」 단추까지 둔다. **CE 결함이 아니다.**
- **고친 것** — 위드웍스의 거절 문구가 사람을 엉뚱한 데로 보냈다.
  이제 **「이 계정의 기준정보에 교환 주문 유형 코드(1506)가 없습니다 —
  코드 관리(TYPE)에 등록한 뒤 다시 보내주세요」**라고 말한다.
  (위드웍스 저장소 · `CeAdminController::missingReturnTypeCode`)
- **남은 일** — 위드웍스 기준정보에 **1506(교환)ㆍ1504(취소)** 를 등록해야
  교환ㆍ취소가 창고로 전달된다. **코드 체계는 위드웍스 담당의 몫이라 손대지 않았다.**

## 사람이 눌러 확인해야 할 것 — 진행 단계 단추

진행 단계의 걸음 단추(`form.rt-go` 의 submit)를 **Playwright 로 눌렀을 때 폼이
제출되지 않았다.** 같은 요청을 같은 창의 `fetch` 로 보내면 **200 으로 정상 처리**된다.

- 단추는 화면에 보이고, 가려져 있지도 않으며(`elementFromPoint` 가 그 단추를 짚는다),
  중첩 폼도 아니다. 클릭에 오류도 나지 않는다.
- 그래서 **시험 도구 쪽 문제일 가능성이 높다.** 다만 확실히 가르려면
  **사람이 실제로 눌러 봐야 한다.**
- 이 건의 아홉 걸음은 fetch 로 밟았다(같은 세션ㆍ같은 요청ㆍ같은 서버 처리).

> 폼이 화면에 **둘** 있고 그 가운데 하나는 숨어 있다 — 처음에 숨은 쪽 단추를 눌러
> 한참 헛돌았다. 그것은 내 실수였고 결함이 아니다.
