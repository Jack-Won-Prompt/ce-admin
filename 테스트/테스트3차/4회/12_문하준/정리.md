## ⑬ 내가 만든 회귀 — 웹훅이 끊겼다 (고침 `0fe4d2ed6`)

이 사람의 주문이 **창고에서 할당ㆍ피킹ㆍ출고를 다 마쳤는데 CE 는 「확정」에
멈춰 있었다.**

```
창고  SO S2609060012 status=95 · SHIP SH2609060004 status=55
CE    EUD202609061037451 status=confirmed   ← 웹훅이 오지 않음
```

**까닭은 내가 만든 것이다.** CE 주문번호를 `udf1` 에서 `etc_so_no` 로 옮기면서
조회ㆍ응답 자리는 모두 「새 자리 먼저, 없으면 옛 자리」로 고쳤는데,
**웹훅 한 곳만 빠뜨렸다.**

```php
private static function webhookCeOrderNumber(SalesOrder $order): ?string
{
    $udf1 = trim((string) $order->udf1);
    if ($udf1 !== '') return $udf1;
    ...
    return null;          // ← 비면 웹훅을 아예 보내지 않는다
}
```

`etc_so_no` 를 먼저 보게 고치니 곧바로 **배송중**까지 따라왔고 LOT 도 들어왔다.

**새길 것 — 저장하는 자리를 옮길 때는 「읽는 자리를 모두」 세어 본다.**
조회 여덟 곳ㆍ응답 다섯 곳을 세어 고치고도 웹훅 하나를 놓쳤다. 그 하나가
가장 중요한 자리였다 — 사람이 누르지 않는, 저절로 도는 길이라 조용히 끊긴다.

## 부분 반품은 걸음이 아홉이다

```
접수 → 수거중 → 검수중 → 검수 확정 → 전자 승인 → 환불완료 → 금액조정 → 발행 완료 → 완료
                                                        ↑ 부분에만 끼어드는 걸음
```

전량 반품(11번)은 여덟인데 **부분은 「금액조정」이 하나 더 낀다.** 화면이
`is_partial` 을 보고 걸음을 스스로 끼워 넣는다(`OrderReturn::flow()`).

## 조정 금액 문이 제대로 막았다

조정 금액을 적지 않고 「금액조정」으로 넘어가 보았다 — **막혔다.**
상태가 `refunded` 에 그대로 서 있었다.

> 조정 금액을 먼저 적어 주십시오 — 아래 「금액조정」 칸에 얼마를 돌려주는지
> (또는 더 받는지) 적고 저장합니다.

## ⑭ 조정 금액이 방향과 어긋났다 (고침 · 배포함)

「마이너스 발행」 카드의 조정 금액 칸에 **76,500원**이 미리 채워져 있었다.
방향은 **「환불(돌려준다)」**. 그런데 200개를 되돌리니 **돌려줄 돈은 45,000원**이다.

| | |
|---|---|
| 원 본인부담 | 121,500원 (540개) |
| 되돌린 몫 | **45,000원** (200개) |
| 미리 채워진 값 | **76,500원** ← 121,500 − 45,000 |

`adjustedAmount()` 가 셈하던 것은 주석 그대로 **「조정 뒤 남는 금액」**이었다.
그런데 그 값이 들어가는 칸은 **방향과 짝을 이루는 「움직일 금액」**이다.
그대로 저장하면 자취에도, 창고에 세우는 금액조정 주문에도 **틀린 돈이 남는다.**

「줄에서 셈한 값입니다 — 확인 후 저장하십시오」라 적혀 있어 사람이 고칠 수는
있으나, **미리 채운 값이 틀리면 그대로 저장된다.**

되돌린 몫을 그대로 내놓게 고쳤다. 운영에서 **45,000원**으로 열리는 것을 확인했고
저장하니 「**조정 금액을 적었습니다 — 환불 (돌려준다) 45,000원.**」이 떴다.
