## 찾은 결함

### ㉑ 위드웍스 「출고 확정/마감」 조회가 **500** (위드웍스 쪽)

`/schedule_by_ship/get` 이 **조건과 무관하게** 500 이다.

```
빈 조건            → 500
옛 출고번호(SH2609030002) → 500
우리 건(SH2609060006)    → 500
```

`getAllDetails()` 는 `try { … } catch (\Throwable)` 로 감싸 JSON 을 돌려주게
되어 있는데도 500 이 난다 — **catch 밖에서 죽는다.** 위드웍스 서버 로그를
봐야 자리를 짚을 수 있다.

**내가 만든 회귀가 아니다.** 이 저장소에 올린 내 커밋 셋(`7fa92f8ad`
`66911ca1e` `0fe4d2ed6`)은 모두 `api/v1/CeAdminController.php` 만 건드렸다.

**무엇이 막히는가** — 이 화면은 송장번호를 받아 `schedule_by_ships.mst_tracking_no`
에 넣고 출고 상태를 95 로 올린다. 통합 출고 관리의 「확정」으로 우회하면
출고는 되지만 **송장번호가 남지 않는다.** 그래서 이 건의 주문 송장번호가 비어 있다.

## 새길 것

- **서명판이 화면 밖에 있으면 마우스가 닿지 않는다** — `scrollIntoViewIfNeeded`
  를 먼저 해야 서명이 그려진다. 좌표만 맞추면 아무 일도 일어나지 않는다
- **NICE 휴대폰 본인확인**이 서명 앞에 선다. 서버가 `NICE_SIMULATE=true` 라
  「확인됨 (시험)」으로 넘어간다 — 운영 키에서는 실제 인증이다
- 주문 제품 저장은 **검수 승인 → 동의 둘**이 모두 끝나야 붙는다. 그 전에는
  「검수 완료 후 …」ㆍ「동의가 아직입니다」로 막힌다 (막는 것이 옳다)
- 위드웍스 작업 관리는 **toast grid** 다 — `grid1.setValue(0,'work_qty',180)`
  로 넣는다. 셀을 눌러도 편집칸이 열리지 않는다
- 관할 청구처를 밖에서 찾아 고르면 **마스터에 새로 만든다**(`boOuterUse` 는
  등록 창을 채울 뿐이다). 이미 「중구지사」(#11)가 있는데 「공단 중구지사」(#23)가
  또 섰다 — 결함 ⑧(마스터 겹침)의 실제 사례다
