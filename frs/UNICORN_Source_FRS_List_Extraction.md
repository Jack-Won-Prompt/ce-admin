- 작성일: 2026-09-06 · 작성: Jack Won (LTL) · 용도: 내부 검증 (클라이언트 배포 문서 아님)
- 결과 파일명: `UNICORN_Source_FRS_List_RESULT_YYYYMMDD.md` (본 문서 4~7장의 표 스키마를 그대로 사용해 작성)
- 관련 문서: `UNICORN_FRS_v0.4_Implementation_Check.md` (FRS→코드 검증용). 본 문서는 그 역방향(코드→FRS)이다. 두 결과를 회수 후 교차 대조한다.

## 0. 작업 지시 (서버 측 작업자 / 에이전트)

### 0.1 원칙
1. **읽기 전용.** 코드·DB·설정을 변경하지 않는다. `git status`가 작업 전후 동일해야 한다.
2. **무발명·무추정.** 소스에서 직접 확인한 것만 기록한다. "이런 기능이 있을 것이다"라는 판단으로 행을 만들지 않는다. 확인이 안 되는 속성은 빈칸이 아니라 `확인 불가`로 명기하고 사유를 적는다.
3. **근거는 재현 가능하게.** 모든 행은 최소 1개의 근거를 갖는다: `경로:라인`, 라우트 이름, 컨트롤러@메서드, 테이블명.컬럼명, Job/Command 클래스명, 설정 키, 실행한 명령과 출력 요약.
4. **코드가 진실이다.** 주석·TODO·docblock에만 존재하고 실행 코드가 없는 기능은 리스트에 넣지 않는다. 단, 7장(숨은 기능/사각지대)에 별도 기록한다.
5. **모듈 매핑은 잠정 후보다.** 본 문서 3장의 모듈 분류 기준은 참고용이며, 최종 M01~M06 매핑과 FS ID 부여는 회수 후 FRS v0.4 문서와 대조하면서 확정한다. 서버 측에서는 `모듈(잠정)` 열에 후보만 기입한다.
6. **금지 항목 발견 시 즉시 기록.** 5장의 전역 금지 항목이 소스에서 발견되면 해당 행에 `⛔`를 표기하고 5장 표에도 중복 기재한다.

### 0.2 탐색 절차 (Laravel 11 기준)
아래 순서로 전수 스캔한다. 실제 디렉터리 구조가 관례와 다르면 실제 위치를 기록한다.

| 순서 | 대상 | 방법 (예시) |
|---|---|---|
| 1 | 라우트 전수 | `php artisan route:list --json` 또는 `routes/*.php` 직접 판독. 웹/API/미들웨어 그룹 구분 기록 |
| 2 | 컨트롤러 | `app/Http/Controllers/` 전체. public 메서드 단위로 기능 후보 도출 |

## 2. FS 후보 리스트 표 스키마 (본문)

한 행 = 하나의 기능 단위. 원칙: **라우트(또는 Job/Command) 1개당 최소 1행**, 단 순수 CRUD 세트는 리소스 단위로 1행 통합 가능(비고에 포함 액션 명기).

| 열 | 내용 | 기입 규칙 |
|---|---|---|
| No | 일련번호 | S-001부터. FS ID를 임의 부여하지 않는다 (회수 후 매핑) |
| 기능명(잠정) | 코드에서 확인되는 동작을 서술형으로 | 예: "처방전 이미지 업로드 및 접수 생성". 마케팅성 명칭 금지 |
| 모듈(잠정) | 3장 기준의 후보 | 불명확하면 `확인 필요` |
| 앱 구분 | CE Admin / API(SR App용) / 공통 / 확인 불가 | 라우트 그룹·미들웨어 기준 |
| 접근 역할 | RBAC 기준 허용 역할 | Gate/Policy/미들웨어 근거 필수. 없으면 `제한 없음(근거: 미들웨어 부재)` |
| 트리거 | 화면 액션 / API 호출 / 스케줄 / 이벤트 / 큐 | |
| 입력 | 주요 입력 필드 + validation 요지 | FormRequest 기준. 없으면 `검증 없음` 명기 |
| 처리 요지 | 핵심 로직 2~3문장 | 상태 전이가 있으면 enum 값 명기 |
| 출력/저장 | 응답 형태, 기록 테이블.컬럼 | |
| 외부 연계 | Popbill/Toss/WITHWORKS/Entra ID/기타/없음 | 호출 클래스·설정 키 근거 |
| 근거 | 경로:라인, 라우트명, 클래스@메서드 | 최소 1개, 재현 가능하게 |
| 상태 | ✅ 완성 동작 / 🟡 부분(스텁·미완) / ⛔ 금지 위반 / ⚠ 판독 불가 | |
| 비고 | 특이사항, 통합한 CRUD 액션, feature flag 여부 등 | |

## 4. 비화면 프로세스 리스트 (별도 표)

Job, Command, Scheduler, Event Listener 등 화면 없는 기능은 2장 스키마와 동일하되 `트리거` 열에 실행 조건(cron 식, 이벤트명, 큐명)을 반드시 기입한다. 화면 기능에 종속된 비동기 처리는 해당 FS 후보 행의 비고에 연결 표기(`→ S-0xx 후속 Job`)한다.
