## 0. 먼저 — 순서 검증 결과

지시하신 순서를 **소스 로직으로 확인**했다. 주석이 아니라 실제로 도는 코드와
운영 서버의 설정값을 읽었다. **그대로 진행하면 멈추는 자리가 넷 있다.**

### ✗ (가) 공단 팩스 자동 전송이 **꺼져 있다**

```
order.nhis_fax_on_consent = false
order.nhis_fax_on_id_card = false
```

[NhisFaxAuto.php:51](app/Services/NhisFaxAuto.php#L51) 이 이 값을 맨 먼저 보고
**아무 말 없이 물러난다** — 알림도 남지 않는다. 지금 상태로는 「운영 팝빌로 팩스
자동 전송 확인」 단계에서 아무 일도 일어나지 않고, 그것이 실패인지 아닌지조차
화면에 뜨지 않는다.

**시험 전에 둘 다 켜야 한다.**

### ✗ (나) 팩스가 **0504-134-1393 으로 가지 않는다**

받는 번호는 [NhisFaxAuto.php:203](app/Services/NhisFaxAuto.php#L203) 이
**관할 청구처(`billing_offices.fax`)** 에서 읽는다. 지시하신 번호는 그 표에 없다.

운영 설정은 —

```
popbill.fax_mode          live      ← 적힌 곳으로 실제로 나간다
popbill.test.receiver_fax ''        ← 시험 수신처가 비어 있다
```

`fax_mode` 를 **`redirect`** 로 두고 **시험 팩스 번호에 0504-134-1393** 을 넣으면,
관할 청구처를 건드리지 않고 그 번호로만 간다([FaxService.php:67](app/Services/Popbill/FaxService.php#L67)).
**운영 청구처의 팩스번호를 고쳐 시험하면 안 된다** — 되돌리기를 잊으면 공단으로
갈 팩스가 엉뚱한 곳으로 간다(2026-09-07 에 그 일이 있었다).

### ✗✗ (다) 세금계산서·현금영수증이 **국세청 실신고로 나간다**

```
billing.auto_issue        true
billing.auto_issue_start  '2026-09-01'   ← 오늘(9-30)은 이미 지났다
popbill.issue_simulate    false
팝빌 갈래                 live
enabled(taxinvoice)       true
enabled(cashbill)         true
```

즉 결제가 확인되면 [DepositAutoIssue](app/Services/DepositAutoIssue.php) 가
**실제로 국세청에 신고**한다. 시험 환자 「최연아」 이름으로 세금계산서와
현금영수증이 콜로플라스트 명의로 발행된다.

**팝빌은 한 번 발행하면 API 로 지우지 못한다.** 되돌리려면 취소 신고를 또 해야
하고 그것도 기록에 남는다(2026-09-27 에 취소현금영수증 셋을 만들어 남긴 적이 있다).

**고를 수 있는 길 둘** —

1. `popbill.issue_simulate = true` 로 두고 시험한다. 조회는 그대로 팝빌에 묻고
   **쓰는 일(발행ㆍ취소)만 막는다.** 화면에는 발행된 것처럼 보이고 서류도 만들어진다.
   국세청에는 가지 않는다.
2. 실신고를 감수하고 그대로 진행한 뒤, 시험이 끝나면 **취소 신고**를 낸다.

### ✗ (라) 「처방전 업로드 분리」는 사용자별로 갈리지 않는다

업로드 화면은 담당자를 **고르는 칸**일 뿐, 로그인한 사람에 따라 올릴 수 있는 서류가
달라지지 않는다. 관리자가 처방전·결과지를, stella 가 등록신청서를 올리는 것은
**같은 화면에서 각자 로그인해 올리면 그대로 된다** — 막는 것도 나누는 것도 없다.
다만 그렇게 하면 두 사람이 **같은 처방전에** 올려야 하므로, 관리자가 먼저 올려
처방전을 세운 뒤 stella 가 그 처방전을 열어 등록신청서를 더해야 한다.

### 지시하신 순서와 다른 점 — 셋

**① 팩스는 「신분증 링크 발송」 다음 걸음이 아니다.**
서명이 끝나는 그 순간(8)과 신분증이 닿는 그 순간(11), **두 번** 저절로 재어진다.
사람이 누르는 걸음이 아니다. 둘 중 **나중에 갖춰지는 쪽**에서 나간다.

**② 「유형·자격 선택」이 빠져 있다.**
주문 줄은 **유형을 고를 때 선다**. 이것을 안 하면 주문 제품 탭이 비고, 청구전략이
서지 않아 금액도 서명 안내도 서지 않는다.

**③ 증빙 생성ㆍ위드웍스 확정ㆍ거래명세서 작성일은 한 덩어리다.**
셋을 따로 부르는 자리가 없다. `DepositAutoIssue` 안에서 차례로 일어난다 —
발행 → 거래명세서 → `WithworksConfirm`(작성일 함께). 그래서 발행이 막히면
**확정도 함께 멈춘다.**

### 증빙 넷은 결제 갈래로 갈린다

| 서류 | 언제 |
|---|---|
| 거래명세서 | 늘 |
| 세금계산서 | 청구전략이 정한 몫 (공단 일반이면 90%) |
| **현금영수증** | **가상계좌ㆍ무통장일 때만** |
| **카드매출전표** | **카드결제일 때만** |

카드와 현금영수증을 둘 다 내면 같은 금액이 두 번 신고된다.

### 오류 — 설정을 엉뚱한 묶음에 담았다

처음에 `fax_mode`ㆍ`test_receiver_fax` 를 **`test` 묶음**에 담았다. 화면의 탭 이름이
「테스트 설정」이라 그것이 묶음 이름인 줄 알았는데, `config/settings-schema.php` 의
최상위 묶음은 **`web`** 이다(`test` 라는 묶음은 없다).

`ServiceSettings::applyToConfig()` 는 **스키마에 있는 묶음만** 훑으므로, 담긴 값은
어느 코드도 읽지 않는 채로 누워 있었다 — 담았는데 `config()` 는 그대로 `live` 였다.
**담은 것만 보고 됐다고 읽으면 안 된다.** 반드시 `config()` 를 다시 읽어 확인한다.

**고침** — `test` 묶음의 두 줄을 걷고 `web` 묶음에 다시 담았다. 확인한 값 —

```
order.nhis_fax_on_consent true
order.nhis_fax_on_id_card true
popbill.fax_mode          redirect
popbill.test.receiver_fax '0504-134-1393'
popbill.issue_simulate    false
```

### 유형ㆍ자격

지시대로 **유형 = 처방전 · 자격 = 일반** 으로 고른다.
`BillingStrategy` 가 그 짝을 **건강보험공단 일반(10/90)** 으로 읽는다 —
세금계산서 90% + 현금영수증 10%(가상계좌ㆍ무통장일 때)다.
